# C++ 코드 흐름 실험 (앱 미통합)

MQ에는 C++ 과정도 C++ 채점기도 없습니다. 그래서 이 폴더는 **앱에 들어가지 않는 실험**입니다. 나중에 C++ 과정을 만들 때 "실제 실행을 기록해 이전/다음으로 볼 수 있는가"를 다시 확인할 수 있도록, 고친 추적기와 검사를 git에 남겨 둡니다.

- 실행 방식: 이미 설치된 VS 2022 BuildTools의 MSVC `cl /Zi /Od`로 빌드합니다. Windows 기본 디버거 엔진(`dbgeng.dll`, 드라이버는 `assets/c-trace/dbgeng.py`를 같이 씁니다)으로 실제 프로그램을 멈춰 가며 기록합니다. STL은 BuildTools의 `stl.natvis`로 읽습니다.
- C++ 채점기가 생기면 **그 채점 컴파일러**로 다시 맞춰야 합니다. 이 결과를 "채점과 같은 실행"이라고 보면 안 됩니다.

## 고친 것(실제 실행으로 확인)
- 선언 줄을 지나기 전의 지역 변수는 `(아직 선언·생성 전)`으로 표시하고 내용을 그리지 않습니다. 그래서 생성 전 vector가 빈 목록처럼 보이지 않습니다. 선언 줄을 찾지 못하면 `(볼 수 없음)`으로 표시합니다.
- 함수 첫 바이트(프롤로그 전)의 정지는 `call` 단계로 기록하되, 값은 `(함수 시작 직후: 아직 준비 전)`으로 둡니다. 이 덕분에 한 줄짜리 가상 함수의 실제 대상도 보입니다.
- 닫는 중괄호와 소멸자 실행 중인 객체는 `(수명이 끝나는 중: 소멸자 실행)`으로 표시합니다. 포인터는 이 표시에서 제외합니다.
- `throw`는 `exception` 단계로, catch 핸들러는 `main · catch` 프레임으로(바깥 함수의 지역 변수는 중복해서 보이지 않음), 처리되지 않은 예외는 `uncaught_exception`으로 기록합니다.

## 검사
```bash
python -I -X utf8 tools/cpp-code-flow-experiment/check.py
```
`check.py`는 저장된 trace와 비교하지 않습니다. 매번 빌드하고, 정상 실행 출력과 소스에서 나오는 사실(선언 줄, push_back 결과, 가상 호출 대상, 소멸자 횟수, throw 전 출력)에 대고 검사합니다.

## 아직 안 되는 것
- catch된 예외 객체(`e`)는 주소로만 보입니다.
- 템플릿 사용자 함수, `std::map` 등 다른 컨테이너, 람다, 스마트 포인터, 이동 의미론은 실험하지 않았습니다.
- 선언 줄은 소스 글자로 찾습니다. 한 줄에 여러 선언이 있는 복잡한 형태는 `(볼 수 없음)`으로 떨어질 수 있습니다.
