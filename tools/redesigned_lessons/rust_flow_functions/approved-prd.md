## 근거와 확인 한계

- if의 조건은 bool이어야 하고 블록은 중괄호로 감싼다. else는 조건이 false일 때 실행된다. if는 식이라 let 오른쪽에 쓸 수 있고 두 갈래의 타입이 같아야 한다. for는 범위의 값을 차례로 받아 되풀이한다. — Rust 공식 책 3.5절의 내용이에요. 중괄호 누락 오류, else 없는 if 식의 E0317, 범위 반복 출력은 rustc 1.95.0, edition 2024에서 실측했어요.; 확인 2026-11-02. [원문](https://doc.rust-lang.org/book/ch03-05-control-flow.html)
- 함수는 fn으로 만들고 매개변수마다 타입을 적는다. 반환 타입은 -> 뒤에 적고, 본문의 마지막 식이 세미콜론 없이 오면 그 값을 돌려준다. 세미콜론을 붙이면 문장이 되어 값을 돌려주지 않는다. — Rust 공식 책 3.3절의 내용이에요. 끝 세미콜론의 E0308, 함수 안에서 main의 이름을 쓴 E0425는 rustc 1.95.0 실측이에요.; 확인 2026-11-02. [원문](https://doc.rust-lang.org/book/ch03-03-how-functions-work.html)
- start..end 범위는 start를 포함하고 end를 빼는 반열린 범위다. ..=는 끝을 포함한다. — 표준 라이브러리 Range 문서의 정의예요. 0..3과 1..boxes + 1의 반복 출력은 rustc 1.95.0 실측이에요.; 확인 2026-11-02. [원문](https://doc.rust-lang.org/std/ops/struct.Range.html)
- 정수 리터럴의 밑줄은 자리 구분용이고 값에 영향을 주지 않는다. 쉼표는 숫자의 일부가 아니다. — Rust 레퍼런스 정수 리터럴 절의 내용이에요. 32_000이 32000으로 출력되고 30,000이 컴파일되지 않는 것을 rustc 1.95.0으로 실측했어요.; 확인 2026-11-02. [원문](https://doc.rust-lang.org/reference/tokens.html#integer-literals)
- E0317은 값을 만드는 if에 else가 없어 false일 때의 값이 없을 때의 오류다. — Rust 오류 코드 색인 항목이에요. 해설의 expect_error는 rustc stderr에 그 코드가 들어 있는지만 봐요.; 확인 2026-11-02. [원문](https://doc.rust-lang.org/error_codes/E0317.html)
