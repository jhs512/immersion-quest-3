## 근거와 확인 한계

- println!은 함수가 아니라 매크로이고, 문자열을 인수로 받아 화면에 한 줄로 출력한다. rustc main.rs로 컴파일한 뒤 실행 파일을 실행한다. — Rust 공식 책 1.2절 확인. 이 수업은 rustc 1.95.0, edition 2024에서 실측했어요.; 확인 2026-11-02. [원문](https://doc.rust-lang.org/book/ch01-02-hello-world.html)
- 변수는 기본으로 불변이다. 불변 변수에 다시 대입하면 E0384로 컴파일되지 않고, 선언에 mut를 붙이면 다시 넣을 수 있다. — Rust 공식 책 3.1절 확인. 대표 문제의 E0384와 mut 뒤 출력은 rustc 1.95.0으로 실측했어요.; 확인 2026-11-02. [원문](https://doc.rust-lang.org/book/ch03-01-variables-and-mutability.html)
- i32는 부호 있는 32비트 정수 타입이고 표기가 없으면 정수 리터럴은 i32로 정해진다. bool은 true와 false 두 값을 갖고 비교 연산의 결과로 쓰인다. — Rust 공식 책 3.2절 확인. "3000"을 i32에 담는 E0308, 글자와 정수 덧셈의 E0369는 rustc 1.95.0 실측이에요.; 확인 2026-11-02. [원문](https://doc.rust-lang.org/book/ch03-02-data-types.html)
- 형식 문자열의 {이름}은 같은 범위의 변수를 바로 가져와 그 자리에 출력한다. — 표준 라이브러리 std::fmt 문서 확인. {stock}·{left} 출력은 rustc 1.95.0 실측이에요.; 확인 2026-11-02. [원문](https://doc.rust-lang.org/std/fmt/index.html)
- E0384는 불변 변수에 두 번 대입했을 때의 오류이며 mut 선언으로 고친다. — Rust 오류 코드 색인 확인. 해설의 expect_error는 rustc stderr에 그 코드가 들어 있는지만 본다.; 확인 2026-11-02. [원문](https://doc.rust-lang.org/error_codes/E0384.html)

## 챕터·단원·스텝과 핵심 흐름

### 값과 이름

교육 목표: 값이 출력과 계산으로 이어지는 과정을 확인해요.

#### 출력할 값

교육 목표: 문자열과 이름 붙인 값을 출력해요.

공통 전제: 작은 가게의 재고를 Rust 코드로 출력해요. 각 스텝은 fn main 하나만 있는 준비된 main.rs에서 새로 시작해요.

**println! 문구를 재고 있음으로 바꾸세요**

스텝 코드: stp_a2fc8157-5a39-4d89-8d26-48f5836450b1

교육 목표: println!이 큰따옴표 안의 문자열 리터럴을 그대로 출력하는 것을 확인해요.

코드 실행을 누르면 rustc가 main.rs를 컴파일하고 만든 프로그램을 실행한다. 프로그램은 fn main 안에서 시작한다. 준비 코드 println!("재고 확인")의 출력 `재고 확인`을 먼저 본다. 닫는 따옴표를 빠뜨린 시도는 E0765로 컴파일되지 않는다. 따옴표를 닫고 문구를 재고 있음으로 바꿔 출력이 바뀐 것을 확인한다. 변형 값이 없으므로 기대 출력이 옛 문구와 달라 시작 코드를 거절한다.

**{stock} 자리로 재고 수량을 출력하세요**

스텝 코드: stp_f38cdacd-70a6-46a9-9234-e54bfe263fbd

교육 목표: let으로 값에 이름을 붙이고 {이름} 자리로 그 값을 출력해요.

let stock = 5;가 준비돼 있고 출력은 "재고: 0"으로 적혀 있다. 실행하면 stock과 무관하게 재고: 0이 나온다. 중괄호 없이 stock을 적으면 글자 stock이 출력된다. {stock}으로 고쳐 재고: 5를 본다. 채점은 stock을 12·0으로 바꿔 실행해 "재고: 5" 직접 적기를 거절한다.

#### 계산한 값

교육 목표: 이름 붙인 정수로 계산하고 정수와 글자를 타입으로 구분해요.

공통 전제: 재고·판매 수량·가격에 이름을 붙여 계산해요. 각 스텝에서 바뀐 조건만 확인해요.

**stock - sold를 계산해 left에 담으세요**

스텝 코드: stp_8a5fc6f9-e306-4cf6-a140-32441e786cfd

교육 목표: 이름 붙인 두 정수를 빼서 계산 결과를 새 이름에 담아요.

stock = 5, sold = 2가 준비돼 있고 left는 0으로 적혀 있다. 실행하면 남은 수량: 0이다. 빼는 순서를 바꾼 sold - stock은 -3을 낸다. stock - sold로 고쳐 남은 수량: 3을 본다. 채점은 stock 9, sold 5로 바꿔 계산 결과를 직접 적은 답을 거절한다.

**price에 따옴표 없는 숫자 3000을 담으세요**

스텝 코드: stp_f2868e55-c9fe-47bf-85a4-5bab11c33b72

교육 목표: i32 타입 표기가 정수만 받는 것을 컴파일 결과로 확인해요. / 따옴표로 감싼 3000과 숫자 3000을 구분해요.

let price: i32 = "3000";은 E0308(타입 불일치)로 컴파일되지 않는다. 표기 : i32만 지우면 글자와 정수를 더하는 줄에서 E0369가 난다. 표기를 두고 따옴표를 지워 3000을 담으면 합계: 5500이 나온다. 채점은 price 4000·delivery 0으로 바꿔 합계를 직접 적은 답을 거절한다.

### 변경과 참거짓

교육 목표: 다시 넣을 수 있는 이름과 참거짓 값을 구분해요.

#### 다시 넣는 값

교육 목표: let과 let mut의 차이를 컴파일 결과로 확인해요.

공통 전제: 판매와 입고로 재고 수량이 바뀌어요. 바뀌는 이름은 선언에서 밝혀야 해요. 각 스텝의 코드는 새로 준비돼 있어요.

**stock 선언에 mut를 붙이세요**

스텝 코드: stp_0ad742e9-f7c6-4221-ab90-60f85a3dfafa

교육 목표: let 이름은 기본으로 다시 넣을 수 없음을 E0384로 확인해요. / 값을 다시 넣을 이름에만 mut를 붙여요.

대표 문제다. 제공 코드는 let stock = 5; 뒤 stock -= 2;로 다시 넣어 E0384로 컴파일되지 않는다. 앞 스텝의 풀이가 이어진 상태가 아니다. 오류 난 줄을 지우면 컴파일은 되지만 남은 수량: 5로 판매가 빠진다. 줄을 되살리고 선언에 mut를 붙이면 남은 수량: 3이다. 모든 이름에 mut를 붙이라고 설명하지 않는다. 채점은 stock 8·2로 바꿔 3을 직접 적은 답을 거절한다.

**+=로 입고 수량을 stock에 더하세요**

스텝 코드: stp_1790cade-87fa-435b-bbf6-6400938088e8

교육 목표: +=로 현재 값에 더한 결과를 같은 이름에 다시 넣어요. / 출력은 실행한 순서대로 그 시점의 값을 보여 줌을 확인해요.

let mut stock = 5; 뒤 판매(stock -= sold)와 판매 후 출력이 있다. 입고 후 출력 앞이 비어 있어 두 줄 모두 3이다. stock = arrived;로 쓰면 더하지 않고 덮어써 입고 후: 4가 된다. stock += arrived;로 고쳐 입고 후: 7을 본다. 채점은 arrived 10·stock 8로 바꿔 입고 수량 숫자를 적은 답을 거절한다.

#### 참과 거짓

교육 목표: 비교 결과를 bool 값으로 담아 판매 가능 여부를 정해요.

공통 전제: 재고가 0보다 많으면 팔 수 있고, 0이면 팔 수 없어요.

**stock > 0 비교 결과를 can_sell에 담으세요**

스텝 코드: stp_f22604b7-5c70-45a5-98f2-61e3cf5048e6

교육 목표: 비교 식의 결과가 bool 값 true·false임을 확인해요. / 적어 둔 true와 재고에 따라 바뀌는 비교 결과를 구분해요.

let stock = 3;과 let can_sell: bool = true;가 있다. 실행하면 판매 가능: true다. stock을 0으로 바꿔도 true다. stock >= 0은 0에서도 true다. stock > 0으로 고치면 false, stock을 3으로 되돌리면 true다. 채점은 stock 0·7로 바꿔 true 그대로인 답을 거절한다. R2의 if가 이 bool을 이어 쓴다.

**mut와 비교를 함께 써서 판매 뒤 상태를 출력하세요**

스텝 코드: stp_dd586ed7-cd7b-4535-b432-1fe343297056

교육 목표: mut 선언과 비교 결과를 함께 써서 판매 뒤 수량과 판매 가능 여부를 출력해요.

재고 1에서 1을 판다. 제공 코드는 let stock = 1;에 stock -= sold;를 써서 E0384다. stock에만 mut를 붙이면 남은 수량: 0, 판매 가능: true가 나와 판매 가능이 틀렸다. can_sell을 판매 뒤 stock > 0으로 고쳐 false를 본다. 채점은 stock 5, sold 0으로 바꿔 두 줄을 직접 적은 답과 true를 둔 답을 거절한다.

## 채점

- 필수 문제를 직접 제출해 맞히면 성공이에요. 실행·해설 열람만으로 성공시키지 않아요.
- 답안은 실제 rustc --edition=2024로 컴파일·실행해 표준 출력의 끝 줄바꿈을 뗀 값이 기대 출력과 같아야 해요. 컴파일 실패는 오답이에요.
- 준비 값 바꾸기(variations)로 주석·문자열 밖의 첫 let 선언의 처음 값을 바꿔 다시 실행해요. 출력 상수를 적은 답, true를 그대로 둔 답, 입고 수량 숫자를 적은 답을 이것으로 거절해요.
- 준비 코드는 모두 채점에서 실패해야 해요. 대표 문제(5번)는 E0384로 컴파일되지 않고, mut 뒤 남은 수량: 3, 시작 수량 8이면 6을 출력해야 해요.

- 한 번에 1~3줄만 고치고 실행해 결과를 읽어요. 실제로 저지르기 쉬운 실수(닫는 따옴표 누락, 중괄호 없는 이름, 빼기 순서, 표기만 지우기, 오류 줄 삭제, = 덮어쓰기, >= 비교)는 쳐 보고 실행한 뒤 고쳐요.
- 컴파일 실패 단계는 실행되지 않은 것으로 말하고 값 변화를 그리지 않아요. 모든 변수에 mut를 붙이면 된다고 설명하지 않아요.
