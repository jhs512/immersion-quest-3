## 대상과 선수 지식

- 터미널과 Git을 처음 배우는 학습자
- 파일과 폴더의 차이를 알아요.

## 제작 범위

- Git 첫 수업 바로 앞에 배치한다.
- 23단계에서 탐색·생성·읽기·쓰기·복사·이동·삭제을 실제 터미널로 익힌다.
- 첫 단계의 빈 폴더에서 직접 만든 파일과 작업 위치를 이후 단계에도 이어 쓴다. 파일을 몰래 만들거나 바꾸지 않는다.
- macOS Bash와 Windows Git Bash를 지원하며 cp -R 등 양쪽에서 가능한 문법을 사용한다.
- 모든 스텝에 할 일을 1., 2., 3. 번호 목록으로 표시한다. 작성 기준은 docs/voice.md를 따른다.

## 제외 범위

- Vim 편집은 다음 독립 수업에서 다룬다.
- 고급 셸 스크립트·권한 관리는 후속 범위다.

## 근거와 확인 한계

- pwd와 cd는 현재 작업 폴더 확인·변경에 쓰는 Bash 내장 명령이다. — 공식 문서 검색 결과 확인; 확인 2026-10-20. [원문](https://www.gnu.org/software/bash/manual/html_node/Bourne-Shell-Builtins.html)
- cat은 지정한 파일의 내용을 표준 출력으로 보낸다. — 공식 문서 검색 결과 확인; 확인 2026-10-20. [원문](https://www.gnu.org/software/coreutils/manual/html_node/cat-invocation.html)
- 입력 모드·일반 모드, 이동, 삭제, 실행 취소와 종료 방법을 명시한다. — Vim 공식 사용자 매뉴얼 확인; 확인 2026-10-20. [원문](https://vimhelp.org/usr_02.txt.html)

- 힌트는 선택이고 오답 뒤 즉시 다시 도전한다. 해설을 보기만 해서는 성공하지 않는다.
- 해설 뒤 직접 맞혀도 정상 성공이다. 성공 전후 열람을 상세 아이콘의 부가 정보로 구분한다.
- 해설은 작은 실제 명령 실행과 결과 확인을 연결하고 버튼·줄·결과를 정확히 강조한다.
- 시연은 학생 답안과 저장소를 보존한다. 음성을 미리 준비한 뒤 화면과 동기화한다.
- 이미지·만화·시각화는 이해를 도울 때만 사용한다. 표현 수단을 모든 스텝에 강제하지 않는다.
- 학생 글은 짧은 한국어 해요체를 쓴다. 새 용어는 처음에 풀어 쓰고 결과 숫자는 실제 실행에 근거한다.
- PRD와 대표 문제 승인 후 제작한다. 목표나 교수법 변경은 다시 승인받는다. 오탈자·명백한 오류는 자율 수정하고 이력을 남긴다.

- 파일 상태·현재 폴더와 실제 명령 완료를 확인한다. 출력 언어와 절대 경로를 고정 문자열로 채점하지 않는다.
- 읽기 전용 명령은 실제 터미널 실행 완료를 기록해 판정한다. 단순히 준비된 결과를 보여 준 것으로 성공시키지 않는다.
- 파일 작성과 폴더 생성은 학습자 실습 폴더의 실제 결과로 판정한다.
- 복사에서는 원본과 사본, 이동에서는 이전 경로 부재와 새 경로의 내용을 각각 검사한다.
- 삭제에서는 지정한 연습 파일만 없어지고 다른 자료는 유지됐는지 확인한다.
- Vim은 실제 대화형 PTY에서 키 입력·모드 전환·종료와 저장 결과를 확인한다. Ex 배치 실행만으로 대화형 검증을 대체하지 않는다.

## 초기화

- 단계 이동으로 파일과 현재 위치를 바꾸지 않는다.

- 해설은 앞 단계까지의 상태를 별도 폴더에 준비하고 먼저 설명한다. 종료 뒤 학습자 파일과 작업 위치를 보존한다.

## 해설

- 명령 한 개 입력 → 출력 확인 → 의미 설명을 반복한다.
- 현재 경로·파일 목록·파일 내용을 해당 터미널 출력에서 짚는다.
- 시연은 별도 폴더에서 수행하고 학습자 파일·작업 위치를 보존한다.
- 파일 쓰기 전 >의 덮어쓰기 동작을 설명한다.
- 파일 복사·이동·삭제 전후에 ls와 cat으로 대상과 결과를 비교한다.
- Vim 해설은 실행 명령과 편집기 키 입력을 구분하고 실제 화면 변화를 기다린다.

## 검증과 완료

- macOS 실제 Bash에서 30단계의 연속 상태·판정·해설 복귀를 확인한다.
- Windows Git Bash의 탐색·설치 안내·경로·UTF-8 입출력을 검증한다. 확인 전 플랫폼 검증 완료로 표시하지 않는다.
- 읽기 전용 명령을 실행하지 않은 경우 통과하지 않는지 확인한다.
- 대표 문제의 명령을 실제 Bash에서 실행하고 기대 출력을 확인한다.
