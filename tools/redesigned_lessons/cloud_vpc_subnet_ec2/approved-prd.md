## 근거와 확인 한계

- 서브넷 CIDR은 VPC CIDR과 같거나 그 일부이고, 한 VPC의 서브넷 CIDR은 겹칠 수 없다. 각 서브넷의 처음 네 주소와 마지막 주소는 예약된다. — AWS 공식 문서를 열어 문장을 확인했다. 예약 주소는 이 수업에서 가르치지 않는다.; 확인 2026-11-10. [원문](https://docs.aws.amazon.com/vpc/latest/userguide/subnet-sizing.html)
- VPC IPv4 CIDR은 /16에서 /28 사이다. — AWS 공식 문서를 열어 확인했다. 실습 VPC는 /16이다.; 확인 2026-11-10. [원문](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-cidr-blocks.html)
- 인스턴스는 서브넷의 CIDR 범위에서 사설 IPv4 주소를 받고, 같은 VPC의 인스턴스끼리 사설 주소로 통신할 수 있다. — AWS 공식 문서를 열어 확인했다. 로컬 실습에서는 같은 VPC의 다른 서브넷 HTTP 응답만 실측했다.; 확인 2026-11-10. [원문](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/using-instance-addressing.html)
- 인스턴스는 시작할 때 pending 상태를 거친다. — AWS 공식 문서를 열어 확인했다. 수명주기의 나머지는 다음 수업 범위다.; 확인 2026-11-10. [원문](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-instance-lifecycle.html)
- create-subnet은 --vpc-id와 --cidr-block을 받는다. run-instances의 --subnet-id는 인스턴스를 실행할 서브넷이다(같은 CLI 참조). — AWS CLI 공식 참조를 열어 확인했다.; 확인 2026-11-10. [원문](https://docs.aws.amazon.com/cli/latest/reference/ec2/create-subnet.html)
- Floci는 로컬 AWS 에뮬레이터다. 고정 이미지에서 VPC·서브넷 생성·조회, 범위 밖·겹침 거절, 실제 EC2 게스트의 사설 주소와 같은 VPC HTTP 응답을 실측했다. — 저장소를 열어 확인했다. 실행 근거는 docs/floci-first-lesson-preflight.md와 docs/floci-cloud-native-runtime.md에 따로 있다. 라우팅·NACL·NAT·피어링·보안 그룹의 AWS 동등성은 입증하지 않았다.; 확인 2026-11-10. [원문](https://github.com/floci-io/floci)
