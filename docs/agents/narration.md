# 해설 모드 스크립트 (narration)

`/auto`와 `/auto-all`이 미션마다 재생하는 해설은 빌드 때 미리 컴파일되어 `courses/kpc-finance.json`의 각 미션 `narration` 필드에 들어간다. 앱은 CLI를 부르지 않고 그 동작 목록을 바로 실행하고, 대본을 패널에 먼저 보여 준다.

## 파생물과 원본

학생이 보는 글은 전부 **원본 블록**이고, 블록마다 키와 내용 해시가 있다(`tools/kpc_course/sources.py`): `1-4-1/p3`(개념 1-4-1의 세 번째 문단·펜스), `1-4-1/check`, `1-4-2/solution`, `1-4-5/s7`(덱의 7번째 장), `1-4-9/q3`(퀴즈 3번 문항). 빌드가 `courses/kpc-finance.sources.json`에 모든 블록의 키·해시·첫머리를 쓰므로, 그 파일의 git diff가 곧 "어느 블록이 바뀌었나"다.

| 파생물 | 원본 | 만드는 법 | 신선도 |
| --- | --- | --- | --- |
| 개념·코딩 미션 해설(`narration`) | 본문 블록, 확인 문항, 문제, 정답 | AI(`tools/narrate.py`) → `narration_cache/<id>.json` | 캐시가 줄마다 원본 블록 키·해시를 기록. 블록이 바뀌면 빌드 거부, 그 블록의 줄만 다시 씀 |
| 덱 해설 | 각 장의 강사 스크립트(`<!-- -->`) | 빌드가 컴파일 | 매 빌드 새로 만듦 |
| 퀴즈 해설 | 문항 풀이 | 빌드가 컴파일 | 매 빌드 새로 만듦 |
| 핵심 훑기 문장(`tour`) | 위 해설 | 빌드가 컴파일 | 매 빌드 새로 만듦 |

즉 AI가 쓴 것은 캐시에만 있고, 캐시는 원본 블록에 묶여 있다. 원본을 고치면 빌드가 "1-4-1/p3 바뀜 「…」 → 다시 쓸 해설 줄: 2, 3 (전체 7줄 중 5줄은 그대로)"처럼 정확히 알려 주고, `python tools/narrate.py`는 그 줄만 다시 쓴다(나머지 줄은 모델 답과 무관하게 원래 글자로 되돌린다). `--check`는 같은 내용을 쓰지 않고 나열한다. `--migrate`는 블록 기록이 없는 옛 캐시에 지금 블록을 기록한다(내용이 그대로인 것만).

## 규칙: 내용을 바꾸면 해설도 같이 바꾼다

개념 본문, 코딩 문제의 정답, 퀴즈 해설, 덱의 강사 스크립트를 고치면 **같은 커밋에서** 그 미션의 해설도 고친다. 빌드가 이를 강제한다.

- 개념 해설의 구절(anchor)이 본문에 없으면 빌드 실패.
- 코딩 해설의 코드 조각을 이어 붙인 것이 정답 코드와 다르면 빌드 실패.
- 개념·코딩 미션에 해설 항목이 없으면 빌드 실패 (`KPC_LENIENT=1`이면 경고만).
- 슬라이드(강사 스크립트)와 퀴즈(문항 해설)는 내용에서 자동으로 컴파일되므로 따로 쓰지 않는다.

## 핵심 훑기(`/tour-all`)의 `tour`

빌드가 미션마다 `tour`(1~3문장)를 해설에서 자동으로 뽑는다(`compile_tour`): 개념은 처음·마지막 구절 해설과 확인 문항 풀이의 첫 문장, 코딩은 문제 줄과 결과 줄, 퀴즈는 문항 수와 앞 두 문항의 풀이, 덱은 첫 장과 마지막 장 대본의 첫 문장. 따로 쓰지 않으며 해설을 고치면 함께 바뀐다.

## 재작업: `python tools/narrate.py`

개념·코딩 미션의 해설은 `tools/kpc_course/narration_cache/<미션 id>.json`에 있고, 각 파일은 그 해설을 쓸 때의 원본 해시(`hash`)를 기록한다. 본문·정답·힌트·확인 문항이 바뀌면 해시가 달라져 빌드가 "낡았다"며 멈춘다. 그때 "AI 나레이션 재작업" = `python tools/narrate.py`를 돌린다.

- 바뀐 미션과 해설이 없는 미션만 이 컴퓨터의 Claude CLI(`claude -p`)로 다시 쓴다. 바뀐 게 없으면 아무것도 하지 않는다.
- 코딩 미션은 정답을 실제로 실행한 출력을 함께 주어 "결과" 문장이 실제 값을 말하게 한다.
- 만든 해설은 빌드와 같은 검사(구절이 본문에 있는가, 코드 조각이 정답과 같은가)를 통과할 때까지 오류를 돌려주며 최대 세 번 다시 쓴다.
- `--all`은 전부 다시 쓰고, `--ids a b`는 그 미션만, `--check`는 낡은 것만 나열한다. 캐시 파일을 손으로 고쳐도 된다(`by: hand`). 본문을 고친 뒤 해설을 손으로 맞췄다면 `--stamp <id>`로 해시만 다시 찍는다.
- 미션이 사라지거나 id가 바뀌어 주인 없는 캐시 파일이 남으면 빌드가 멈춘다. 지우거나 이름을 바꾼다.
- 덱과 퀴즈는 내용에서 자동으로 컴파일되므로 재작업 대상이 아니다.

## 어디에 쓰나

`tools/kpc_course/narration_cache/<미션 id>.json`의 `entry` (아래 형식). 컴파일러와 검사는 `tools/kpc_course/narration.py`, 생성은 `tools/narrate.py`.

### 개념 (concept): `(구절, 말)` 목록

```python
"numbers-text": [
    ("title", "자, 이 개념에서 볼 건 하나예요."),                      # 제목(h2)
    ("print(30000)과 print('30000')은", "화면엔 똑같아 보이죠? 파이썬한텐 전혀 달라요."),  # 그 구절이 든 문단
    ("제목: 따옴표 하나의 차이", "만화를 보세요. 글자를 세 번 이어 붙여요."),   # 만화·그림·코드는 펜스 안 글자로
    ("check", "확인 문항이요. 방금 봤죠?"),                            # 확인 문항
],
```

- 구절은 학생이 읽는 글자 그대로(백틱·굵게 표시는 뺀다). 문단 앞부분 10~30자가 좋다. 코드·만화·그림 블록은 펜스 안 글자(`제목: ...`, 코드 한 줄)로 가리킨다.
- 앱은 그 구절이 든 블록을 화면 가운데로 **천천히 스크롤**해 보라색 테두리를 치고 문장을 읽는다. 위에서 아래 순서로 쓴다.
- 확인 문항의 답과 풀이는 `check` 문항의 `explanation`으로 자동으로 붙는다. `check` 줄은 선택.

### 코딩 (coding): 단계 목록

**규칙(콘텐츠 룰, 영구):** 한 번에 다 쓰고 끝에 한 번 실행하지 않는다. **살짝 코딩 → 실행 → 출력 읽기**를 반복해서, 보는 사람이 프로그램이 자라는 걸 본다. 그리고 **"이렇게 해볼까요? 이렇게 하기 쉬운데, 그러면 이런 문제가 생기니 조심하세요"**를 1~2번 넣는다(실제로 쳐 보고 되돌리거나, 말로만). 빌드가 강제한다: 조각이 둘 이상이면 run이 둘 이상, 마지막 조각 뒤에 run·output, try/undo 또는 caution이 하나 이상, run 뒤엔 반드시 output.

```python
"variable-print": [
    ("problem", "자, 같은 계산을 이름표로 해요. ..."),           # 생략하면 목표 첫 문단을 읽는다
    ("starter", "준비 코드 두 줄은 그대로 둘게요."),              # 정답이 준비 코드로 시작할 때만
    ("code", "amount = price * quantity\n", "오른쪽을 먼저 계산해서 amount에 넣어요."),
    ("run", "일단 실행해 볼게요."),
    ("output", "아무것도 안 나오죠? 넣기만 했지 꺼내지 않았거든요."),   # 그 시점의 실제 출력을 말한다
    ("try", "print(amount\n", "이렇게 해 볼까요?"),                 # 틀리기 쉬운 코드를 실제로 쳐 본다
    ("run", "실행하면요."),
    ("output", "SyntaxError가 나요. 괄호를 안 닫았거든요."),
    ("undo", "그래서 괄호를 꼭 닫아요."),                            # try 전으로 되돌린다
    ("code", "print(amount)\n", "그다음 줄에서 꺼내 써요."),
    ("run", "다시 실행해요."),
    ("output", "30000이 나왔죠?"),
    ("caution", "숫자 30000을 직접 적기 쉬운데, 가격이 바뀌면 틀리니 조심하세요."),  # 말로만 하는 주의
    ("submit", "제출할게요."),
],
```

- 단계: `problem`, `examples`, `hint`, `starter`, `code`(조각), `try`(쳐 보고 되돌릴 조각), `undo`(try 전으로), `run`, `output`, `caution`, `input`, `submit`.
- `code` 조각은 **덧붙일 부분만**. 준비 코드의 코드 줄(끝의 `# ...하세요` 주석 제외)은 앱이 그대로 두고, 조각을 전부 이으면(try는 undo로 되돌린 뒤) `solution`과 글자 단위로 같아야 한다. 정답이 준비 코드로 시작하지 않으면 첫 조각이 편집기를 비우고 시작한다.
- 조각은 1~3줄씩, 한 조각에 새로 배우는 것 하나. 오류 없이 무언가 보이는 자리에서 run 한다.
- `output`은 실제로 나올 값을 말한다. `tools/narrate.py`가 run마다 코드를 실제로 실행해 그 출력으로 output 줄을 다시 쓰고, try가 아닌 조각 뒤의 run이 오류로 끝나면 대본을 거부한다.
- 앱에서 `undo`는 편집기를 try 전 내용으로 되돌리는 `set_code`, `caution`은 편집기를 비추며 말하는 `say`가 된다.

## 말투

`docs/voice.md`를 따른다. 그 파일이 `tools/narrate.py`의 프롬프트와 앱 조교의 프롬프트에 통째로 들어가므로 말투 규칙은 거기에만 적는다. 해설만의 형식(구절 anchor, 코드 조각 나누기, 결과 줄)은 위 "어디에 쓰나"가 정한다.

## 검증

```bash
python tools/build-kpc-course.py
```

통과하면 `courses/kpc-finance.json`이 다시 쓰인다. 한 챕터만 고치는 중이면 그 모듈만 먼저 검사할 수 있다(해설 anchor·코드 조각·편집 검사를 같은 규칙으로 돌린다).

```bash
python tools/verify-kpc-module.py d1_p1_environment narration_python
``` 앱에서는 해당 미션을 열고 AI 패널에 `/auto`를 쳐서 대본과 동작을 확인한다.
