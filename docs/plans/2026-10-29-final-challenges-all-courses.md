## 3. 백엔드 24수업의 도전 설계

공통 규칙

- 새 스텝은 마지막 챕터에 새 단원 「마지막 도전」을 만들어 넣어요(새 `unt_`·`stp_` UUID4). 기존 챕터·단원·스텝의 ID와 목표는 그대로예요. 수업 목표(첫 수업의 서사 포함)도 바꾸지 않아요.
- 할 일은 이번에 할 행동만 순서대로 써요. 풀이 명령·코드를 그대로 주지 않고, 시작 상태·목표 상태·관찰할 결과를 보여 줘요. 객관식 없음, 가짜 콘솔·새 해석기 없음.
- 채점은 기존 실제 채점기만 써요: 자바(JDK 실행 출력·준비 값 바꾸기 `variations`·표준 입력 `tests`·파일 `expected_files`), JUnit(정상 구현 통과+결함 구현 `mutations` 탐지), 실제 Bash(최종 파일·폴더·위치+필수 확인 명령), 실제 Vim(편집 상태·저장·종료 기록), 실제 Git(`state_goal`·`git_checks`, 로컬 원격), 실제 GitHub(`github_pr`).
- 해설은 문제 상황과 목표를 먼저 말하고, 그 뒤 실제 코드·터미널을 한 동작씩 실행해 실제 결과를 읽어요. 실행 결과는 검증기에서 실제로 다시 실행해 맞춰요.
- 검증: 준비 상태는 실패, 해설대로 통과, 기록한 오답·우회는 거절, 동등한 다른 풀이는 통과. 증거는 `target/final-challenges/<key>.json`(수업 해시 포함)에 남기고 요약을 `docs/curriculum/final-challenges-evidence.md`에 적어요.
