# MQ 단축키

단축키의 기준과 플랫폼 표시는 `assets/layout/shortcuts.js`에서 관리한다. 화면은 `data-shortcut-action`만 선언한다. 버튼의 키 표시·툴팁·접근성 속성과 단축키 안내가 같은 정의를 사용한다. macOS는 Command, Windows와 Linux는 Ctrl을 기본 조합키로 쓴다.

| 행동 | macOS | Windows |
| --- | --- | --- |
| 코드 실행 | ⌘ + Enter | Ctrl + Enter |
| 답안 제출 | ⌘ + Shift + Enter | Ctrl + Shift + Enter |
| 이전 스텝 | ⌘ + ← | Ctrl + ← |
| 다음 스텝 | ⌘ + → | Ctrl + → |
| 단축키 안내 | ⌘ + / | Ctrl + / |
| 전체 화면 | Control + ⌘ + F | F11 |
| 해설 일시정지·재개 | Space | Space |
| 해설 정지·안내 닫기 | Esc | Esc |
| 관리자 자동 풀이 시작 (코스 편집 권한 계정만) | Control + Option + Shift + A | Ctrl + Alt + Shift + A |

## 입력과 이동

- 실행·제출은 코드와 터미널에 초점이 있어도 사용할 수 있다. 실행 버튼이 없는 터미널 실습에는 코드 실행 키를 적용하지 않는다. 터미널 명령과 Vim의 콜론 명령은 Enter로 실행한다.
- 스텝 이동·목차·조교·단축키 안내의 조합키는 코드, 터미널, 텍스트 입력에서 편집 의미를 보존한다. 입력 밖에서 쓰거나 화면의 버튼을 사용한다. 코드의 ⌘/Ctrl+/ 주석 처리를 가로채지 않는다.
- 단원 이동(⌘/Ctrl+↑↓), 목차(⌘/Ctrl+K), 조교(⌘/Ctrl+I)는 해당 기능이 있는 기존 학습 화면에서만 작동한다. 새 과정에 존재하지 않는 기능이 있다고 안내하지 않는다.
- 한글 조합 중이거나 키가 자동 반복되는 동안 제출·이동하지 않는다.
- 실행은 실행만 한다. 두 번 누르거나 실행 직후 Enter를 눌렀다고 제출하지 않는다. 비활성 버튼에 대한 단축키를 나중에 실행하도록 예약하지 않는다.
- 문제 영역의 Enter는 제출, 통과 창의 Enter는 다음으로 이동한다. 입력창·터미널·버튼·링크의 기본 Enter 동작은 유지한다.
- 검사·해설 중에는 스텝 이동 단축키가 작동하지 않는다. 열린 대화상자 뒤의 실행·제출·이동도 막는다.
- 안내는 실제 dialog로 열고, 닫으면 원래 초점으로 돌아간다. 초기화에는 단축키를 배정하지 않는다.

## 제출 결과

- 오답: 붉은 `제출 실패` 표시를 제출 버튼 옆에 둔다. 결과 영역에 아이콘·`제출 실패 · 다시 풀어보세요`·수정 방향을 표시한다. 화면 읽기 프로그램에도 알린다.
- 실행 오류·검사 불가: 학습자가 틀렸다고 단정하지 않고 오류를 확인한 뒤 다시 시도하도록 안내한다.
- 통과: 초록색 계열의 통과 안내를 표시한다. 진도 저장 메시지와 판정 상태를 구분한다.
- 판정은 진도 저장을 기다리지 않고 표시한다. 실패한 제출로 수업 완료를 새로 알리지 않는다.
- 해설 시연은 결과 상태도 보존한다. 초기화·새 실행은 이전 실패 표시를 지운다.

## 관리자 자동 풀이

- 시작 키는 `event.code`(KeyA)로 판정한다. Option·AltGr가 글자를 바꿔도 같은 키다. 앱 창 안에서만 동작하며 신고용 전역 단축키(B·P)와 겹치지 않는다. 단축키 안내 창에는 넣지 않고 관리자에게만 보이는 시작 버튼의 설명에 표시한다.
- 실행 중에는 Space가 일시정지·재개, Esc가 멈춤이다. 터미널·편집기에 초점이 있어도 같다(실행 중 문제 영역 입력은 막혀 있다). 버튼·선택 상자의 Space는 그대로다.
- 자세한 동작은 `docs/admin-auto-review.md`.
