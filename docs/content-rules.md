# 콘텐츠 룰

수업 내용을 만들거나 고칠 때 항상 지키는 규칙이다. 말투·용어는 `docs/voice.md`, 해설 대본의 형식은 `docs/agents/narration.md`가 정하고, 이 파일은 **무엇을 어떻게 보여 주는가**의 규칙을 모은다. 수업 본편과 도전 과제에 똑같이 적용되며, 빌드가 지킬 수 있는 것은 빌드가 강제한다. LLM이 만드는 글(해설, 주석)의 프롬프트에는 이 파일이 들어간다.

## 1. 코딩 해설은 프로그램이 자라는 걸 보여 준다

- 한 번에 다 쓰고 끝에 한 번 실행하지 않는다. **살짝 코딩 → 실행 → 출력 읽기**를 반복한다. 보는 사람이 "아, 이렇게 발전하는구나"를 느껴야 한다.
- 조각은 1~3줄. 실행했을 때 오류 없이 무언가 보이는 자리에서 실행한다(변수를 만들었으면 print로 확인).
- 결과 줄은 그 시점에 실제로 나온 값을 말한다. 생성 도구가 run마다 코드를 실제로 돌려 맞춘다.
- 빌드 강제: 조각이 둘 이상이면 실행이 둘 이상, 실행 뒤엔 결과 읽기, 마지막 조각 뒤에 실행·결과·제출.

## 2. "이렇게 해볼까요? 이렇게 하기 쉬운데, 그러면 이런 문제가 생기니 조심하세요"

- 코딩 해설마다 1~2번. 틀리기 쉬운 줄을 **실제로 쳐 보고**(try) 실행해서 무엇이 잘못되는지 보여 준 뒤 **되돌린다**(undo), 또는 코드를 치지 않고 말로만 짚는다(caution).
- 흔한 실수 예: 따옴표를 빼먹거나 붙임, 숫자를 글자로 계산, 열 이름 오타, 0부터 세는 자리, 괄호 안 닫음, 테스트 자료로 학습, 시간 순서를 섞어 나눔.
- 빌드 강제: try/undo 또는 caution이 하나 이상.

## 3. 정답 코드에는 주석이 풍부하다

- 모든 정답 코드(정답 보기, 해설이 타이핑하는 코드, `courses/kpc-solutions.json`)에 `#` 주석을 단다. 그 줄이 무엇을 왜 하는지, 수강생이 헷갈리는 지점을 짚는다. 코드 2~3줄마다 하나 이상.
- 주석은 해설(말)로 읽지 않는다. 해설은 코드가 하는 일을 말하고, 주석은 화면에 남는 글이다.
- 주석은 코드를 바꾸지 않는다. 주석을 지우면 원래 코드와 줄 단위로 같아야 하고, 준비 코드 부분은 글자 그대로 둔다. 도구: `python tools/annotate.py`(캐시 `tools/kpc_course/solution_comments/`, 원본 코드 해시로 신선도 관리).
- 도전 과제의 정답·해설은 강사 자료(암호화, `site/data/instructor.json`)에 있다. `python tools/practice-materials.py`가 같은 규칙으로 주석과 해설을 만들어 이 컴퓨터의 비밀번호 파일로 암호화한다(평문과 비밀번호는 `target/course-guide-authoring/`, Git 제외). `--verify`는 게시된 자료를 복호화해 재생·실행 검사만 한다.

## 4. 쓰지 않는 import는 없다

- 준비 코드와 정답에 정답이 쓰지 않는 import를 두지 않는다. 그래프 미션에 `import seaborn as sns`가 있는데 matplotlib만 쓴다면 그 줄은 없어야 한다.
- 빌드가 처리한다: 준비 코드의 import 중 정답이 쓰지 않는 줄은 준비 코드와 정답에서 함께 뺀다(`dsl.drop_unused_imports`). 정답 본문에 남은 쓰지 않는 import는 빌드 실패.

## 5. 파생물은 원본에 묶인다

- 학생이 보는 글은 블록 단위로 키·해시가 있고(`courses/kpc-finance.sources.json`), AI가 쓴 해설·주석은 어느 원본에 쓴 것인지 기록한다. 원본이 바뀌면 빌드가 거부하고 바뀐 부분만 다시 만든다. 자세한 것은 `docs/agents/narration.md`.
