# 콘텐츠 룰

플레이어 리포지터리 수준의 공통 콘텐츠 가이드다. 모든 수업의 필수 규칙, 권장 교육 방식, 수업별 자율 영역을 구분한다. 말투·용어는 `docs/voice.md`, 해설 대본의 형식은 `docs/agents/narration.md`를 따른다. LLM이 만드는 글(해설, 주석)의 프롬프트에는 이 파일이 들어간다.

## 모든 수업의 필수 구조

수업은 챕터, 챕터는 단원, 단원은 스텝으로 구성한다. 이 포함 관계는 수업마다 바꾸지 않는다. 각 용어의 정의는 `CONTEXT.md`를 따른다.

새로 합의한 구조를 기존 수업 데이터와 플레이어에 반영하는 작업은 별도다. 이 정책 기록만으로 구현이 바뀌지는 않는다.

## 모든 단계의 교육 목표는 필수

**수업·챕터·단원·스텝에는 각각 교육 목표가 반드시 있어야 한다.** 권장 사항이나 수업별 선택 사항이 아니다. 상위 단계의 목표가 있다는 이유로 하위 단계의 목표를 생략하지 않는다.

- 수업: 해당 수업의 교육 목표를 명시한다.
- 챕터: 각 챕터의 교육 목표를 명시한다.
- 단원: 각 단원의 교육 목표를 명시한다.
- 스텝: 각 스텝의 교육 목표를 명시한다.

콘텐츠를 점검할 때 네 단계 각각의 목표가 명시되어 있는지 확인한다. 수업 소개나 제목을 목표가 있는 것으로 자동 간주하지 않는다.

교육 목표는 내부 제작 자료에만 두지 않고 **사용자에게 명확히 노출한다.** 수업을 보면 수업의 목표, 챕터를 보면 챕터의 목표, 단원을 보면 단원의 목표, 스텝을 보면 스텝의 목표를 해당 화면에서 확인할 수 있어야 한다.

목표는 한 줄로 제한하지 않는다. 필요한 경우 여러 줄이나 여러 항목으로 작성하고 표시한다. 각 목표는 해당 단계에서 무엇을 배우고 이해하게 되는지 명확하게 전달한다.

## 콘텐츠 계층과 변경 검토

교육 목표 → 핵심 흐름 → 학습 콘텐츠 → 부가 설명 자료의 관계를 따른다. 각 용어는 `CONTEXT.md`에서 정의한다. 핵심 흐름은 내부 마크다운 원문이며 학생에게 직접 노출하지 않는다.

원본이 바뀌면 변경 전후의 차이를 근거로 바로 인접한 레이어의 수정 필요성만 검토한다. 실제로 수정하지 않으면 그 경로의 전파는 멈춘다. 수정한 경우에만 그 차이를 다음 레이어로 전달한다. 검토 근거·결과·이유를 남기고, 실패나 미확인을 영향 없음으로 취급하지 않는다.

이미지는 교육적 의미와 필수 요소를 정의한 원본 설명문을 갖는다. 생성 프롬프트·설정은 따로 관리한다. 이미지의 의미에 영향이 없으면 기존 이미지를 유지한다. 해설·음성 등 파생물도 필요한 부분만 다시 만들고 재사용 가능한 결과는 캐싱한다.

## 단순함과 점진적 과부하

**Simple is best.** 문제와 수행 행동, 풀이 논리를 단순하고 명확하게 만든다. 화려한 효과·잦은 화면 방식 전환·작성량으로 학습 부담을 만들지 않는다. 이미 이해한 것에 조건과 판단을 조금씩 더해 문제 배열 자체가 징검다리가 되게 한다.

최소한 한 단원에는 하나의 이어지는 상황이 있다. 기본 전제를 공통으로 두고, 각 스텝에서는 달라진 조건·사건만 짧게 보여 준다. 매 문제마다 긴 배경을 새로 읽게 하지 않는다. 긴 설명은 단계적으로 펼치거나 적절한 그림으로 돕는다.

## 수업 PRD와 승인

수업을 만들기 전에 제목·교육 목표·대상·선수 지식·범위·조사 근거·교육 방향·구성·판정·초기화·검증 기준을 PRD에 종합한다. 적용한 공통 교육 철학의 버전을 기록한다. 외부 문서를 매번 조합하지 않아도 이 PRD를 제작 기준으로 삼을 수 있어야 한다. 특별한 교육 전략은 필요할 때만 적는다.

PRD와 대표 문제 초안을 함께 승인받은 뒤 정식 제작한다. 승인 범위 안의 수정·오탈자·명백한 오류는 자율적으로 고치고 변경 이력을 남긴다. 목표나 적용 교육 기법이 바뀌면 다시 승인받는다. 새 교육 기법은 용어·배경·근거·한계·예시를 소개하고 승인받은 것만 채택한다.

공통 철학이 바뀌면 먼저 PRD에 대한 영향을 검토한다. 영향이 없으면 검토한 버전만 갱신하고 멈춘다. 실제 수정이 필요할 때 해당 PRD와 관련 하위 레이어로 변경을 이어간다.

## 문제 정체성과 성취

한 번 만든 문제의 본질은 유지한다. 본질이 달라지면 기존 문제를 비활성화하고 새 고유 코드의 문제를 추가한다. 기존 완료 이력은 보존하고 새 문제의 완료로 옮기지 않는다.

해설 열람만으로 통과시키지 않는다. 해설을 본 뒤 직접 풀어 맞혀도 정상 성공이다. 성공 전 열람과 성공 후 열람을 부가 정보로 구분하고, 학생에게는 상세의 작은 아이콘으로만 표시한다. 재도전에 쿨다운을 두지 않는다. 힌트는 필수가 아니다.

해설은 학생의 답안·선택·입력·실습 상태를 보존한 채 시연하고 종료·중단 뒤 복귀할 수 있게 한다. 음성과 정확한 버튼·코드 줄·결과 강조가 맞아야 하며, 음성이 준비되기 전에 화면만 먼저 진행하지 않는다.

## 권장 교육 방식

**실제 문제를 풀면서 원리를 깨우친다.** 작고 단순한 문제에서 시작해 조건과 복잡도를 점진적으로 높인다. 학습자가 직접 풀고 결과를 관찰하면서 개념을 서서히 발전시키고, 스스로 원리를 발견하게 하는 것이 기본 방향이다. 이 교육 방식은 권장이며 모든 수업의 필수 형식은 아니다.

핵심 제작 기준은 **작은 실습 경험이 이어지면서 원리가 자연스럽게 이해되는가**다. 학생이 앞 문제에서 발견한 관계를 다음 문제에 적용하고, 결과가 달라진 이유를 스스로 납득하도록 문제의 연결과 난도 상승을 설계한다.

- 처음 배우는 사람이 시작할 수 있는 작은 문제부터 구성한다. 문제마다 필요한 선수 지식을 앞선 학습에서 다룬다.
- 앞 문제의 경험을 바탕으로 다음 문제에 새로운 조건이나 관계를 조금씩 더한다. 개념의 발전과 문제 난도의 상승이 이어지도록 구성한다.
- 실제 문제 풀이와 판단을 중심에 둔다. 객관식도 AI가 제시한 대안을 이해·비교·선택·검증하는 중요한 학습·평가 수단이다. 문제의 조건과 선택지가 그 능력을 드러내게 설계한다. 객관식 점수만으로 실무 능력을 입증한다고 주장하지 않는다.
- 준비된 코드와 자료를 제공한다. 학생은 핵심 부분을 조금 바꾸고 실행하며 차이를 확인한다. 많은 코드를 직접 작성하는 부담보다 원리를 이해하는 데 집중한다.
- 원리를 확인하는 문제와 배운 것을 조합하는 도전 문제를 함께 구성한다. 도전에서도 불필요한 반복 입력은 줄인다.
- 해설은 과외 선생님처럼 판단 근거를 친절히 설명한다. 코드를 조금 바꾸고 실행한 뒤 결과를 읽는 과정을 단계적으로 보여 준다. 설명하는 코드 줄과 화면 요소를 정확히 강조한다.
- 값의 변화나 관계를 그림으로 보면 도움이 되는 경우에는 비주얼라이저를 활용한다.

일반 개발 과정은 원리 이해와 판단을 중심에 둔다. 수료 후 AI 중심 개발을 지향해도 학습 중 손코딩을 금지하지 않는다. 직접 작성·수정은 이해에 필요한 만큼 사용한다. 자격증은 공식 범위·실제 답안 수행·시험 제약을 먼저 분석하고 필요한 기억·직접 작성·판단 연습을 따로 설계한다.

Mermaid 다이어그램과 UML 표현, 발전적 인터랙티브 시각화, 이미지·만화는 선택 자료다. 만화를 특히 중요하게 고려하되 매 스텝에 강제하지 않는다. 문제 풀이 흐름을 단순하게 만드는 경우에 사용한다.

## 수업별 자율 영역

각 수업은 고정된 포함 관계 안에서 콘텐츠 방식과 스텝의 구체적인 종류를 정한다. 수업 목표와 대상에 맞게 권장 교육 방식을 달리 적용할 수 있다. 공통 스텝 유형 목록은 아직 확정하지 않았다.

## 기존 코딩 콘텐츠 제작 규칙의 적용 범위

아래 규칙은 기존 코딩 해설·정답 제작과 빌드 검사의 기준이다. 해당 코딩 콘텐츠에 적용하며, 모든 종류의 스텝에 코드 입력·실행을 강제하는 뜻은 아니다. 수업 본편과 도전 과제의 코딩 콘텐츠에 같은 기준을 적용한다.

## 1. 코딩 해설은 프로그램이 자라는 걸 보여 준다

- 한 번에 다 쓰고 끝에 한 번 실행하지 않는다. **살짝 코딩 → 실행 → 출력 읽기**를 반복한다. 보는 사람이 "아, 이렇게 발전하는구나"를 느껴야 한다.
- 조각은 1~3줄. 실행했을 때 오류 없이 무언가 보이는 자리에서 실행한다(변수를 만들었으면 print로 확인).
- 결과 줄은 그 시점에 실제로 나온 값을 말한다. 생성 도구가 run마다 코드를 실제로 돌려 맞춘다.
- 빌드 강제: 조각이 둘 이상이면 실행이 둘 이상, 실행 뒤엔 결과 읽기, 마지막 조각 뒤에 실행·결과·제출.

## 2. "이렇게 해볼까요? 이렇게 하기 쉬운데, 그러면 이런 문제가 생기니 조심하세요"

- 코딩 해설마다 1~2번. 틀리기 쉬운 줄을 **실제로 쳐 보고**(try) 실행해서 무엇이 잘못되는지 보여 준 뒤 **되돌린다**(undo), 또는 코드를 치지 않고 말로만 짚는다(caution).
- 흔한 실수 예: 따옴표를 빼먹거나 붙임, 숫자를 글자로 계산, 열 이름 오타, 0부터 세는 자리, 괄호 안 닫음, 테스트 자료로 학습, 시간 순서를 섞어 나눔.
- 빌드 강제: try/undo 또는 caution이 하나 이상.

## 3. 정답 코드에는 주석이 풍부하다

- 모든 정답 코드(정답 보기, 해설이 타이핑하는 코드, `courses/kpc-solutions.json`)에 `#` 주석을 단다. 그 줄이 무엇을 왜 하는지, 수강생이 헷갈리는 지점을 짚는다. 코드 2~3줄마다 하나 이상.
- 주석은 해설(말)로 읽지 않는다. 해설은 코드가 하는 일을 말하고, 주석은 화면에 남는 글이다.
- 주석은 코드를 바꾸지 않는다. 주석을 지우면 원래 코드와 줄 단위로 같아야 하고, 준비 코드 부분은 글자 그대로 둔다. 도구: `python tools/annotate.py`(캐시 `tools/kpc_course/solution_comments/`, 원본 코드 해시로 신선도 관리).
- 도전 과제의 정답·해설은 강사 자료(암호화, `site/data/instructor.json`)에 있다. `python tools/practice-materials.py`가 같은 규칙으로 주석과 해설을 만들어 이 컴퓨터의 비밀번호 파일로 암호화한다(평문과 비밀번호는 `target/course-guide-authoring/`, Git 제외). `--verify`는 게시된 자료를 복호화해 재생·실행 검사만 한다.

## 4. 쓰지 않는 import는 없다

- 준비 코드와 정답에 정답이 쓰지 않는 import를 두지 않는다. 그래프 미션에 `import seaborn as sns`가 있는데 matplotlib만 쓴다면 그 줄은 없어야 한다.
- 빌드가 처리한다: 준비 코드의 import 중 정답이 쓰지 않는 줄은 준비 코드와 정답에서 함께 뺀다(`dsl.drop_unused_imports`). 정답 본문에 남은 쓰지 않는 import는 빌드 실패.

## 5. 파생물은 원본에 묶인다

- 학생이 보는 글은 블록 단위로 키·해시가 있고(`courses/kpc-finance.sources.json`), AI가 쓴 해설·주석은 어느 원본에 쓴 것인지 기록한다. 원본이 바뀌면 빌드가 거부하고 바뀐 부분만 다시 만든다. 자세한 것은 `docs/agents/narration.md`.
