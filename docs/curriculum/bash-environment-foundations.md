# 환경 변수: 독립 최소 실험과 세션 계약

2026-10-20. `bash-environment`의 실행 가능한 다음 제작 초안이다. 정식 수업·과정에는 아직 등록하지 않았다.

## 먼저 이해할 것

앱 설정이나 서버를 만들기 전에 값 하나가 어느 프로세스에서 보이는지 확인한다. 변수 이름은 MQ_LABEL 하나다. Bash에서 이미 배운 실행·문자열 출력만 사용한다. 자식용 두 스크립트는 제공된 준비 코드라고 먼저 설명하고, 각각의 내용을 읽어 무엇을 출력·변경하는지 확인하게 한다.

| 단계 | 바꾸는 조건 | 실제 관찰 |
| --- | --- | --- |
| 1 | 현재 Bash에서 변수 하나에 Blue 저장 | 현재 셸은 Blue를 읽음 |
| 2 | 같은 이름을 자식 Bash에서 읽기 | export 전에는 unset |
| 3 | 같은 값을 export한 뒤 자식 실행 | 자식은 Blue를 읽음 |
| 4 | 명령 앞에 Green을 한 번 지정 | 그 자식만 Green을 읽음 |
| 5 | 임시 지정 없이 다음 자식 실행 | 다시 Blue를 읽음 |
| 6 | 자식 안에서만 Green으로 변경 | 그 자식은 Green을 읽음 |
| 7 | 원래 부모 Bash에서 다시 읽기 | 부모는 계속 Blue를 읽음 |
| 8 | 부모에서 unset 후 자식 실행 | 다시 unset |

이후 System.getenv, 시스템 속성, .env 파일, 배포 설정은 각각 별도 예제로 연결한다. export를 운영체제의 영구 설정 변경이라고 설명하지 않는다. 새 프로세스가 어떤 부모에서 시작됐는지도 구분한다.

## 확인한 실행기 차이

현재 GitTerminal은 컴포넌트가 사라질 때 PTY를 종료한다. 문제를 바꾸면 같은 파일 폴더를 다시 열어도 새 셸이다. 따라서 위의 8단계를 기존 파일 연속 실습처럼 그대로 등록하면 앞 단계의 변수·export 상태가 사라진다. 해설용 준비 코드로 이를 몰래 보충하면 개념과 실제 동작이 어긋난다.

정식 등록 전에는 학습자 세션이 살아 있는 동안 같은 Bash를 유지하고, 단계별 목표·명령 체크포인트만 바꾸는 계약을 구현·검증한다. 해설은 별도 세션이다. 앱 재실행·초기화로 새 셸이 생기면 그 사실을 표시하고 필요한 앞 실습을 다시 수행하게 한다. 변수를 파일로 직렬화해 Bash 상속처럼 보이게 하지 않는다.

## 실행 근거와 다음 판정

`python tools/verify-bash-environment-prototype.py`는 실제 Bash 한 프로세스에서 8단계를 수행한다. Blue/Green과 Amber/Purple 두 사례를 검사한다. 새 Bash를 다시 열었을 때 기존 변수 없이 export만 실행하면 값이 생기지 않는 반례도 확인했다. 결과는 `target/bash-environment-prototype/evidence.json`에 기록한다.

후속 앱 검사는 단계 이동 뒤 같은 셸 상태, 두 실습 간 격리, 해설 중단/완료 뒤 부모 상태, 새 셸 표시, 오류 뒤 재시도, 초기화 후 자식 종료, 실제 Windows·Mac을 포함한다. 이 경계를 통과하기 전에는 해당 수업을 제공 중이라고 표시하지 않는다.

## 2026-10-29 정식 수업으로 분리·등록

이 초안의 8단계를 세 수업으로 나눠 등록했다: `bash-variables`(셸 변수), `bash-environment`(export와 자식 프로세스), `bash-command-env-args`(명령 한 번의 환경 값과 실행 인자, 자바 `System.getenv`). 위의 "같은 Bash를 단계 사이에 유지하는 계약"은 만들지 않았다. 대신 각 스텝이 새 Bash에서 시작하는 짧은 실험이 되도록 설계했고, 새 셸에 이전 export가 없다는 사실 자체를 `bash-environment`의 관찰 대상으로 쓴다. 단계 사이에 변수를 몰래 다시 만들지 않는다. 계획과 근거: `docs/plans/2026-10-29-shell-env-lessons-reset-challenge.md`. 실제 PTY 검증: `tests/shell_environment_lessons.rs`. 이 파일의 prototype.json과 검증 스크립트는 이전 기록으로 남긴다.
