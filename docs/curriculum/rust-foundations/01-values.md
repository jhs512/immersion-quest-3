# R1 · Rust에서 값을 담고 변경을 구분해요

상태: 승인 검토용 PRD와 대표 문제 초안.

## 목표·대상·선수 경험

수업 목표는 값·타입·변경 가능성을 구분하는 것이다. 학습자에게는 "값을 출력하고, 바꿀 수 있는 이름을 구분해요"로 보여준다. 대상은 자바 백엔드 과정 초반 학습자다. 키보드 입력과 코드 실행·결과 확인 경험만 권장한다. Java 객체나 메모리 관리 지식은 요구하지 않는다.

제공된 `main.rs`와 `fn main` 골격에서 시작한다. 학생이 처음에 작성하는 것은 문자열·숫자 한 곳이다. `println!`은 출력 도구로 제공한다. 매크로 작성법, 소유권, 참조, Cargo 의존성, 서버는 제외한다.

## 계층별 목표와 핵심 흐름

| 챕터 | 챕터 목표 | 단원 | 단원 목표 |
| --- | --- | --- | --- |
| 1. 값과 이름 | 값이 출력으로 이어지는 과정을 확인해요. | A. 표시할 값 | 문자열과 숫자를 출력해요. |
| 1. 값과 이름 | 값이 출력으로 이어지는 과정을 확인해요. | B. 계산에 붙인 이름 | 이름을 통해 같은 값을 사용해요. |
| 2. 변경과 타입 | 변경 가능성과 값의 종류를 구분해요. | C. 다시 넣을 수 있는 값 | `let`과 `let mut`의 차이를 확인해요. |
| 2. 변경과 타입 | 변경 가능성과 값의 종류를 구분해요. | D. 값의 종류 | 정수·참거짓과 타입 표기를 구분해요. |

같은 작은 재고 상황을 이어 간다. 글자를 출력하고, 수량을 출력한 뒤, 수량에 이름을 붙인다. 계산한 값과 다시 대입하는 동작을 구별한 후 변경 허용을 관찰한다.

| 스텝·단원 | 학습자가 볼 목표 | 새 개념 하나 | 이미 해 본 경험 | 바꾸는 조건·학생 수정 | 관찰 근거 | 새 외부 서비스 |
| --- | --- | --- | --- | --- | --- | ---: |
| 1·A | 표시할 문구를 바꿔요. | 문자열 리터럴 | 실행 버튼 | 따옴표 안 문구 한 곳 | 출력 문구 | 0 |
| 2·A | 숫자를 글자와 구분해 출력해요. | 정수 값 | 출력 확인 | 출력할 정수 한 곳 | 숫자 출력 | 0 |
| 3·B | 값에 이름을 붙여 사용해요. | `let` 바인딩 | 정수·출력 | 출력의 상수를 변수로 교체 | 같은 값의 출력 | 0 |
| 4·B | 이름으로 수량 계산을 표현해요. | 정수 연산 | 변수 | 빼는 수량 한 곳 | 계산 전후 값 | 0 |
| 5·C | 바꾸지 않는 이름을 확인해요. | 기본 불변성 | 변수·연산 | 재대입 한 줄을 추가한 제공 코드 실행 | E0384, 실행되지 않음 | 0 |
| 6·C | 바꿀 값을 명시해요. | `mut` | 불변성 오류 | 선언에 `mut` 추가 | 컴파일 성공·남은 수량 | 0 |
| 7·D | 정수 타입을 명시해요. | `i32` 타입 표기 | 정수 변수 | 타입 표기 한 곳 | 값과 계산 결과 유지 | 0 |
| 8·D | 참과 거짓 값을 구분해요. | `bool` | 출력·타입 | `true`를 `false`로 교체 | 참거짓 출력 | 0 |
| 9·D | 변경 허용과 계산을 함께 적용해요. | 새 개념 없음 | 1~8 | 재고의 선언·차감 한두 줄 | 다른 시작 수량에서도 계산 유지 | 0 |

## 대표 문제 · 남은 수량을 다시 담아요

챕터 2, 단원 C의 6번 스텝이다. 목표는 "바꿀 값에 `mut`를 붙여요"다. 앞 스텝에서는 `let stock = 5;`만 출력하면 정상 실행되는 것을 확인했다. 이번에는 재대입이 추가된 **컴파일 실패 상태를 제공한다**. 학생의 앞 풀이가 자동으로 이어진 상태가 아니다.

초기 코드는 [01-values-starter.rs](representatives/01-values-starter.rs), 정답 초안은 [01-values-solution.rs](representatives/01-values-solution.rs)다. `stock` 선언 한 곳만 고친다. 출력문이나 차감 수량을 고치지 않는다.

학습자에게 보일 할 일은 다음과 같다.

1. 제공된 코드를 실행하세요.
2. 바꿀 수 없다는 오류가 가리키는 이름을 확인하세요.
3. `stock` 선언에 `mut`를 추가하세요.
4. 다시 실행해 남은 수량을 확인하세요.
5. 현재 답안을 제출하세요.

초기 코드는 E0384로 컴파일에 실패해야 한다. 정답은 `남은 수량: 3`을 출력한다. 시작 수량만 8로 바꾸면 6을 출력해야 한다. 출력에 3을 고정한 답은 변형에서 실패하도록 판정한다. 진단의 번역 문장 전체가 아니라 실패 여부·E0384와 해당 선언 위치를 확인한다.

## 판정·초기화·검증

정식 제작에서는 정답, 잘못된 초기 코드, 시작 수량 변형, 출력 상수로 우회한 오답을 Windows·macOS에서 실행한다. R1~R4 공통 [제작 기준과 정책 버전](README.md#공통-제작-기준과-버전)을 적용한다. 초기화는 이 스텝의 제공 코드·입력·결과로 복구하고 기존 완료 기록은 보존한다.

해설 초안은 정상 선언 출력→재대입 실패→`mut` 수정→실행·결과 확인으로 나눈다. "모든 변수에 `mut`를 붙이면 된다"고 설명하지 않는다. 불필요한 변경 허용을 넣지 않는 예를 함께 비교한다. 비주얼라이저는 두 실행 시점의 `stock` 값 관찰에 도움이 될 때 사용한다. 컴파일 실패 단계에는 실행된 것처럼 값 변화를 그리지 않는다.

근거는 기본 불변 바인딩과 명시적인 `mut`를 설명하는 [Rust 공식 책의 변수와 변경 가능성](https://doc.rust-lang.org/book/ch03-01-variables-and-mutability.html)이다. 대표 문제의 실측은 [검증 기록](verification.md)에 적는다.
