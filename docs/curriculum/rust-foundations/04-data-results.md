# R4 · 여러 값과 없는 값·실패를 다뤄요

상태: 승인 검토용 PRD와 대표 문제 초안.

## 목표·대상·선수 경험

수업 목표는 구조화한 값과 조회·변환 결과를 타입으로 구분하는 것이다. 학습자에게는 "여러 값을 묶고, 없는 값과 실패 결과를 구분해요"로 보여준다. R1~R3의 값·분기·함수·변경·읽기 빌림을 권장 선수 경험으로 둔다.

작은 상품 정보와 가격 목록을 사용한다. 구조체, Vec, Option, Result는 각기 다른 단원에서 소개한다. 첫 스텝부터 네 가지를 한꺼번에 읽게 하지 않는다. 제네릭 타입·trait 구현, 반복자 체인, `?` 전파, 파일·네트워크·DB와 외부 크레이트는 제외한다. `unwrap`으로 실패를 숨기거나 강제 종료하는 풀이를 기본 해법으로 가르치지 않는다.

## 계층별 목표와 핵심 흐름

| 1. 모아 둔 값 | 값의 이름과 목록을 구분해요. | B. Vec | 목록에 값을 더하고 빌려서 읽어요. |
| 2. 결과의 구분 | 값이 없는 경우와 실패를 다뤄요. | C. Option | 조회 성공·없음을 분기해 처리해요. |
| 2. 결과의 구분 | 값이 없는 경우와 실패를 다뤄요. | D. Result | 변환 성공·실패를 분기해 처리해요. |

| 2·A | 필드를 읽고 한 곳만 바꿔요. | 필드 접근·변경 | 구조체·`mut` | 필드 대입 한 줄 | 다른 필드는 유지 | 0 |
| 3·B | 같은 타입의 값을 목록으로 담아요. | `Vec`·`vec!` | 값·출력 | 원소 한 곳 | 제공된 출력의 목록 | 0 |

| 8·C | 값 0과 없는 값을 구분해요. | 새 개념 없음 | Option·match | None 문구 한 줄 | 가격 0·목록 밖 조회의 차이 | 0 |
| 9·D | 변환의 성공·실패 결과를 확인해요. | `Result` | match·정수 | 제공된 변환 입력 한 곳 | `Ok`·`Err` 갈래 | 0 |

9번은 제공된 작은 변환 함수의 Result를 먼저 읽는다. 함수 내부의 `parse`는 10번에서 관찰한다. 제네릭 함수 표기 전체를 새로 작성시키지 않는다. 외부 입력 파싱·예외 전파까지 한 문제에 추가하지 않는다.

## 대표 문제 · 가격 0과 상품 없음은 달라요

챕터 2, 단원 C의 8번 스텝이다. 목표는 "`None`을 실제 값 0과 구분해 표시해요"다. 가격 목록과 조회 위치·`match` 골격을 제공한다. 초기 코드는 실행되지만 없는 상품을 가격 0이라고 표시한다.

초기 코드는 [04-data-starter.rs](representatives/04-data-starter.rs), 정답 초안은 [04-data-solution.rs](representatives/04-data-solution.rs)다. `None` 갈래의 출력 한 줄만 고친다.

1. 제공된 조회 위치로 코드를 실행하세요.
2. 목록 밖 조회의 결과가 `None`인지 확인하세요.
3. `None` 갈래를 "상품 없음"으로 바꾸세요.
4. 목록 안·밖의 위치를 각각 실행하세요.
5. 첫 가격을 0으로 바꿔 없는 상품과 다른지 확인하세요.
6. 현재 답안을 제출하세요.

대표 초기 코드는 `가격: 0`, 정답은 `상품 없음`을 출력한다. 위치 0·1은 각각 1200·1800의 가격을 표시한다. 첫 원소가 실제 0이면 `가격: 0`을 표시해야 한다. 모든 입력에 "상품 없음"을 출력하는 답은 실패해야 한다.

## 판정·초기화·검증

정식 제작에서는 구조체의 다른 필드 보존, Vec 끝 추가와 조회 범위, Some·None, Ok·Err를 각각 검사한다. 라이브러리 오류 메시지 전체나 내부 메모리 배치를 고정된 정답으로 삼지 않는다. Rust의 Vec·String 내부 레이아웃을 언어가 보장하는 고정 형태라고 설명하지 않는다.

비주얼라이저는 구조체 필드·작은 Vec의 값 변화를 확인하는 보조 자료다. 현재 Rust 실행·추적 연결은 제작 중이다. 큰 Vec·제네릭·라이브러리 타입은 실제 지원 실험을 통과한 범위만 표시한다. 요약·일부 생략이면 그 범위를 학습자에게 알린다. 실행되지 않은 분기의 상태나 Option의 없는 값을 만들어 채우지 않는다.

R1~R4 공통 [정책 버전·초기화·답안 보존](README.md#공통-실행과-판정)을 적용한다. 해설에서 가격이 0인 경우와 없는 경우를 실제 입력으로 비교한다. 그림이나 비주얼라이저를 여는 행위 자체를 학습 목표로 삼지 않는다.

근거는 [구조체](https://doc.rust-lang.org/book/ch05-01-defining-structs.html), [Vec](https://doc.rust-lang.org/book/ch08-01-vectors.html), [Option](https://doc.rust-lang.org/book/ch06-01-defining-an-enum.html#the-option-enum-and-its-advantages-over-null-values), [match](https://doc.rust-lang.org/book/ch06-02-match.html), [Result](https://doc.rust-lang.org/book/ch09-02-recoverable-errors-with-result.html)의 공식 설명이다. 대표 문제의 실측은 [검증 기록](verification.md)에 적는다.
