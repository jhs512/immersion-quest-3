# R3 · 소유권과 빌림을 구분해요

상태: 승인 검토용 PRD와 대표 문제 초안.

## 목표·대상·선수 경험

수업 목표는 이동·복사·빌림 뒤에 사용할 수 있는 값을 구분하는 것이다. 학습자에게는 "값을 넘길 때 소유권을 옮길지 빌려줄지 구분해요"로 보여준다. R1의 변경 가능성과 R2의 함수 인자·반환을 권장 선수 경험으로 둔다.

짧은 ASCII 문자열 하나와 정수 하나를 사용한다. `String`은 이번 수업에서 처음 소개한다. 컴파일러의 사용 가능 판정을 먼저 관찰하고 메모리 그림은 보조 근거로만 사용한다. 명시적 lifetime, 스마트 포인터, 사용자 정의 `Drop`, raw pointer, unsafe, 동시성은 제외한다. Rust가 추적형 GC를 반드시 사용한다고 설명하지 않는다.

## 대표 문제 · 제목을 보여줘도 소유자는 유지해요

챕터 2, 단원 C의 6번 스텝이다. 목표는 "읽기만 하는 함수에는 값을 빌려줘요"다. 앞선 단계에서 `String`을 함수에 넘기면 이동한다는 것을 확인했다. 이번 초기 코드는 함수 호출 뒤 원래 문자열을 다시 사용해서 **컴파일에 실패하는 상태를 제공한다**.

초기 코드는 [03-ownership-starter.rs](representatives/03-ownership-starter.rs), 정답 초안은 [03-ownership-solution.rs](representatives/03-ownership-solution.rs)다. 매개변수 타입과 호출 인자의 두 줄만 고친다. `clone`을 요구하지 않으며 출력문 삭제로 사용을 피하지 않는다.

1. 제공된 코드를 실행하세요.
2. 제목이 함수로 이동했다는 오류를 확인하세요.
3. 함수가 `String`을 빌리도록 매개변수 타입을 바꾸세요.
4. 호출할 때도 제목을 빌려주세요.
5. 다시 실행해 함수 안과 호출 뒤의 출력을 확인하세요.
6. 현재 답안을 제출하세요.

초기 코드는 E0382로 실패해야 한다. 정답은 `MQ`를 두 번 출력한다. 제목을 `Rust`로 바꿔도 두 번 출력해야 한다. 출력문을 지우거나 항상 문자열 상수를 출력하는 우회 답은 허용하지 않는다. 정식 판정은 출력과 함께 읽기 참조 매개변수·호출 뒤 원래 바인딩 사용을 확인한다. 다른 타당한 빌림 표현은 문법 한 형태만 강요하지 않는다.

## 판정·초기화·검증

일반 값 복사와 `String`의 이동을 같은 동작으로 표시하지 않는다. 이동 뒤에 메모리에 남은 비트가 있더라도 유효한 원래 바인딩으로 그리지 않는다. 이 정확성은 비주얼라이저 구현팀의 별도 통과 조건이며 현재 검증 완료가 아니다. 빌림의 유효성은 컴파일러로 먼저 판정한다.

`String::len`을 쓰는 후속 문제가 생기면 UTF-8 바이트 수라는 의미를 명시한다. 이 초안의 대표 문제는 길이 계산을 사용하지 않아 문자 수와 바이트 수를 섞지 않는다. `clone`은 "언제나 금지"도 "빌림 오류의 기본 해법"도 아니다. 독립 복사가 필요한 목적과 읽기만 필요한 목적을 구분한다.

R1~R4 공통 [정책 버전·초기화·답안 보존](README.md#공통-실행과-판정)을 적용한다. 해설은 이동 오류→읽기 빌림 수정→실행·출력으로 나눈다. 빌림을 설명할 때만 검증된 비주얼라이저를 사용하며, 아직 지원하지 않는 소유권 상태를 애니메이션으로 꾸미지 않는다.

근거는 [소유권](https://doc.rust-lang.org/book/ch04-01-what-is-ownership.html)과 [참조와 빌림](https://doc.rust-lang.org/book/ch04-02-references-and-borrowing.html)의 공식 설명이다. 대표 문제의 실측은 [검증 기록](verification.md)에 적는다.
