# R2 · 조건과 반복을 함수로 나눠요

상태: 승인 검토용 PRD와 대표 문제 초안.

## 목표·대상·선수 경험

수업 목표는 조건·반복·함수의 실행 순서를 근거로 결과를 설명하는 것이다. 학습자에게는 "조건을 고르고, 반복할 일을 함수로 나눠요"로 보여준다. R1의 값·출력·변수·정수 연산·`mut`·`bool` 경험을 권장한다. Java의 조건문·배열·메서드는 선수 조건이 아니다.

배송비 하나와 작은 수량 계산에서 시작한다. `if`는 한 갈래씩, 반복은 실행 횟수가 눈에 보이는 작은 범위, 함수는 인자와 결과를 각각 익힌다. 컬렉션·재귀·소유권·파일 입력·외부 크레이트는 제외한다.

## 대표 문제 · 30,000원부터 배송비가 없어요

챕터 2, 단원 D의 9번 스텝이다. 목표는 "경계값도 조건에 포함해요"다. 제공된 `shipping` 함수와 실행 골격을 사용한다. 초기 코드는 정상 컴파일되지만 기준값 자체를 유료로 처리한다.

초기 코드는 [02-flow-starter.rs](representatives/02-flow-starter.rs), 정답 초안은 [02-flow-solution.rs](representatives/02-flow-solution.rs)다. 비교 연산자 한 곳만 바꾼다.

1. 제공된 코드로 30,000원의 배송비를 실행하세요.
2. 조건의 경계값과 비교 연산자를 확인하세요.
3. 경계값도 무료가 되도록 비교 연산자를 바꾸세요.
4. 29,999원·30,000원·30,001원을 각각 확인하세요.
5. 현재 답안을 제출하세요.

대표 초기 코드는 3000, 정답은 0을 출력한다. 변형에서 `shipping(29_999)`는 3000, `shipping(30_000)`과 `shipping(30_001)`은 0이어야 한다. 함수가 항상 0을 반환하는 우회 답은 앞 경계 검사에서 실패해야 한다. 반복문을 쓰지 않아도 되는 대표 문제에 반복문을 강요하지 않는다.

## 판정·초기화·검증

정식 제작에서는 조건의 양쪽과 정확한 경계를 테스트한다. 범위 문제는 끝을 포함한다고 착각한 오답을 검사한다. 반환 문제는 끝 표현식 뒤의 세미콜론이 반환 타입과 맞지 않는 실패를 별도 스텝으로 다룰 수 있다. 그 경우 다른 새 문법을 동시에 요구하지 않는다.

R1~R4 공통 [정책 버전·초기화·답안 보존](README.md#공통-실행과-판정)을 적용한다. 해설에서는 조건 한 곳 변경 뒤 세 경계값을 차례로 실행한다. 함수 호출과 반환을 보기가 도움 될 때 비주얼라이저를 사용한다. 반복문이 실제로 편리한 스텝은 같은 처리가 여러 값에 적용되는 배치로 검증한다.

근거는 [제어 흐름](https://doc.rust-lang.org/book/ch03-05-control-flow.html)과 [함수](https://doc.rust-lang.org/book/ch03-03-how-functions-work.html)의 공식 설명이다. 함수의 입력·반환은 조건·반복과 처음부터 한꺼번에 도입하지 않는다. 대표 문제의 실측은 [검증 기록](verification.md)에 적는다.
