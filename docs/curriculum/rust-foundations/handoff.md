# Rust 기초 네 수업 인계

이 폴더는 승인 검토용 설계와 실행 가능한 대표 문제다. 정식 수업 네 개가 등록됐다는 뜻이 아니다. 기존 코스 파일, 수업 식별자, 학습 진도, 필수 수업 여부는 수정하지 않았다.

검토 순서:

1. [설계 요약과 공통 기준](README.md)에서 제안 위치·선택 수업 여부를 검토한다.
2. 네 PRD의 수업·장·단원·스텝 목표와 선수 경험을 검토한다. R1 값과 변경 → R2 흐름과 함수 → R3 소유권과 빌리기 → R4 구조화한 값과 결과 순서다.
3. `representatives/`의 초기 코드·정답을 [검증 명령](verification.md)으로 실행한다.
4. PRD와 대표 문제의 승인을 받은 뒤 정식 제작한다. 승인 전에는 계획 스텝을 앱에 넣지 않는다.

후속 담당자가 지켜야 할 범위:

- 모든 코스의 레벨링과 비주얼라이저 활용 해설 재검토 계획은 별도 전반 작업이다. 이 초안은 Rust 도입 구간의 재료로 사용한다.
- JavaScript, Python, Java, C, C++, Rust의 Windows·macOS 실행·시각화 지원은 별도 실행기 작업이다. Rust 시각화 완료를 전제로 문구를 만들지 않는다.
- 관찰이 학습에 도움이 되는 단계에서 값의 변화·호출·이동·빌리기 해설을 붙인다. 해설은 실제 관찰된 상태만 가리킨다.
- 지원 범위와 큰 데이터는 실험으로 먼저 확인한다. 지원하지 않는 타입·잘린 출력은 사실대로 안내하며, 보여주기 위해 잘못된 메모리 상태를 만들지 않는다.
- 초안의 41스텝은 생산량 목표가 아니다. 기존 철학의 한 문제 한 개념·1~3줄 수정 기준에 따라 대표 문제 승인 때 조정한다.
- macOS 검증은 아직 없으며, 실제 UI·해설·등록·배포도 미실행이다. [검증 기록](verification.md)의 한계를 유지한다.
