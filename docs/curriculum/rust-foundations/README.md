# 자바 백엔드 과정의 Rust 기초 네 수업

상태: **승인됨, 정식 제작 중.** 콘텐츠와 코스 등록은 이 브랜치에 있다. 앱의 Rust 실행기 통합 전이며 게시하지 않았다.
기준일: 2026-11-02. 대상 코스 원본은 `courses/redesigned-courses/java-backend.json`이다.

## 승인 기록

2026-11-02 사용자가 구체 PRD와 대표 문제의 승인 질문에 「이 구성으로 제작」이라고 답했다(Codex 경유). `docs/content-rules.md`의 「PRD와 대표 문제 초안을 함께 승인받은 뒤 정식 제작한다」는 조건이 이것으로 충족됐다.

승인 범위:

1. Java 실행 수업("자바 · 파일 하나를 실행하고 다시 빌드해요") 직후에 Rust 네 수업을 연속 배치한다.
2. ① 값·타입·`mut`·출력 ② 조건·반복·함수 ③ 소유권·move·`clone`·빌림·`&mut` ④ `struct`·`Vec`·`Option`·`Result`·`match`.
3. 초안의 41스텝은 수량 강제가 아니다.
4. 신규 수업은 선택 수업(`required: false`)으로 추가한다. 이 문서의 초안 권장안을 그대로 따랐다.

각 수업의 `tools/redesigned_lessons/rust_*/approved-prd.json`은 이 승인을 `approval`에 기록한다(`stamp_prd.py`). 이 폴더의 `01`~`04` 문서는 승인된 초안으로 보존한다. 정식 제작의 스텝 구성은 [정식 제작 계획](production-plan.md)이 기준이다.

## 정식 제작 변경 기록

승인 범위 안에서 바꾼 것이다. 목표와 교육 기법은 바꾸지 않았다.

- 2026-11-02: 스텝을 41개에서 40개로 정했다(R1 9→8). 출력만으로 개념을 구분할 수 없는 R1·R3 스텝은 출력이 달라지는 문제로 바꿨다. R2 대표 문제는 채점이 금액을 바꿀 수 있게 `let total`을 둔다. 스텝별 내용과 이유는 [정식 제작 계획](production-plan.md#초안에서-바꾼-것)에 있다.
- 2026-11-02: 주제 분류(category)는 정하지 않았다. 승인된 분류가 없으면 앱에 「미분류」로 보인다. 분류는 별도 승인 대상이다.
- 2026-11-02: 마지막 도전 지정은 하지 않았다. 앱의 Rust 채점을 확인하기 전이기 때문이다(`lesson-challenges.json`의 `not_designated`).

## 배치와 범위

현재 코스의 44수업은 유지한다. 초반의 "자바 · 파일 하나를 실행하고 다시 빌드해요" 뒤, "자바 · 비교로 배송비를 고르는 과정" 앞에 네 수업을 연속해서 두는 안을 제안한다. Bash·Java 값·Vim·Java 실행을 본 뒤 같은 값·실행을 Rust로 관찰한다. Java 조건·배열·메서드를 먼저 알아야 Rust를 시작하게 만들지 않는다. Rust의 도입과 집중 연습을 한 구간에 묶는다.

| 순서 | 수업 | 수업 목표 | 계획된 스텝 |
| --- | --- | --- | ---: |
| R1 | [값을 담고 변경을 구분해요](01-values.md) | 값·타입·변경 가능성을 구분해요. | 9 |
| R2 | [조건과 반복을 함수로 나눠요](02-flow-functions.md) | 조건·반복·함수의 실행 순서를 확인해요. | 10 |
| R3 | [소유권과 빌림을 구분해요](03-ownership-borrowing.md) | 이동·복사·빌림의 사용 가능 범위를 확인해요. | 10 |
| R4 | [여러 값과 없는 값·실패를 다뤄요](04-data-results.md) | 구조화한 값과 조회·변환 결과를 타입으로 구분해요. | 12 |

41스텝은 설계 초안의 수다. 현재 앱에 추가된 문제 수가 아니다. R4는 구조체·Vec·Option·Result를 각기 다른 단원으로 나눈다. 하나의 문제에서 네 개념을 처음 요구하지 않는다. Dioxus, HTTP, DB, async, 외부 크레이트, 사용자 정의 trait와 lifetime 표기는 이번 범위에 넣지 않는다.

권장 순서는 R1→R2→R3→R4다. 추천 선수 관계로만 표시하며 진도 잠금을 만들지 않는다. 기존 Java 수업의 선수 관계와 required 값은 변경하지 않는다. 신규 네 수업은 초안에서 `required: false`를 권장한다. 자바 백엔드 코스의 기존 완료 조건을 조용히 확대하지 않기 위해서다. 필수 전환은 승인 때 별도로 확정한다.

## 공통 제작 기준과 버전

각 PRD는 아래 기준을 포함한다. 승인 뒤에도 이 버전을 기준으로 변경 영향을 검토한다.

| 근거 | 기준 |
| --- | --- |
| 정책 문서의 최근 변경 커밋 | `7515b2c267c6f8d64bb3b0264e2d9c61001af338`, 2026-10-24 |
| 현재 `docs/content-rules.md` SHA-256 | `6ade42ca3d906b604ba45eb6cd68c964c28657e951af0cf5c951b5d00c635fa3` |
| 현재 `docs/voice.md` SHA-256 | `64b92cd8829c27e01efebd34bbb4668da1acd40814837bc77d6ef6445b7719fc` |
| 현재 `docs/agents/narration.md` SHA-256 | `ccf5eb1dbf4189a78f4c0c8430ea1dec546cf4c44d6f6901033b8adf1a9e6def` |

- 개별 개념을 최소 예제로 먼저 관찰한다. 프로젝트의 기능 수를 성취로 삼지 않는다.
- 수업·챕터·단원·스텝마다 학습자가 볼 목표를 둔다.
- 각 스텝은 시작 상태와 순서 있는 "할 일"을 갖춘다.
- 정상 실행을 본 뒤 조건 하나를 바꾼다. 의도한 실패로 시작하는 대표 문제는 그 사실과 앞선 정상 상태를 먼저 설명한다.
- 한 단원은 같은 상황을 이어 간다. 학생은 보통 1~3줄을 고친다.
- 해설은 작은 수정→실행→출력 관찰로 구성한다. 실행하지 않은 결과를 말하지 않는다.
- 정답·변형 입력·흔한 오답을 실제 컴파일러로 판정한다. 경고 문구 전체나 우연한 주소값을 정답으로 삼지 않는다.
- 새로운 수업·챕터·단원·스텝은 새 리소스 코드를 받는다. 기존 ID와 완료 기록을 재사용하지 않는다.

## 공통 실행과 판정

대표 문제는 외부 의존성이 없는 `main.rs` 하나다. 초안 검증은 `rustc --edition=2024`로 컴파일한 뒤 실행한다. `cargo new`나 프로젝트 설정을 처음부터 학생에게 작성시키지 않는다. 준비된 파일과 컴파일·실행의 역할은 R1에서 설명한다.

Windows와 macOS에서 같은 정답·경계 변형을 실제 실행해야 한다. 현재 이 초안의 대표 문제 검증은 Windows의 `rustc 1.95.0 (59807616e 2026-04-14)`로 수행한다. macOS 검증 결과는 아직 없다. 두 운영체제의 Rust 실행기·비주얼라이저 연결도 별도 구현 중이며, 여기서 완료했다고 주장하지 않는다.

컴파일 실패는 프로그램이 실행되지 않은 결과다. 실행되지 않은 줄에 메모리 변화나 실행 애니메이션을 만들어 붙이지 않는다. 소유권·빌림 판정은 컴파일러 진단과 실제 사용 가능성으로 확인한다. 이동 뒤 메모리에 남은 비트를 유효한 Rust 바인딩처럼 표시하지 않는지 비주얼라이저에서 별도로 검사한다. 큰 Vec·긴 문자열·복잡한 타입은 실험한 관찰 한도만 제공하고 생략된 범위를 표시한다.

초기화는 현재 스텝의 초안·입력·결과만 준비된 초기 상태로 되돌린다. 다른 수업이나 완료 이력을 지우지 않는다. 해설 시연은 학생 답안의 복사본에서 실행하고 종료 뒤 학생 상태를 복원한다.

## 대표 문제와 검증

각 PRD에 대표 문제의 목표·시작 상태·할 일·수정 범위·초기 코드·정답 파일을 연결했다. 실행 기록은 [대표 문제 검증 기록](verification.md)에 남긴다.

```powershell
python docs/curriculum/rust-foundations/verify_representatives.py
```

이 검사는 대표 문제 네 개와 그 변형만 확인한다. 41개 스텝, 앱 UI, 소유권 시각화, 음성 해설, 코스 등록을 검증한 것으로 보고하지 않는다. 초안이므로 해설 캐시나 수업 JSON을 생성하지 않았다.

## 승인 때 확인한 항목

1. Java 실행 수업 직후에 Rust 네 수업을 연속 배치한다.
2. R1~R4 범위와 대표 문제를 기준으로 정식 제작한다.
3. 신규 수업은 우선 선택 수업으로 추가한다.

세 항목 모두 [승인 기록](#승인-기록)대로 승인됐다.

## 조사 근거

2026-11-02에 Rust 공식 책을 확인했다. 기본 불변 바인딩, 함수, 제어 흐름, 이동과 빌림, 구조체, Vec, Option과 Result의 의미를 각 PRD의 범위에 연결했다. 모든 API와 언어 기능을 가르치는 과정으로 확대하지 않는다. [Rust 공식 책](https://doc.rust-lang.org/book/).
