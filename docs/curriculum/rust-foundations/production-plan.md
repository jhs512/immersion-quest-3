# Rust 기초 네 수업 정식 제작 계획

기준일: 2026-11-02. 승인 사실과 근거는 [README](README.md#승인-기록)에 있다. 이 문서는 승인된 초안 PRD를 정식 제작용으로 점검한 결과다. 초안과 달라진 스텝과 그 이유를 남긴다. 목표와 교육 기법은 바꾸지 않았다.

## 점검 기준

각 스텝은 아래를 만족해야 한다. 초안의 스텝 중 이것을 어긴 곳을 고쳤다.

1. 개념 순서: 앞 스텝에서 쓴 것만 쓴다. 새 개념은 한 스텝에 하나다.
2. 응집도: 한 단원은 같은 상황을 이어 간다. 상황 설명은 단원 premise에 한 번 둔다.
3. 낮은 불필요 의존: Java 지식, 배열, 반복자, 외부 크레이트를 전제하지 않는다.
4. 도입 → 연습 → 조합: 단원 첫 스텝이 개념을 들이고, 마지막 스텝이 앞의 것을 조합한다.
5. 학습자에게 보이는 목표 텍스트가 수업·챕터·단원·스텝마다 있다.
6. 시작 코드·정답·할 일·채점·해설이 서로 맞는다. 해설의 마지막 코드가 정답의 코드 줄과 같다.
7. 단순 우회 풀이가 실패한다. 출력 상수 하드코딩은 준비 값 바꾸기(`variations`)로 거절한다. 출력만으로 구분할 수 없는 개념은 출력이 달라지도록 문제를 바꾼다.

## 초안에서 바꾼 것

| 수업 | 초안 | 정식 제작 | 이유 |
| --- | --- | --- | --- |
| R1 | 9스텝. 5번이 E0384만 관찰, 6번이 `mut` 수정 | 8스텝. 대표 문제(5번)가 관찰과 수정을 함께 한다 | 대표 문제의 할 일이 이미 "실행 → 오류 확인 → `mut` 추가"다. 관찰만 하는 스텝은 제출할 행동이 없다. |
| R1 | 2번 "정수 출력"은 `println!("{}", 5)` | 2번에서 `let` 이름과 `{stock}` 자리를 함께 들인다 | `println!("5")`와 출력이 같아 채점이 개념을 구분하지 못한다. 이름이 있어야 준비 값을 바꿔 하드코딩을 거절한다. |
| R1 | 7번 `i32` 표기만 추가 | 4번에서 `i32` 표기가 따옴표 글자를 거절하는 것을 본다 | 표기만 붙이면 출력이 같다. `"3000"`을 `i32`에 담으면 E0308이 난다. 숫자 3000으로 고쳐야 다음 덧셈이 된다. |
| R1 | 8번 `true`를 `false`로 교체 | 7번 비교 결과 `stock > 0`을 `bool`에 담는다 | 리터럴 교체는 판단이 없다. 비교 결과는 재고 값을 바꾸면 달라져 채점할 수 있다. R2의 `if`가 이 `bool`을 이어 쓴다. |
| R2 | 9번 대표 문제의 `shipping(30_000)` 직접 호출 | `let total = 30_000;`을 두고 `shipping(total)` | 채점이 `total`을 29,999·30,001로 바꿔 실행해야 한다. 비교 연산자 한 곳만 고치는 범위는 같다. |
| R2 | 앞 스텝의 조건 | 2~8번은 `total > 30_000`을 쓰고 경계에서 먼 금액(32,000·20,000)만 쓴다 | 대표 문제에서 같은 식이 30,000원에서 틀리는 것을 처음 발견한다. |
| R3 | 1번 `String::from` 내용 교체 | 1번에서 `push_str`이 `&str`에는 없고 `String`에는 있음을 본다 | 문자열 리터럴로도 출력이 같아 `String`의 의미가 드러나지 않는다. 늘릴 수 있는 소유 문자열이 이유다. |
| R3 | 3번 이동, 4번 이동 후 사용 오류 | 3번에서 이동 뒤 E0382를 보고 새 소유자로 출력한다. 5번은 함수로 넘기는 이동이다 | 이동만 하는 정상 실행은 관찰할 차이가 없다. 함수 이동이 대표 문제(6번)의 바로 앞 경험이 된다. |
| R3 | 7번 `*`로 정수를 읽음 | 같은 개념. `*stock < 3` 비교를 쓴다 | `&i32 + 1`은 `*` 없이도 컴파일된다. 비교는 `*`가 없으면 E0308이라 개념이 드러난다. |
| R3 | 8~10번 | 8번 `&mut String`, 9번 겹친 `&mut`(E0499), 10번 `&`와 `&mut`를 목적에 맞게 고르며 `*stock -= 1` | 7번의 `*`와 8번의 `&mut`를 10번에서 처음 조합한다. |
| R4 | 3번 `vec!` 원소 한 곳 | `vec!`와 `{:?}` 목록 출력은 준비 코드로 주고 원소를 더한다 | 배열 리터럴을 따로 배우지 않는다. |
| 공통 | 41스텝 | 40스텝 (8·10·10·12) | 수량은 목표가 아니다. 한 스텝 한 개념과 1~3줄 수정 기준으로 정했다. |

## 수업별 스텝

`*`는 대표 문제다. "막을 우회"는 채점이 거절해야 하는 대표 오답이다.

### R1 · 값을 담고 변경을 구분해요 (`rust-values`, 폴더 `rust_values`)

챕터 1 값과 이름 · 단원 A 출력할 값 / 단원 B 계산한 값. 챕터 2 변경과 참거짓 · 단원 C 다시 넣는 값 / 단원 D 참과 거짓. 상황: 작은 가게의 재고 수량.

| # | 새 개념 | 시작 상태 → 학생 수정 | 관찰 | 막을 우회 |
| --- | --- | --- | --- | --- |
| 1 | 문자열 리터럴·`println!` | `println!("재고 확인");` → 따옴표 안 문구 | 바뀐 문구 | 옛 문구 그대로, 따옴표 빠뜨림(컴파일 실패) |
| 2 | `let` 이름과 `{이름}` 자리 | `let stock = 5;`와 `println!("재고: 0");` → `{stock}` | `재고: 5` | `"재고: 5"` 직접 적기, `"재고: stock"` |
| 3 | 정수 빼기 | `let left = 0;` → `stock - sold` | 남은 수량 | 계산 결과 숫자 적기 |
| 4 | `i32` 표기와 숫자·글자 구분 | `let price: i32 = "3000";` → `3000` (E0308) | 덧셈 결과 | 표기만 지우기(여전히 실패) |
| 5* | 기본 불변·`mut` | 대표 문제 그대로 (E0384) | `남은 수량: 3` | `3` 직접 적기 |
| 6 | `+=` 다시 넣기 | 판매 뒤 입고를 더하는 줄 | 판매 후·입고 후 두 줄 | 입고 수량 숫자 적기 |
| 7 | `bool`과 비교 결과 | `let can_sell = true;` → `stock > 0` | `판매 가능: true` | `true` 그대로(재고 0에서 실패) |
| 8 | 조합 | 선언의 `mut`와 판매 가능 비교 두 곳 | 판매 뒤 수량과 판매 가능 | 상수 출력 |

### R2 · 조건과 반복을 함수로 나눠요 (`rust-flow-functions`, 폴더 `rust_flow_functions`)

챕터 1 흐름 선택 · 단원 A 참일 때와 아닐 때 / 단원 B 반복할 범위. 챕터 2 함수 경계 · 단원 C 인자와 반환 / 단원 D 경계 검증. 상황: 온라인 주문의 배송비.

| # | 새 개념 | 시작 상태 → 학생 수정 | 관찰 | 막을 우회 |
| --- | --- | --- | --- | --- |
| 1 | `if` | 회원 안내를 항상 출력 → `if member { }`로 감싸기 | 회원일 때만 안내 | 안내 줄 삭제 |
| 2 | 비교 연산 `>` | `if true` → `total > 30_000` | 32,000원은 무료 배송 문구 | `true` 그대로(20,000원에서 실패) |
| 3 | `else` | 반대 갈래 한 줄 추가 | 20,000원은 배송비 문구 | 두 문구 모두 출력 |
| 4 | `if` 표현식 | `let fee = 3000;` → `if total > 30_000 { 0 } else { 3000 }` | 고른 배송비 | 숫자 직접 대입 |
| 5 | `for`와 반열린 범위 | `0..3` → 상자 1~3이 나오게 범위 끝 | 반복 횟수 | `1..3`(끝 미포함) |
| 6 | 누적 | `sum += 0;` → `sum += daily;` | 단계별 합계 | 합계 숫자 적기 |
| 7 | 함수 인자 | `show_total(0)` → `show_total(total)` | 함수 안에서 받은 값 | 상수 인자 |
| 8 | 반환 타입·끝 표현식 | 항상 3000을 돌려주는 본문 → 조건식 | 호출한 쪽의 배송비 | 끝 세미콜론(E0308) |
| 9* | 경계값 | 대표 문제 (`>` → `>=`) | 29,999·30,000·30,001원 | 항상 0 |
| 10 | 조합 | 반복 안에서 함수 결과를 출력하는 한 줄 | 경계 세 금액의 배송비 | 결과 문자열 직접 출력 |

### R3 · 소유권과 빌림을 구분해요 (`rust-ownership-borrowing`, 폴더 `rust_ownership_borrowing`)

챕터 1 값 전달 · 단원 A 소유한 문자열 / 단원 B 복사와 이동. 챕터 2 빌려 쓰기 · 단원 C 읽기 빌림 / 단원 D 변경 빌림. 상황: 책 제목 `String`과 재고 정수. 판정은 컴파일러 진단과 실제 출력으로만 한다.

| # | 새 개념 | 시작 상태 → 학생 수정 | 관찰 | 막을 우회 |
| --- | --- | --- | --- | --- |
| 1 | `String::from` | `let mut title = "MQ";`에 `push_str`(E0599) → `String::from("MQ")` | 늘어난 제목 | 결과 문구 직접 출력 |
| 2 | 정수 `Copy` | 복사 뒤 두 이름을 함께 출력하는 줄 | 두 이름 모두 사용 | 숫자 직접 출력 |
| 3 | 이동과 이동 뒤 사용 제한 | 이동한 `title` 출력(E0382) → 새 소유자 출력 | 새 소유자의 제목 | 제목 상수 출력 |
| 4 | `clone` | 두 이름이 모두 필요 → `title.clone()` | 원본·복사본 각각 | 복사본 대신 상수 |
| 5 | 함수로 넘기는 이동 | `show(title)` 호출 추가 | 함수 안 출력 | 함수 밖 출력으로 대신 |
| 6* | `&String` 읽기 빌림 | 대표 문제 그대로 (E0382) | 함수 안·밖 두 번 | 호출 뒤 출력 삭제, 제목 상수 출력 |
| 7 | 역참조 `*` | `stock < 3`(E0308) → `*stock < 3` | 부족 여부 | 상수 `true` |
| 8 | `&mut` | `&String`에 `push_str`(E0596) → `&mut` 두 곳과 `let mut` | 바뀐 원래 제목 | 함수 밖에서 직접 붙이기 |
| 9 | 겹친 변경 빌림 | 두 `&mut`가 겹침(E0499) → 첫 참조 사용을 둘째 생성 전으로 | 차례로 바뀐 제목 | 한 줄 삭제(출력이 달라 실패) |
| 10 | 조합 | 읽기·변경 목적에 맞게 매개변수 두 곳과 `*stock -= 1` | 판매 뒤 재고와 제목 | `clone` 뒤 복사본만 변경(원래 값 그대로라 실패) |

### R4 · 여러 값과 없는 값·실패를 다뤄요 (`rust-data-results`, 폴더 `rust_data_results`)

챕터 1 모아 둔 값 · 단원 A 구조체 / 단원 B Vec. 챕터 2 결과의 구분 · 단원 C Option / 단원 D Result. 상황: 작은 빵집의 상품과 가격 목록.

| # | 새 개념 | 시작 상태 → 학생 수정 | 관찰 | 막을 우회 |
| --- | --- | --- | --- | --- |
| 1 | `struct`와 필드 읽기 | 준비된 `Product` 값의 두 필드를 출력하는 줄 | 이름·가격 | 문구 직접 출력 |
| 2 | 필드 변경 | 필드 대입이 E0594 → `let mut` | 바뀐 가격, 그대로인 이름 | 새 값 직접 출력 |
| 3 | `Vec`·`vec!` | 원소 하나 추가 | `{:?}` 목록·`len()` | 목록 문자열 직접 출력 |
| 4 | `push` | `push` 한 줄(목록에 `mut`) | 원소와 길이 변화 | 처음부터 세 원소로 선언 |
| 5 | `for x in &v` | 합계 누적 뒤 목록 길이 출력 | 합계·원래 목록 유지 | `for x in v`(이동, E0382) |
| 6 | `Option`과 `get` | `{:?}`로 `get(index)` 출력 | `Some(1800)`·`None` | `prices[index]`(범위 밖 패닉) |
| 7 | `match` | `Some`·`None` 두 갈래 | 갈래별 문구 | 한 문구만 출력 |
| 8* | 0과 없음 구분 | 대표 문제 그대로 | `가격: 1200`·`가격: 1800`·`상품 없음`·`가격: 0` | 모든 입력에 `상품 없음` |
| 9 | `Result` | 준비된 `check_qty`의 결과를 `match` | `Ok`·`Err` 갈래 | 한 갈래만 처리 |
| 10 | `parse::<i32>` | 문구를 정수로 바꾸는 호출 | 숫자·잘못된 문구 | 숫자 직접 대입 |
| 11 | 실패를 0으로 숨기지 않기 | `Err` 갈래가 `수량: 0` → 실패 문구 | `"0"`과 `"abc"`의 차이 | 모든 입력에 실패 문구 |
| 12 | 조합 | 조회 없음·변환 실패 두 예제의 한 갈래씩 | `None`과 `Err`를 따로 표시 | 두 실패를 같은 문구로 |
