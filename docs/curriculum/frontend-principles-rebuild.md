# React·Tailwind 원리 수업 개편 (2026-10-26)

사용자는 기존 두 수업이 짧은 사용법 안내에 머물렀다고 지적했다. 순수 JavaScript·CSS로 먼저 문제를 경험하고, React·Tailwind가 바꾸는 책임과 표현 방식을 비교하는 긴 코딩 수업으로 교체했다. 문제 수를 늘리는 것 자체를 목표로 삼지 않았다.

## React: 6문제에서 22문제로

수업 ID는 유지하고 revision을 `java-react-4`로 올렸다. 본질이 달라진 문제에는 새 ID를 부여했다. 이전 완료 기록을 새 문제의 완료로 옮기지 않는다.

1. 순수 JavaScript에서 변수 변경과 DOM 변경을 따로 수행한다. 여러 표시의 갱신 누락을 겪고 render 함수로 모은다.
2. 자료에서 화면을 계산하는 함수를 JSX·컴포넌트·props·목록으로 옮긴다. 문자열 렌더러를 React 내부 구현이라고 설명하지 않는다.
3. 상태 설정, 렌더 스냅샷, 누적 갱신 함수, 배열·객체의 새 참조를 실제 클릭으로 비교한다.
4. 독립된 상태와 공유할 상태, 원본과 파생 값, 제어 입력을 구별한다.
5. 목록을 뒤집어 key에 따라 입력 상태가 누구를 따라가는지 확인한다. key를 바꿔 편집 상태를 초기화한다.
6. 폼 이벤트, 외부 DOM과의 동기화, 이벤트 구독 정리를 다룬다. 화면에서 계산할 값을 Effect로 복제하지 않는다.
7. 추가·검색·개수가 일치하는 작은 명언 목록으로 조합한다.

## Tailwind: 6문제에서 24문제로

수업 ID와 기존 여섯 문제의 본질·ID를 유지하고 `java-tailwind-4`로 올렸다. 앞뒤에 원리 실험을 연결했다.

1. 순수 CSS로 선택자·상속·선언 순서·명시도를 비교한다.
2. 박스 모델·flex·gap·미디어 조건을 직접 바꾸고 계산된 스타일을 읽는다.
3. 짧은 CSS 유틸리티를 직접 만든 뒤 Tailwind의 CSS와 비교한다.
4. 간격 토큰·상태 조건·작은 화면 우선 반응형·grid를 단계적으로 적용한다.
5. HTML 클래스 순서와 CSS 우선순위가 다름을 실험한다. 반복 요소의 정의를 한곳에서 공유한다.
6. 완전한 클래스 이름을 매핑하는 이유와 브라우저 런타임·운영 정적 빌드의 차이를 구분한다.
7. 상태·폭·여백을 함께 검증하는 카드 문제로 마친다.

## 확인한 것

- 두 수업 모두 객관식 없이 코드 수정·실행·제출로 진행한다.
- 앱과 같은 브라우저 runner에서 준비 코드는 실패하고 정답은 통과한다. 클릭·입력·순서 변경·뷰포트·계산된 CSS를 검사한다.
- Rust 공개 채점 경로 `validate_redesigned_lesson`에서 React 22문제와 Tailwind 24문제, 해설 실행 92회와 Tailwind 추가 오답 18건을 검증했다.
- 94개 수업의 정적 빌드 검사, 과정 묶음 검사, 추천 순서 검사, 게시 메타데이터 보존 검사를 통과했다.
- 수업은 앱 설치 파일과 별도로 immutable revision으로 게시한다. 과정의 다른 수업·분류·진도는 유지한다.
