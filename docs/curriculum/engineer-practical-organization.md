# 정보처리기사 실기: 분류와 추천 순서

2026-11-03 기준 공개 과정 62개를 대상으로 한다. 수업을 찾는 **주제 분류**와 처음부터 배우는 **추천 순서**를 구분한다. 선수 수업은 안내이며 입장 조건이 아니다. 기존 수업·문제 ID, 고정 버전, 정답, 필수 여부와 학습 기록은 바꾸지 않는다.

언어별 2~6개짜리 세부 분류까지 늘리는 안도 비교했다. 현재 규모에서는 주제 11개와 추천 순서의 학습 묶음을 조합하면 탐색과 입문 흐름을 모두 설명할 수 있다. 기존의 Java/Python 합친 분류와 보안·OS·네트워크·배포를 합친 분류를 나누고, 미분류 32개를 모두 배정한다. `basic`은 난이도 등급으로 다시 해석하지 않는다.

| 15 | 종합 | 1 | 여러 주제를 섞어 실행과 결과를 판단한다. |

C 14개를 모두 끝내고 Java·SQL로 넘어가는 안은 포인터·동적 메모리가 초반 진입을 가로막는다. Python·DB로 개발 생명주기를 모두 끝내고 C·Java를 마지막에 두는 안은 두 언어에 너무 늦게 도달한다. 채택안은 언어마다 기초 묶음을 유지하면서 C 심화 전에 Java와 SQL을 경험하게 한다. 그 비용은 언어로 돌아오는 시점의 복습 부담이다. 개별 개념마다 언어를 바꾸지 않고 묶음 경계에서 전환한다.

SQL은 GROUP BY/HAVING과 집계를 익힌 뒤 AVG/MAX와 상관 질의를 사용하는 서브쿼리로 간다. Java의 기본 생성자·초기화는 static 수업에서 먼저 배우고, 오버라이드를 익힌 뒤 생성자 실행 중 재정의 호출까지 쓰는 심화 수업으로 간다. C 연결 구조 앞에는 구조체 포인터와 호출 추적을 둔다. 클로저·생성기·트리 재귀를 묶은 Python 심화 수업은 뒤로 둔다. 입문 호출 수업에도 가변 기본 인자와 상속 문제 일부가 있으므로 초반 난이도는 별도 개선 여지가 있다.

## 공식 범위와의 관계

큐넷의 [종목 안내](https://www.q-net.or.kr/crf005.do?id=crf00503s02&jmCd=1320&jmInfoDivCcd=B0), [2026년 출제기준](https://www.q-net.or.kr/pageLink.do?link=cst/cstReport&jmCd=1320&mcrtrNo=991), [2027–2029년 출제기준](https://www.q-net.or.kr/pageLink.do?link=cst/cstReport&jmCd=1320&mcrtrNo=1453)의 실기 원문을 대조했다. 아래 12개 주요 영역은 두 판에서 유지된다. 공식 나열 순서는 입문 학습 순서나 배점표가 아니다. C·Java·Python의 비중이나 출제 빈도를 이 문서에서 추정하지 않는다.

| 공식 실기 영역 | 과정에서 찾아갈 주제 |
|---|---|
| 요구사항 확인 | 소프트웨어: 요구·분석 |
| 데이터 입출력 구현 | DB: 논리·물리 설계·데이터 조작 |
| 통합 구현 | 소프트웨어: 서버·연계·인터페이스 |

| 인터페이스 구현 | 소프트웨어: 인터페이스 구현·검증 |
| 화면 설계 | 소프트웨어: UI |

| 제품 소프트웨어 패키징 | 배포·운영 |

이는 대응표이며 세부 출제항목을 모두 충분히 실습했다는 뜻은 아니다. 현재 SQL은 SQLite 실행이 중심이다. 사용자·그룹 권한, 일부 저장·파티션·프로토콜·클라우드·복구 항목은 Python 모형으로 다룬다. JDBC 연결, 실제 DBMS의 사용자 관리·프로시저/UDF 작성·실행계획 튜닝, 실제 패킷·TLS 운영을 했다고 표시하지 않는다. OS 권한 실습도 Linux 터미널 전체 실습과 구분한다. Git 일부는 임시 저장소에서 실제 명령을 실행한다.

기존 종합 1개는 새 심화 32개 전체를 평가하는 최종 모의고사가 아니다. 공식 세부 범위의 보강 수업과 종합 평가 확장은 별도 콘텐츠 제작 과제로 남긴다. 이번 작업은 기존 62개를 빠짐없이 찾고 합리적인 순서로 학습하게 하는 구성 변경이다.

## 적용과 검증

실행 가능한 계획은 `tools/redesigned_courses/engineer-organization.json`, 게시 도구는 `tools/organize-engineer-course.py`다. 검토한 공개 course.json의 blob SHA가 달라지면 게시를 중단한다. 62개 정확한 일치, 단일 분류, 명시적 선수 목록, 앞 방향의 선수 관계를 검사한다. 실제 앱의 SnapshotStore 파서로 고정 수업 문서와 해시·메타데이터를 검증한다. 게시 후 다시 읽어 결과가 같은지 확인한다.

공개 62개가 권위 있는 원격 과정이다. 기존 앱 번들의 30개 구성은 이번 범위에서 확장하지 않는다. 기존 승인표나 별도 정처기 프로젝트의 수업 원문을 가져와 번들 수업을 중복 발행하지 않는다.
