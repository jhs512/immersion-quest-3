# SQL 조회 결과를 표로 표시

2026-10-27 요청: MQ DB 수업에서도 실제 조회 결과의 열 이름과 행을 볼 수 있어야 한다.

SQL 기초, MySQL 제약, JOIN·집계, 인덱스, 트랜잭션 5개 수업의 39문제를 대상으로 한다. MySQL은 `--table`, PostgreSQL은 aligned 형식·테두리·명시적 NULL 표시를 사용한다. 애플리케이션에서 가짜 테이블을 만들지 않고 실제 DB 클라이언트가 출력한 표를 보여 준다. PostgreSQL의 빈 조회는 열 이름과 0행을 보여 주며, MySQL의 빈 조회는 해당 CLI의 출력 방식을 따른다.

실행·해설은 `MQ3_OUTPUT=raw`, 제출 검사는 `grading`으로 나눈다. 기존 채점 값과 오류 처리를 유지한다. 표 표시를 위해 변경 SQL을 다시 실행하지 않는다. 별도 연결에서 저장 여부를 읽는 실습도 실제 두 클라이언트를 유지한다.

정답·준비 코드·문제 ID·해설 문장·변형 채점 조건은 바꾸지 않는다. Java/JDBC에서 학습자가 작성한 `println` 로그를 SQL 결과로 추측해 변환하지 않는다.

검증:

SQL 검증은 `MQ3_VALIDATE_SQL_SESSION=1`로 실제 앱의 `LessonSession`을 사용한다. 컨테이너는 재사용하되 각 채점과 해설 실행의 DB 데이터는 초기화한다. 준비 코드 거부·정답·변형 입력·해설 출력 검사는 생략하지 않는다. 검사가 성공하거나 실패한 뒤에는 검증용 세션을 닫는다.

- `tools/test_sql_visible_tables.py`: 두 실제 엔진의 열 이름·NULL·한글·오류 뒤 조회·빈 결과·한 번만 쓰기·새 연결 조회.
- `tools/record_sql_table_outputs.py`: 표시한 모든 행을 기존 승인 출력과 대조한 뒤 실제 표를 해설 재생의 기대값으로 저장.
- `tools/validate-sql-tables.py`: 기존 실제 실행기에서 39문제의 준비 코드 실패·정답 성공·오답 거절·해설 재생을 검사.
- `tools/publish-sql-tables.py`: 현재 파일 해시와 검증 근거를 확인하고 수업 개정만 게시. 원격의 다른 수업과 분류·학습 기록은 보존.

빌드 143의 실행/채점 출력 분리를 이용한다. 이 수정은 앱 재빌드가 필요 없다.

검증 결과: 5개 수업 39문제의 준비 코드·정답·해설 재생을 통과했다. 추가 오답 42개를 거절했고 다른 정답 풀이 3개를 허용했다. 실제 MySQL·PostgreSQL의 NULL·한글·빈 결과·오류 후 조회·변경 SQL 한 번 실행·별도 연결 조회 검사도 통과했다. 네이티브 앱 화면과 음성 청취 검증을 수행했다는 뜻은 아니다.
