# 단축키와 제출 실패 표시

요청: Mac/Windows 실행·제출·스텝 이동 단축키를 체계화하고 오답을 붉은 표시로 즉시 구분한다.

기존 navy·mint 학습 화면을 유지하는 Operate 모드의 기능 보완이다. Impeccable harden/craft-floor 기준을 적용했다. 시각 스타일을 교체하지 않았다.

- 단축키 정의·표시·안내를 `assets/layout/shortcuts.js`에서 관리한다. 실행·제출은 서로 다른 조합키다. 실행 두 번으로 제출하는 기존 기능과 대기 제출을 제거했다.
- 새 과정의 이전·다음 버튼에 실제 이동을 연결하고 버튼에 플랫폼별 키를 표시한다. 입력 중 편집키·터미널 Enter·한글 조합은 유지한다.
- 학습 화면과 과정 목록에 단축키 버튼을 제공한다. 안내는 native dialog의 초점 범위를 따르고 닫은 뒤 초점을 복원한다.
- TaskWorkspace의 feedback을 해설 스냅샷에 포함한다. 오답·실행 오류·검사 불가·통과를 구분한다. 오답은 제출 근처 배지와 결과 영역의 붉은 배경·테두리·아이콘·문장으로 표시한다. 기본 초록색 실행 상태 글씨는 현재 판정을 따른다.
- 판정을 받은 즉시 보여주며 진도 저장 결과가 학습 판정을 덮지 않는다. 과거 성공 때문에 새 오답 제출에서 완료를 알리던 분기도 막았다.

검증:

- WebKit/Chromium × Mac/Windows 키 모사: 실행·제출 분리, 중복/예약 제출 방지, 편집·터미널·IME·모달·이동 범위 및 플랫폼 표시. 기존 Enter와 F11 검사 포함 6개 통과.
- 실제 macOS 네이티브 플레이어: 단축키로 오답 제출 → 붉은 경고/배지 → 해설 중단 뒤 판정 복원 → 앞뒤 스텝 이동 → 단축키 안내. 4개 시나리오 통과. 최초 검사는 숨겨진 같은 이름의 멈춤 버튼을 선택해 실패했고, 실제 보이는 버튼/현재 문제의 중단 버튼으로 범위를 좁혀 통과했다.
- 실제 프로덕션 CSS를 쓰는 1280px/720px 렌더를 WebKit/Chromium에서 확인했다. 붉은 글씨 대비 4.5:1 이상, 문장 줄바꿈, 제출 버튼과 좁은 안내의 접근을 검사했다. `target/shortcut-feedback/`에 캡처가 있다. 이 캡처는 CSS 검증용 렌더이며 네이티브 화면 캡처로 주장하지 않는다.
- Windows 실기기 입력·스크린 리더 실제 낭독은 미확인이다. 자동 Windows 키 모사와 실제 macOS 동작을 구분한다.
- Impeccable detector 결과 없음.

정책: `docs/keyboard-shortcuts.md`. 앱 표시 이름은 MQ이며 식별자와 진도 저장 위치는 유지한다.

설치: 최신 실행 파일을 `/Applications/MQ.app`에 적용하고 서명을 검증했다. Vim 버그 수정과 함께 실제 앱을 재실행해 단축키 버튼·제출 키 표시·이전/다음 키 표시가 보이는 것을 확인했다.
