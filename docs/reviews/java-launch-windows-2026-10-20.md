# java-launch Windows 제작 및 검증

2026-10-20 사용자의 명시적 재개 지시로 승인된 PRD와 8스텝의 ID를 유지해 정식 콘텐츠를 제작했다. 자바 백엔드 과정의 java-crud 뒤, java-testing 앞에 등록했다. 다음 후보 수업은 이번 구현 범위가 아니다.

## 구현

- 같은 Main.java와 Main.class를 스텝 전환·재접속에도 유지한다. 첫 단계의 초기화는 새 소유 폴더를 만들고 이전 폴더를 복구용으로 보존한다.
- 실제 JDK 25의 java/javac를 같은 설치 경로에서 찾는다. 소스·클래스 실행과 컴파일은 별도 명령이며 학생 파일을 몰래 다시 컴파일하지 않는다.
- 클래스 파일은 UTF-8 텍스트 검사에서 분리했다. 실제 실행 결과와 변경 전후 SHA-256, 해당 스텝의 실제 명령·소스 해시·종료 상태·선택 답을 함께 검사한다. 클래스 검증은 별도 복사본에서 실행한다.
- 편집 내용은 원자적으로 저장한다. 터미널에 Enter를 전달할 때 화면의 편집 값을 같이 보내 저장 완료 후 명령을 실행한다. 예측 단계는 보기 선택 전 Enter 실행을 막되 입력한 명령은 유지한다.
- 실행 시간 20초·출력 64KB·JVM 메모리 128MB 제한을 두고 Windows Job Object / Unix 프로세스 그룹으로 자식 프로세스를 정리한다.
- 해설은 별도 소유 폴더·편집기·클래스를 준비한다. 해설 종료의 JS 복원이 교사용 코드를 학생 편집기에 덮어쓰지 않도록 분리했다.

## Windows에서 함께 발견한 문제

Git Bash를 --noprofile/--norc로 시작하면 GUI 앱의 PATH에 cat 등 coreutils가 없었다. 설치된 Git Bash 디렉터리를 해당 자식 세션의 PATH에 추가했다. Vim 준비 검사도 같은 설치 경로를 사용한다.

Git Bash는 Windows 임시 폴더를 /tmp로 표시할 수 있다. /c만 바꾸던 경로 변환으로는 cd 이후 채점·복원이 틀렸다. Windows Bash의 builtin pwd -W로 실제 경로를 기록한다. 테스트 PTY는 ConPTY의 커서 위치 요청에 응답한다.

xterm의 text()는 줄 끝 공백을 제거한다. 준비 상태는 "$ " 부분 문자열 대신 공백을 제외한 프롬프트의 끝으로 확인한다.

## 검증

- 실제 Windows Bash/JDK 통합 검사: 8스텝의 학생·격리 해설, 재접속, 클래스 유지·변경, 초기화, 컴파일 오류와 출력 제한 통과.
- Windows 배포용 실행 파일에서 같은 JDK 통합 검사 통과.
- 승인 전 프로토타입 검증도 Windows에서 8스텝 × 두 문구 시나리오 통과. 이 검사는 정식 앱 검증과 별개다.
- 기존 Bash 23스텝, Vim 14스텝, Git 실행·프로세스 종료·실습 복구 검사 및 75수업/734스텝 레지스트리 검사 통과.
- 한글 입력·Enter 이동·해설 순서·패널 크기 브라우저 회귀 검사 23개 통과.
- PRD·등록·해설 캐시·수업 및 과정 번들 검사 통과. 정식 수업은 courses/redesigned/java-launch.json이다.
- 실제 Windows WebView 앱 8스텝 → 100% 완료 통과. 선택 답만 제출·오답은 실패했고, 실행 전 예측 선택, 실제 JDK 출력, 해설 중단 및 전체 시연 후 학생 편집기/터미널 복귀를 확인했다. 근거: target/pilot-java-launch-native-result.json (개발용 격리 계정만 사용).
- Mac에는 같은 JDK/네이티브 WebView 검사를 릴리스 CI에 추가했다. 첫 실행(39350739118)에서 실제 JDK 검사는 통과했으나 네이티브 검증 스크립트가 수업 진입 직후 아직 없는 molipAgent를 호출해 실패했다. 수업 편집기·PTY와 해설 모듈의 준비를 확인한 뒤 진행하도록 검증 스크립트를 보완했다. Mac 재검증 및 설치 파일 게시 완료 여부는 후속 CI 결과로 확인한다.

## 게시 범위

로컬 과정 번들과 실행기를 구현했다. 원격 과정 저장소의 기존 콘텐츠·고정 태그를 덮어쓰지 않았다. 이후 원격 과정 공개는 대상 버전·기존 참조와의 일치를 따로 확인해야 한다.
