# 이해 중심 백엔드 확장 계획 검토

사용자의 기술 목록은 주제별로 조합한 11단계·44개 후보 소수업으로 정리했다. 후보 수는 제작 확정·필수 이수 수가 아니다. 현재 20수업 187스텝과 기존 식별자·진도는 유지한다.

최우선 정책은 docs/content-rules.md에 기록했다. 첫 초안의 모든 스텝은 새 개념 하나·학생 수정 0~1줄·새 외부 서비스 0개다. PRD 검증기에 난도 근거 누락, 한 스텝의 여러 개념, 과도한 수정 줄 수, 한 단원의 여러 새 서비스 도입을 거부하는 검사를 추가했다. 기존 PRD와 신규 난도 검사 11개가 통과했다.

전체 추천 의존 관계는 순환이 없고 후보 키 중복이 없다. 첫 수업은 java-crud 뒤·java-testing 앞의 검토용 위치이며 과정에 등록하지 않았다. catalog에는 별도 draft 확장안의 경로만 연결했다. 기존 콘텐츠·코스 번들 검사가 그대로 통과한다.

첫 수업 PRD와 대표 문제는 draft다. 공식 실행·컴파일 문서를 확인하고, 로컬 JDK로 8스텝을 두 가지 문구 시나리오에서 실행했다. 소스 모드의 산출물 부재, 컴파일의 class 생성, 소스만 변경한 뒤 이전 class 출력, 재컴파일 뒤 변경 출력을 확인했다. 다른 문구에서도 같은 관계가 유지된다. 실제 Windows 실행은 미검증이다.

현재 앱의 텍스트 전용 셸 파일 검사에 class 파일을 그대로 넣을 수 없음을 확인했다. 코드 편집·실제 JDK 명령·바이너리 산출물의 연동은 첫 정식 구현의 별도 작업이다. 환경변수와 백그라운드 수업에는 파일 연속성 외에 셸 프로세스 연속성도 필요하다.

PRD·대표 문제 검토를 사용자에게 요청했다. 아직 승인으로 기록하거나 정식 수업을 게시하지 않았다. Docker·DB·모델 다운로드 등 외부 서비스는 시작하지 않았다.

## 승인 및 중단 기록

사용자가 PRD·대표 문제에 “이 구성으로 첫 수업부터 제작”이라고 승인하여 approved-prd.json 및 md에 기록했다. 이후 사용자가 계획만 세우고 진행을 중지하라고 요청했다. 정식 제작·등록·앱 반영은 시작하지 않은 상태다. Windows 이관 및 재개 기준은 docs/curriculum/windows-handoff.md를 따른다.
