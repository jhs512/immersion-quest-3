# 실행 인자 수업과 개념 우선 원칙 적용

2026-10-20 사용자는 개별 지식의 기초·원리를 예제로 이해하는 원칙을 메모 앱의 발전보다 상위에 두고 계속 진행하도록 지시했다. 질문 없이 진행하라는 기존 위임 안에서 실행 인자·환경 변수 후보를 더 작은 독립 수업으로 나눴다. 새 PRD 문서를 사용자가 직접 열람했다고 기록하지 않는다.

## 교육 범위

`docs/content-rules.md`에 최상위 원칙을 기록했다. 사람용 확장 계획·기계용 후보 목록·Windows 인계에도 같은 우선순위를 반영했다. 메모 앱은 원리 이해 뒤의 선택적 적용이다. 기존 java-launch는 이미 파일 하나·출력 한 줄로 개념을 관찰하므로 내용을 바꾸거나 과거 승인 해시를 다시 찍지 않았다.

새 java-arguments는 이전 앱을 몰라도 시작할 수 있다. Main.java 하나, 출력문 한 줄, 외부 서비스 0개다. 배열과 소스 실행만 선수 지식으로 쓴다. 인자 없음 → 하나 → 둘 → 첫 위치 → 순서 변경 → 둘째 위치 → 공백 포함 값 → 숫자 모양 문자열의 8스텝이다. 수정은 한 줄 이하이며 선택지와 실제 실행 결과를 함께 확인한다. 환경 변수·시스템 속성·Gradle은 넣지 않았다.

## 구현

- 고정된 Main/Main.java 뒤의 프로그램 인자를 실제 JDK에 그대로 전달한다. 파일 이름 앞의 임의 JVM 옵션이나 다른 시작 파일을 허용하는 기능으로 넓히지 않았다. 인자 수·길이 제한과 기존 실행 시간·출력·프로세스 종료 제한을 유지했다.
- 실습 명세와 실행기의 명령 검증을 같은 함수로 맞췄다. 실제 argv·소스 해시·표준 출력·클래스 상태를 채점한다. 컴파일된 Main에 인자가 있는 경우 검증용 복사본도 같은 인자로 실행한다.
- 해설은 별도 폴더에서 직전 소스부터 시작한다. 코드 한 줄 변경 → 명령 하나 → 출력 설명 순서를 따른다. 예측 단계는 선택 후 실행하도록 유지한다.
- java-launch 뒤에 별도 식별자로 등록했다. 현재 로컬 자바 과정은 22수업 203스텝, 전체는 76수업 742스텝이다. 기존 ID·진도는 유지했다.

## 검증

- 실제 Bash/JDK 프로토타입: 8스텝 × 두 문구 시나리오 통과. `python tools/verify-java-arguments-prototype.py`로 재현한다.
- `cargo test --locked --test java_arguments`: 학생·해설 8스텝, 미실행 거부, 재접속·초기화, 인자 누락 오류·빈 문자열·한글·공백·옵션 모양 문자열, 컴파일된 클래스와 검증 복사본의 동일 인자 전달 통과.
- 실제 Windows WebView: 8스텝 → 100%, 선택지만 제출 및 잘못된 관찰 거부, 실행 전 예측, 해설 중단·전체 재생 뒤 파일과 터미널 보존 등 12개 검사 통과. 근거는 `target/pilot-java-arguments-native-result.json`이다.
- 기존 java-launch 실제 Windows 화면 12개 검사와 실행·컴파일·시간/출력 제한 검사를 다시 통과했다.
- PRD 11개·등록 검사 3개, 모든 76수업 파생물과 과정 번들 검사 통과. 새 수업은 `courses/redesigned/java-arguments.json`이다.
- 새 수업의 동일한 JDK·실제 WebView 검사를 Mac 릴리스 CI에 추가했다. Mac에서 통과했다고 미리 기록하지 않는다. 결과는 해당 커밋의 CI 및 `pilot-java-arguments-native-result.json`에서 확인한다.

## 게시와 다음 범위

로컬 번들·실행기 변경이다. 기존 원격 과정의 고정 태그나 진도 이슈를 덮어쓰지 않는다. 설치 파일 게시 여부는 릴리스 CI로 구분한다. 다음 수업은 셸 변수와 환경변수이며, 각 스텝의 셸 수명과 자식 프로세스 상속을 먼저 설계·검증한다. 변수 상태가 파일처럼 단계 이동·앱 재실행에도 보존된다고 가르치지 않는다.
