# Bash 8번 채점과 앱 업데이트 버튼

Bash 8번은 실제 `cd notes/` 실행에 성공해 현재 폴더·파일·폴더 목록이 모두 맞아도 명령 기록을 `cd notes` 문자열과 비교해 실패했다. `clear` 자체는 원인이 아니었다.

명령 기록은 성공한 필수 명령을 순서대로 찾는다. 앞선 실패나 사이의 추가 명령은 오답 사유가 아니다. `cd`의 단순 경로 표기에서 끝의 슬래시, 앞의 `./`, 따옴표와 명령 뒤 공백 차이를 허용한다. 셸 연산·변수·명령 치환은 정규화하지 않는다. 최종 현재 폴더와 파일·폴더 검사는 계속 수행한다. 과거에 맞게 실행했더라도 현재 상태가 틀리면 통과하지 않는다.

상단 ↻는 앱 업데이트 확인 기능이었다. 결과가 버튼의 툴팁에만 드러나 누른 뒤 반응을 알기 어려웠다. 중복 아이콘을 제거하고 앱 설정에 확인 중/최신/실패 상태와 설치 버튼을 모았다. 확인 중에는 즉시 상태를 표시하고 중복 확인·설치를 막는다. 나중에를 선택한 새 버전도 앱 설정에서 설치할 수 있다.

검증:
- 실제 Bash PTY로 사용자 명령열 `cd notes/`, `pwd`, `ls`, `clear`, `pwd`, `ls`가 수정 전 실패함을 확인했다.
- 수정 후 기본 표기, 끝 슬래시, `./`, 따옴표 네 가지가 통과했다. 앞선 실패 후 재시도는 통과하고, 최종 폴더가 틀리면 실패하며 다시 고치면 통과했다.
- 기존 Bash/Vim 전체 23단계를 포함한 bash_basics 3개 테스트가 통과했다. Windows 및 두 Mac의 릴리스 검증에도 추가했다.
- Chromium/WebKit 상단 메뉴 배치 검사 3개 통과. 로컬 WebKit은 설치된 webkit-2336 실행 파일을 명시했다.
- cargo check와 updater 단위 검사 5개 통과. 외부 다운로드 검사 3개는 기존 ignored 상태다.

각 단계 초기 상태 복원 방식에 대한 앞선 설명은 설계 제안이며 이 수정에 포함하지 않았다.
