# Bash 8번 채점과 앱 업데이트 버튼

Bash 8번은 실제 `cd notes/` 실행에 성공해 현재 폴더·파일·폴더 목록이 모두 맞아도 명령 기록을 `cd notes` 문자열과 비교해 실패했다. `clear` 자체는 원인이 아니었다.

명령 기록은 성공한 필수 명령을 순서대로 찾는다. 앞선 실패나 사이의 추가 명령은 오답 사유가 아니다. `cd`의 단순 경로 표기에서 끝의 슬래시, 앞의 `./`, 따옴표와 명령 뒤 공백 차이를 허용한다. 셸 연산·변수·명령 치환은 정규화하지 않는다. 최종 현재 폴더와 파일·폴더 검사는 계속 수행한다. 과거에 맞게 실행했더라도 현재 상태가 틀리면 통과하지 않는다.

상단 ↻는 앱 업데이트 확인 기능이었다. 결과가 버튼의 툴팁에만 드러나 누른 뒤 반응을 알기 어려웠다. 중복 아이콘을 제거하고 앱 설정에 확인 중/최신/실패 상태와 설치 버튼을 모았다. 확인 중에는 즉시 상태를 표시하고 중복 확인·설치를 막는다. 나중에를 선택한 새 버전도 앱 설정에서 설치할 수 있다.

검증:
- 실제 Bash PTY로 사용자 명령열 `cd notes/`, `pwd`, `ls`, `clear`, `pwd`, `ls`가 수정 전 실패함을 확인했다.
- 수정 후 기본 표기, 끝 슬래시, `./`, 따옴표 네 가지가 통과했다. 앞선 실패 후 재시도는 통과하고, 최종 폴더가 틀리면 실패하며 다시 고치면 통과했다.
- 기존 Bash/Vim 전체 23단계를 포함한 bash_basics 3개 테스트가 통과했다. Windows 및 두 Mac의 릴리스 검증에도 추가했다.
- Chromium/WebKit 상단 메뉴 배치 검사 3개 통과. 로컬 WebKit은 설치된 webkit-2336 실행 파일을 명시했다.
- cargo check와 updater 단위 검사 5개 통과. 외부 다운로드 검사 3개는 기존 ignored 상태다.

각 단계 초기 상태 복원 방식에 대한 앞선 설명은 설계 제안이며 이 수정에 포함하지 않았다.

## 한글 입력 시작 시 앞 따옴표 소실

터미널의 임시 textarea에는 이미 PTY에 전달한 ASCII 키가 남을 수 있다. macOS 방식의 비표준 한글 입력이 그 값을 교체하면 기존 보정 로직은 전체 차이를 삭제 신호로 보냈다. 이 때문에 첫 한글을 입력할 때 앞의 따옴표까지 지울 수 있었다.

보정 코드가 전송한 한글 길이를 별도로 추적한다. insertText로 시작할 때 기존 입력을 지우지 않고, insertReplacementText의 삭제 범위도 직접 전달한 한글로 제한한다. 일반 입력이나 표준 조합 입력으로 전환하면 추적값을 초기화한다. 실제 사용자 입력 문자열은 정규화된 한글 외에 변경하지 않는다.

한글 첫 입력이 임시값을 교체하는 이벤트열을 구성해 실제 번들/입력 브리지에서 수정 전 `echo 첫 ..."`가 되는 것을 두 브라우저 모두에서 재현했다. 수정 후 `echo "첫 메모"` 전체 입력이 일치했다. 표준 조합, macOS 방식 교체, NFC/NFD, 중복 확정, 한글 삭제, 세션 교체를 포함한 15개 브라우저 검사가 통과했다. 이 검사는 합성 입력 이벤트로 브리지 출력을 검증하며 실제 macOS 키보드 이벤트를 직접 발생시키는 검사는 아니다.

## Vim 2번 입력 범위와 문자열 선택

안내와 풀이에서 입력할 내용을 `"첫 메모"`로 명시하고, 따옴표 자체는 입력하지 않는다고 설명했다. 입력값과 채점 조건은 그대로 유지했다. 해설에 같은 안내를 반영하고 narration 캐시, 수업, 검증 코스 해시, 내장 과정 번들을 다시 생성했다. 목표·핵심 흐름은 바꾸지 않았다.

문제 본문의 인라인 코드/문자열은 내부 공백을 포함해 한 단위로 선택하도록 user-select:all 및 WebKit 접두사를 적용했다. 에디터·터미널·코드 블록 선택은 이 규칙의 대상이 아니다. Vim 안내의 첫 항목 문자열을 직접 더블클릭해 전체 `첫 메모`만 선택되고 따옴표·다음 항목이 포함되지 않는지 Chromium/WebKit, 1x/2x, 1470/735px에서 검사했다. 둘째 항목 일반 텍스트 선택도 해당 항목 안에 남는다.

원래 일반 텍스트의 첫 항목을 더블클릭했는데 둘째 항목이 선택된다는 현상은 로컬 두 브라우저에서 재현하지 못했다. 따라서 그 현상의 원인을 특정했거나 macOS 네이티브 앱에서 해결을 확인했다고 주장하지 않는다. 전체 문자열 선택은 변경 후 브라우저 검사에서 확인했다.
