# Vim 입력 모드인데 제출이 잠긴 문제

사용자의 실제 앱에서 입력 모드·목표 완료는 감지되었으나 제출이 비활성화되고 「터미널을 준비하지 못했어요」가 표시됨을 확인했다.

원인: Vim 준비 완료를 xterm 화면의 `memo.txt` 문자열 존재로 판단했다. 시작 직후 크기 조정이나 화면 재그리기로 파일명 알림이 사라지면 실제 Vim 상태와 무관하게 준비 실패로 처리했다.

수정:

- Vim은 소유 세션의 실제 상태 보고가 도착하면 준비 완료로 처리한다. Bash/Git은 기존 프롬프트 감지를 유지한다.
- 최초 상태가 터미널 mount보다 먼저 도착할 수 있어 `mounted` 통지에서 캐시된 상태를 한 번 다시 보낸다. 변하지 않은 상태를 계속 웹뷰에 전송하지 않는다.
- 화면 글자를 정답이나 준비 여부의 근거로 삼지 않는다. `i` 완료는 실제 Vim 입력 모드로 판정한다.

검증:

- 실제 macOS 네이티브 플레이어에서 화면 텍스트 조회가 빈 문자열만 반환하도록 만들어 파일명 알림 부재를 재현했다. 준비 완료·제출 활성화 → 실제 i 입력·실시간 완료 → 제출 단축키·정상 통과 3개 시나리오를 통과했다.
- 실제 PTY의 14스텝, 저장하지 않은 버퍼·입력 모드·커서 복원, 열기/종료만으로 커서 과제가 통과하지 않는 3개 검사를 통과했다.
- 설치 전 사용자의 현재 Vim 버퍼를 백업하고 앱 교체 뒤 내용 보존을 비교했다. 초기화하지 않았다. `/Applications/MQ.app` 서명을 검증했다.

최종 실제 앱 확인: MQ를 재실행하고 사용자 Vim 첫 스텝을 다시 열었다. 입력 모드와 목표 확인 표시가 유지되고 제출 버튼이 활성화되어 있음을 접근성 상태와 실제 화면으로 확인했다. 터미널 준비 실패 문구는 사라졌다. 사용자 진도에 대신 제출하지 않았다.
