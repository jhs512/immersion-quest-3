# Git 수업 문구 검토 — 2026-10-20

사용자 기준: 명확하고 쉽고 직관적으로 쓴다.

## 적용 기준

- 파일 이름과 브랜치 이름을 명시한다.
- 시작 상태 → 실행할 명령 → 관찰할 결과 → 선택 또는 제출 순서로 안내한다.
- 명령은 한 번에 하나씩 실행하게 하고 여러 명령은 번호로 나눈다.
- 준비 영역이라는 말을 일관되게 사용하고 HEAD·origin 등의 의미는 쓰는 곳에서 설명한다.
- 해설은 실제 출력의 파일 이름·내용·표시를 짚고 그 의미를 설명한다.
- 터미널 수행형에는 실행 후 제출을, 선택형에는 보기 선택 후 제출을 명시한다.

## 인접 변경 검토

문제 안내·선택지·해설의 표현을 수정했다. 문제의 교육 목표, 리소스 코드, 시작 파일과 커밋, 정답 식별자, 판정 조건, 해설 시연 명령은 유지했다. 첫 문제는 터미널 수행형이므로 존재하지 않는 보기 선택을 요구하지 않는다. 원격 비교 문제는 시작 상태에 fetch가 실행돼 있지 않아, 안내에도 fetch 실행을 포함했다.

변경된 23문제의 해설 캐시를 다시 만들고 수업 파일·코스의 콘텐츠 해시·검증용 코스를 함께 갱신했다. 이미지 등 다른 파생 자료는 변경이 필요하지 않았다.

## 검증과 앱 반영

- 첫 커밋 6문제와 브랜치 9문제: 실제 Git 해설 재생·판정·독립 초기화 테스트 통과.
- 원격 8문제: 실제 Git 저장소에서 각 문제를 두 번 재생하고 출력·판정·초기화 검증 통과.
- 수업 빌더·코스 번들 해시·기존 KPC 콘텐츠 빌드 검사 통과.
- 설치된 코스는 백업 후 SnapshotStore.prepare/apply로 전체를 검증하고 적용했다. 기존 18수업 중 Git 23문제만 변경됐는지 확인했다.
- 이 반영은 현재 Mac의 설치된 콘텐츠에 적용한다. 원격 수업 저장소의 릴리스는 게시하지 않았다.

실제 앱에서 첫 문제의 안내와 단계별 문단 표시, 수정한 해설 재생, 해설 완료 후 학습 터미널 복귀를 확인했다. 터미널 출력과 하단의 실행 결과 패널을 혼동하지 않도록 첫 문제는 “터미널에 나온 내용”으로 안내한다.

추가 검토: 메모를 다루는 6문제는 cat memo.txt로 현재 파일 내용을 먼저 읽게 했다. 해설에도 고정된 읽기 명령을 실제로 실행하는 read_memo 단계를 추가하고, 출력과 프롬프트 복귀를 확인한 뒤 Git 명령을 이어 간다. 기존 Git 명령의 실행 순서와 판정 조건은 유지했다.

첫 문제의 안내·해설은 pwd → ls → cat memo.txt → git status 순서로 갱신했다. 실제 네이티브 터미널의 명령 출력 순서를 검증하고, 해설 완료·중단 뒤 학습자 쉘 복귀 테스트도 통과했다. Bash 기초 신규 수업은 별도 draft-prd에 8문제와 대표 문제를 준비했으며 정식 등록은 승인 후 진행한다.

추가 검토: 메모 6스텝의 사전 파일·준비 영역·커밋 상태를 지시보다 먼저 설명하고 해설도 같은 상태 안내로 시작한다. 준비 영역은 add 스텝, 커밋은 첫 commit 스텝에 항상 보이는 짧은 도움말로 설명한다. 다시 수정하는 스텝에서는 add한 내용이 자동으로 갱신되지 않음을 되짚는다. 브랜치·원격 문제의 암묵적 시작 상태도 4곳 보완했다. 교육 목표와 실제 Git 시작 상태·판정 조건은 유지한다.

스텝 1의 폴더 점검을 하나의 survey 동작에 묶지 않고 pwd·결과 설명·ls·결과 설명·cat·내용 설명의 별도 동작으로 분리했다. 음성을 출력 설명 단계에서 멈춘 회귀 검증으로, 해당 설명이 끝나기 전에 다음 명령이 입력되지 않는지 확인했다.

사용자 지시에 따라 메모 6문제의 자동 파일·저장소 준비를 제거했다. 새 실습 폴더에는 .git과 memo.txt가 없고, 학습자가 git init·echo·add·commit을 직접 실행한다. 각 문제는 독립 실습임을 명시하고 기존 작업은 별도 작업 공간 버전으로 보존한다. 저장소·준비 영역·커밋·출력 리다이렉션의 의미를 필요한 위치에 설명한다. 원래의 Git 상태 비교·준비·커밋 목표와 리소스 코드는 유지하되 학습자의 상태 구성 과정을 명시했다. Windows Git 실습은 동일한 echo 리다이렉션을 위해 Git Bash를 사용하도록 맞췄다. Windows 실행 검증은 이 Mac에서 수행하지 않았다.

## 첫 Git 수업의 연속 실습 정정

사용자 지시에 따라 이전의 문제별 독립 실습 설계를 대체한다. 첫 단계에서만 git init과 파일 생성을 수행하고, 여섯 단계가 사용자·코스·수업·학습 모드별 동일 저장소를 공유한다. 단계 이동은 파일·준비 영역·커밋을 변경하지 않는다. 해설은 별도 저장소에서 앞 작업을 명령 단위로 재현한다고 먼저 알린다. 초기화는 첫 단계에서만 가능하며 저장소 전체 초기화임을 안내한다.

### 해설의 반복 초기화 제거

앞 수정에서 학습자 저장소만 연결하고 해설에 git init 재현을 남긴 오류를 수정했다. 2~6단계 해설은 앞 단계 완료 상태를 별도 저장소에 준비하고 그 상태를 먼저 설명한다. 화면에서 실행하는 명령은 해당 단계의 새 행동뿐이다. 5단계의 가상 커밋도 제거해 6단계의 시작 상태와 일치시켰다. .git 단독 이름은 공용 발음 모듈에서 깃으로 읽는다.

### 2단계 준비 영역 전후 비교

문제·정답·해설을 cat → status → add → status 순서로 맞췄다. Untracked files와 Changes to be committed를 각각 실제 출력에서 확인하고 설명한 뒤 다음 명령으로 진행한다.

### Git 전체 할 일 적용

Git 첫 기록·브랜치·원격 수업의 23개 스텝 모두 시작 상태와 핵심 개념 다음에 할 일 번호 목록을 표시한다. 기존 해설 명령의 순서를 유지하고 명령별 실행·확인 지점과 마지막 제출 행동을 명시한다. 병합 결과 예상 문제는 예상 후 선택하는 본질을 유지한다. 빌드에서 목록 제목·연속 번호·마지막 제출을 검사한다. ls 빈 목록의 기초 설명은 Bash 첫 등장에만 둔다.
