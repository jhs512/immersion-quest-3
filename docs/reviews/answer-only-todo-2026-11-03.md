# 문제와 맞지 않는 일반 할 일 정리

2026년 11월 3일 게시. 보기를 고르거나 답을 적기만 하는 문제에 질문과 어긋나거나 질문을 되풀이하는 일반 절차 목록(「바뀐 조건과 질문을 읽으세요」 등)이 붙어 있다는 사용자 지적을 반영했다.

## 원인

수업 빌더가 모든 스텝에 제출로 끝나는 할 일 번호 목록을 요구했고, 2026-10-24 커밋 7515b2c2가 이를 맞추려고 정보처리기사 14수업 180스텝에 같은 세 목록을 붙였다. 「바뀐 조건」이 없는 문제, 보기가 셋인 문제에도 「두 보기」라고 적혀 있었다. 규칙과 빌드 검사를 고쳐 코드·명령 없이 답만 하는 스텝은 할 일을 두지 않고, 다시 붙이면 빌드가 실패한다.

## 바꾼 내용

| 과정 | 수업 | 바꾼 필드 |
|---|---:|---:|
| 정보처리기사 실기 | 14 | 180 goal, 15 해설 |
| AICE Associate | 3 | 3 goal |
| 자바 백엔드 | 0 | 0 |

- 답만 하는 180스텝: 일반 할 일 목록 삭제. 질문·보기·답안 칸은 그대로다.
- 코드 수정 3스텝: 할 일 2번이 문제와 어긋난 곳만 실제 고칠 내용으로 고쳤다(aice-features 두 열, aice-quality 두 조건, aice-python-api 제출 중복). 정답이 실제 한 줄 수정인 나머지 22스텝은 유지했다.
- 해설 15스텝: 독립 재검토에서 이 스텝의 실제 실수와 맞지 않던 경고·대조 문장 16개를 고치거나 지웠다.
- 문제 고유 코드, 보기, 정답, 채점, 준비 코드, 챕터 구조는 바꾸지 않았다.

## 게시와 검증

`python tools/publish-course-copy.py --edits tools/course-copy-edits/answer-only-todo-20261103.json --suffix todo-20261103 --publish`

- 게시 직전 세 과정 course.json이 검토한 기준(java 69e63b2e, engineer 77728214, aice 2001337f)과 바이트 단위로 같았다.
- 17수업에 새 고정 태그 `<기존 revision>-todo-20261103`를 만들고 태그 내용을 다시 읽어 확인했다. 기존 17개 태그는 원래 해시 그대로다.
- 코스 커밋: engineer-practical 0ff2f0c8, aice-associate fe287f63. java-backend는 바뀌지 않았다.
- 게시 후 내려받은 세 과정(50/62/24수업)에서 바뀐 것은 17행의 revision·sha256과 변경 이력 한 줄뿐이다. 분류(7/11/6), 수업 순서, 선수 관계, 원격 전용 수업은 그대로다.
- 고정 해시로 내려받은 17수업은 제작 저장소 빌드와 바이트 단위로 같고, 게시 전 수업과의 차이는 검토 목록의 198필드와 revision뿐이다.
- 앱의 갱신 경로(`cargo run --example audit_course_refresh`, 임시 프로필)가 세 과정을 모두 받아들였다.

설치된 앱이 실제로 새 수업을 적용했는지는 별도 확인 사항이다.
