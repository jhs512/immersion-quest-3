# Git 수업 분리와 실제 GitHub PR

2026-10-20 사용자 지시: Git 기본 → 브랜치 기본 → 리모트 → 브랜치 심화 순서로 개편하고 PR은 실제 GitHub에서 실습한다. 추가 지시로 일반 계정도 리모트까지 공개하며 jhs512는 전체 수업을 본다.

## 구성

- 기존 git-first 6단계와 git-remote 8단계를 유지한다. 리모트는 실제 로컬 bare 저장소로 push/fetch/병합 원리를 익힌다.
- 기존 git-branch의 앞 4단계를 브랜치 기본으로 남긴다. 브랜치 생성·전환·커밋·fast-forward 병합이다.
- 뒤 5단계를 새 git-branch-advanced 수업으로 이동한다. 갈라진 변경 병합과 충돌 선택·준비·기록을 다룬다. 기존 스텝 UUID는 유지한다.
- 새 github-pr은 본인의 실제 비공개 GitHub 저장소 하나와 PR 하나로 8단계를 진행한다. 생성 → main push → feature 생성 → 변경 커밋 → feature push → PR 생성 → diff 검토 → 병합과 main 받기다.
- 전체 자바 과정은 24수업 211단계다. 일반 계정은 Bash/Vim/Git 기본/브랜치 기본/리모트 5수업을 본다. jhs512는 24수업을 본다. 다른 두 과정은 표시 범위를 바꾸지 않는다.

## 동작과 보존

실제 GitHub 실습만 HTTPS 전송과 기존 gh 자격 증명 연결을 사용한다. 토큰을 복사하지 않는다. 일반 로컬 Git 실습은 기존 file 프로토콜과 격리 설정을 유지한다. 실습마다 고유한 저장소 이름을 제공하며 같은 수업 안에서 폴더·이름·기록을 유지한다.

검사는 GitHub에 GET 요청만 보낸다. 저장소 소유자·비공개 여부·실제 브랜치 커밋과 PR의 head/base·열림/병합 상태를 확인한다. PR 검토 단계는 실제 터미널에서 성공한 gh pr diff도 확인한다. 해설은 명령을 설명하고 별도 로컬 터미널을 사용하며 GitHub에 자동 생성·병합을 하지 않는다.

저장소는 자동 삭제하지 않는다. 초기화도 GitHub 저장소를 지우지 않는다. 마지막 문제에서 GitHub 웹 설정에서 본인이 정리하도록 안내한다. 본인 PR에 스스로 승인 리뷰를 남기라고 요구하지 않는다.

기존 코스/기본 수업/스텝 ID와 코드·이벤트 파일을 삭제하지 않는다. 이동한 심화 스텝의 예전 답안·이벤트는 기존 Git 브랜치 수업 기록에 남고, 새 심화 수업의 완료로 자동 복사하지 않는다.

## 검증

- 로컬 Git 9단계의 정답, 해설이 학습자 저장소를 바꾸지 않음, 독립 초기화 검사를 통과했다.
- 계정별 공개 범위 5/24와 다른 과정의 전체 표시, 설치 콘텐츠·18수업 캐시 갱신·초안 보존 검사 통과.
- 실제 Windows Bash PTY와 운영용 검사기로 실제 GitHub PR 8단계를 끝까지 통과했다. `target/github-pr-live-result.json`에 결과를 남겼다.
- [검증용 PR](https://github.com/jhs512/mq3-pr-193eaceab78d/pull/1)은 병합을 마쳤으며 저장소와 함께 수동 정리용으로 보존했다. 이 테스트는 외부 쓰기를 하므로 일반 CI에서는 ignored이며 명시적으로 실행해야 한다.
- 전체 78수업/750단계의 등록과 파생물 신선도를 검사한다. Windows에서 대소문자가 같은 검증 디렉터리 이름을 재사용하지 못하도록 예약 키와 중복을 대소문자 구분 없이 검사한다.

실제 Windows 앱 화면에서 기본 4·심화 5·PR 8개 문제의 제목·터미널 배치를 검사했고, PR 해설 완료/중단 후 학습자의 실제 파일이 유지되는 것을 확인했다. `target/pilot-git-course-native-result.json`의 4개 검사가 모두 통과했다. 릴리스 CI 결과는 완료 후 덧붙인다.
