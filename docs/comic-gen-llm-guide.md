# Comic Gen LLM 작성 가이드

Canonical URL: https://jhs512.github.io/comic-gen/llm-guide.md

이 문서는 LLM이 Comic Gen YAML 만화를 작성하거나 수정할 때 읽는 참조입니다. 기준은 v0.8.5의 **한글 기본 문법**과 에셋 라이브러리입니다. 새 코드는 아래 한글 항목·값으로 작성합니다. 기존 영어 문법을 읽거나 수정할 때는 마지막의 영어 호환 표를 참고합니다. 한글 문법에는 v0.3.0 이상, 컷 안 Mermaid 다이어그램에는 v0.4.0 이상 SDK와 비동기 렌더링 연결이 필요합니다. 선택형 공용 뷰어는 v0.5.0 이상, 사람·외형·페르소나는 v0.6.0 이상에서 제공합니다.

만화는 준비된 캐릭터 에셋에 이름표, 표정, 손 제스처, 소품, 대사를 조합한 정적인 그림입니다. 컷 안에 Mermaid 원문을 넣으면 별도 칠판 영역에서 다이어그램을 보여줄 수 있습니다.

## 작성 절차와 출력 형식

1. 설명할 상황을 컷 순서로 나누고 각 컷의 인물 식별자를 정합니다. 컷마다 1~3명, 전체 컷은 1~30개입니다.
2. `등장인물`에 인물을 선언합니다. 식별자는 `웹서버`, `저장소`, `김대리`처럼 주제에 맞는 한글을 권장합니다. 사람의 대화라면 `그림: 사람`과 인물별 `외형`을 정하고, `페르소나`의 직무·성격·말투를 참고해 각자의 질문·반론·설명을 직접 작성합니다. 같은 인물은 모든 컷에서 같은 식별자로 참조합니다.
3. 첫 컷은 완전한 `인물` 목록으로 작성합니다. 이후 컷은 완전한 정의 또는 아래 `구성: 이전` 규칙을 사용합니다. 대사와 전달의 식별자가 해당 컷의 인물 목록에 있는지 확인합니다.
4. 아래 허용 항목·값만 사용합니다. 대사는 YAML 문자열로 인용하고 들여쓰기는 공백 두 칸으로 통일합니다. 숫자는 숫자로, 빈 목록은 `[]`, 초기화 값은 YAML의 `null`로 작성합니다.
5. 브라우저 SDK를 사용할 수 있으면 실제 호스트 버전과 연결 API를 확인한 뒤 코드 펜스 안의 YAML만 전달합니다. 일반 만화는 `만화그리기(원문)` 또는 `컷그리기(원문)`, 다이어그램은 `await 만화그리기비동기(원문)` 또는 `await 컷그리기비동기(원문)`를 사용합니다. `diagnostics`가 빈 목록이고 필요한 컷 수만큼 SVG가 생성되었는지 확인합니다. 도구 없이 작성했거나 실제 호스트에서 검증하지 않았다면 그 호스트에서 실행에 성공했다고 주장하지 않습니다.
6. 채팅 출력은 만화 하나당 **삼중 백틱 `comic-gen` 코드 블록 하나**로 감쌉니다. 블록 안에는 YAML만 넣습니다. 블록 밖에 전체 YAML이나 모든 대사를 반복하지 않습니다.

최소 예제:

```comic-gen
제목: 요청과 응답
등장인물:
  웹서버: {그림: 서버, 이름표: 웹 서버}
  저장소: {그림: 데이터베이스, 이름표: DB}
컷:
  - 인물: [웹서버, 저장소]
    대사:
      - {화자: 웹서버, 상대: 저장소, 내용: "데이터를 부탁해!"}
      - {화자: 저장소, 상대: 웹서버, 내용: "좋아, 바로 찾아볼게!"}
```

`comic-gen`은 Markdown 코드 펜스의 언어 이름입니다. YAML 항목이 아닙니다. 호스트는 `pre > code.language-comic-gen`으로 변환한 블록을 SDK의 `코드블록그리기()`에 연결해야 합니다. 다이어그램을 지원하려면 `await 코드블록그리기비동기()`를 사용합니다. 일반 Markdown 뷰어는 코드로 표시할 수 있습니다. 카드·뷰어 표시 여부는 호스트가 배포한 SDK 버전과 통합에 달려 있습니다.

## 항목과 기본값

파서는 아래 객체별 항목만 허용합니다. 일반 문자열 값은 공백만 있는 값을 제외한 문자열이며 최대 10,000자입니다. 다이어그램 원문만 최대 20,000자입니다. 인물 식별자는 임의 문자열이고 같은 문자열로 일관되게 참조합니다. 식별자·이름표·대사 내용은 번역하거나 치환하지 않습니다.

### 만화와 인물 사전

| 위치                | 항목       | 규칙 / 기본값                                      |
| ------------------- | ---------- | -------------------------------------------------- |
| 최상위              | `제목`     | 선택 문자열. 생략하면 `Comic Gen`                  |
| 최상위              | `등장인물` | 필수 객체. 키는 인물 식별자, 값은 인물 정의        |
| 최상위              | `페르소나` | 선택 프로필 사전. 키는 프로필 식별자               |
| 최상위              | `컷`       | 필수 목록. 1~30컷, 목록 순서로 세로 배치           |
| `등장인물.<식별자>` | `그림`     | 필수. `사람`, `클라이언트`, `서버`, `데이터베이스` |
| `등장인물.<식별자>` | `이름표`   | 선택 문자열. 생략하면 인물 식별자                  |
| `등장인물.<식별자>` | `외형`     | 사람에만 선택 객체. 생략한 항목은 아래 기본값      |
| `등장인물.<식별자>` | `페르소나` | 선택 프로필 객체 또는 최상위 프로필 식별자 문자열  |

`클라이언트`는 원형, `서버`는 둥근 사각형, `데이터베이스`는 원통형 에셋입니다. 학생·선생님·사용자 같은 역할은 `이름표`로 표현할 수 있습니다. 이름표를 바꿔도 새 그림이 생성되지는 않습니다. 현재 문법에는 임의 그림·배경·외부 이미지·에셋 업로드·격자/페이지 배치 항목이 없습니다.

### 사람이 설명하는 페르소나 만화

`그림: 사람`은 준비된 머리·얼굴·옷 부품을 조합한 상반신입니다. `외형`은 인물의 시각적 특징이고 `페르소나`는 대사 작성에 참고하는 정보입니다. 직무를 바꿔도 그림이나 표정은 자동으로 바뀌지 않습니다. 렌더러는 페르소나를 읽어 대사를 생성하지 않습니다. 말투에 맞는 `대사.내용`과 상황에 맞는 `표정`을 직접 작성하세요.

| 프로필 항목 | 규칙                 |
| ----------- | -------------------- |
| `직무`      | 선택 문자열, 1~100자 |
| `성격`      | 선택 문자열, 1~300자 |
| `말투`      | 선택 문자열, 1~300자 |

프로필에는 하나 이상의 항목이 필요하며 공백만 있는 문자열은 허용하지 않습니다. 인물 안에 `{직무: 데이터 전문가, 말투: 짧은 질문으로 설명}`처럼 직접 적거나, 최상위 `페르소나` 사전에 선언하고 인물의 `페르소나: 분석가`로 참조합니다. 프로필에 외형·이름표를 넣거나 프로필 상속·외부 파일 참조를 작성하지 않습니다.

| 외형 항목  | 허용 값 / 기본값                                      |
| ---------- | ----------------------------------------------------- |
| `피부색`   | 따옴표로 감싼 `#RGB` 또는 `#RRGGBB`. 기본 `"#f0c8a6"` |
| `머리모양` | `짧은머리`(기본), `단발`, `긴머리`, `민머리`          |
| `머리색`   | 같은 색상 형식. 기본 `"#47362f"`                      |
| `옷`       | `셔츠`(기본), `재킷`, `후드`                          |
| `옷색`     | 같은 색상 형식. 기본 `"#647bd6"`                      |
| `안경`     | YAML boolean `true` 또는 `false`(기본)                |

인물의 외형과 페르소나는 만화 전체에서 공유합니다. 컷마다 인물 정의를 반복하지 않고 식별자로 참조하며 표정·손·소품만 변화시킵니다. 다른 이야기에서도 같은 인물을 유지하려면 `등장인물`과 `페르소나` 선언을 함께 재사용하세요. 호스트에서는 공유 `cast`·`personas` 객체와 각 이야기의 `panels`를 `JSON.stringify({title, cast, personas, panels})`로 조합해 기존 렌더링 함수에 전달할 수 있습니다. 별도 등록 API는 없습니다.

다음은 김대리·마케팅 팀장·오사원이 질문과 반론으로 구매 전환을 배우는 네 컷입니다. 각자의 관점을 드러내되 한 컷의 대사는 짧게 유지합니다.

```comic-gen
제목: "캠페인 회의: 숫자의 함정"
페르소나:
  분석가:
    직무: 빅데이터 전문가
    성격: 차분하며 근거를 확인한다
    말투: 짧은 질문을 던지고 쉬운 말로 설명한다
  팀장:
    직무: 마케팅 팀장
    성격: 성과를 서둘러 확인하지만 반론을 듣는다
    말투: 결론부터 말하고 업무에 연결해 질문한다
  신입:
    직무: 마케팅 사원
    성격: 호기심이 많고 모르는 점을 솔직히 묻는다
    말투: 구체적으로 질문하고 배운 내용을 자기 말로 정리한다
등장인물:
  김대리:
    그림: 사람
    이름표: 김대리 · 데이터 전문가
    페르소나: 분석가
    외형: {머리모양: 짧은머리, 옷: 재킷, 옷색: "#5379a7", 안경: true}
  마케팅팀장:
    그림: 사람
    이름표: 마케팅 팀장
    페르소나: 팀장
    외형: {피부색: "#d6a279", 머리모양: 단발, 머리색: "#573d36", 옷색: "#b88646"}
  오사원:
    그림: 사람
    이름표: 오사원
    페르소나: 신입
    외형: {머리색: "#303746", 옷: 후드, 옷색: "#609b87"}
컷:
  - 인물: [김대리, {식별자: 마케팅팀장, 표정: 기쁨}, {식별자: 오사원, 표정: 어리둥절}]
    대사:
      - {화자: 마케팅팀장, 상대: 김대리, 내용: "클릭이 늘었으니 광고비를 더 쓰죠?"}
      - {화자: 오사원, 상대: 김대리, 내용: "방문자는 늘었는데 주문은 그대로예요."}
  - 구성: 이전
    인물: [{식별자: 김대리, 손모양: 가리키는손}]
    대사:
      - {화자: 김대리, 상대: 오사원, 내용: "클릭과 구매 전환을 나눠서 보죠."}
      - {화자: 오사원, 상대: 김대리, 내용: "많이 누른다고 많이 사는 건 아니네요?"}
  - 구성: 이전
    인물: [{식별자: 마케팅팀장, 표정: 보통}, {식별자: 오사원, 표정: 보통}]
    대사:
      - {화자: 마케팅팀장, 상대: 김대리, 내용: "그럼 어디서 고객이 떠나는지 봐야겠군요."}
      - {화자: 김대리, 상대: 마케팅팀장, 내용: "맞아요. 장바구니와 결제까지 비교하죠."}
  - 구성: 이전
    인물: [{식별자: 김대리, 손모양: null, 표정: 기쁨}, {식별자: 오사원, 표정: 기쁨}]
    대사:
      - {화자: 오사원, 상대: 마케팅팀장, 내용: "다음 주에는 전환율도 함께 보고할게요!"}
      - {화자: 마케팅팀장, 상대: 오사원, 내용: "좋아요. 같은 기준으로 실험을 확인하죠."}
```

[같은 세 사람의 회의 예제](https://jhs512.github.io/comic-gen/?example=persona-meeting#workspace)와 [Mermaid 설명 예제](https://jhs512.github.io/comic-gen/?example=persona-diagram#workspace)를 수정할 수 있습니다. 사람은 기존 표정·손모양·든소품·전달 문법을 함께 사용하며 대사 없는 컷에도 기본 손이 표시됩니다.

### 컷과 인물 설정

| 위치      | 항목                   | 규칙 / 기본값                                                                                          |
| --------- | ---------------------- | ------------------------------------------------------------------------------------------------------ |
| 컷        | `구성`                 | `전체`(기본) 또는 `이전`. 인물 상태를 작성하는 방식                                                    |
| 컷        | `인물`                 | `전체`에서는 필수. 식별자 문자열 또는 인물 설정 객체의 목록. 결과 인물 수 1~3명, 같은 식별자 중복 불가 |
| 컷        | `제외인물`             | `이전`에서만 허용. 이전 컷에 있는 제거 식별자의 목록                                                   |
| 컷        | `대사`                 | 대사 객체 목록. 생략/`null`이면 빈 목록, 최대 20개                                                     |
| 컷        | `전달`                 | 소품 전달 객체 목록. 생략/`null`이면 빈 목록, 최대 6개                                                 |
| 컷        | `다이어그램`           | 선택 객체. 종류·원문 필수, 제목·높이 선택. 이전 컷에서 상속하지 않음                                   |
| 인물 설정 | `식별자`               | 필수. `등장인물`에 선언한 식별자                                                                       |
| 인물 설정 | `표정`                 | `보통`(기본), `기쁨`, `어리둥절`, `슬픔`, `화남`                                                       |
| 인물 설정 | `손모양`               | 선택. `인사손`, `가리키는손`, `위가리키는손`. 기본 손 제스처 없음                                      |
| 인물 설정 | `손방향`               | 선택(v0.8.0). `왼쪽`, `오른쪽`. `인사손`·`가리키는손`의 자동 방향을 바꿀 때만 손모양과 함께 작성       |
| 인물 설정 | `든소품`               | 선택. `요청`, `데이터`, `열쇠`. 기본 들고 있는 소품 없음                                               |
| 인물 설정 | `가로위치`, `세로위치` | 선택 숫자, 0~1. 기본 자동 배치                                                                         |
| 인물 설정 | `배율`                 | 숫자, 0.5~1.25. 기본 1                                                                                 |

`인물: [웹서버, 저장소]`는 기본 설정의 두 인물을 뜻합니다. 객체를 쓰면 `{식별자: 웹서버, 표정: 기쁨, 든소품: 요청}`처럼 설정합니다. 인물의 `가로위치`는 컷의 내부 여백을 제외한 영역, `세로위치`는 기본 내용 영역의 비율입니다. 캐릭터 크기와 안전 여백에 따라 좌표가 제한되고 좁은 컷에서는 자동 축소됩니다. `배율`은 그 자동 크기에 대한 배율입니다. 좌표는 안전한 대사/인물 영역 안의 위치 보정값이며 컷 전체에 자유롭게 배치하는 좌표가 아닙니다.

손모양은 **정적인 손 그림**입니다. `인사손`은 왼쪽에 펼친 손과 곡선으로 인사를 표현합니다. v0.7.8부터 `가리키는손`은 화자가 처음 지정한 `상대`의 실제 좌우 위치를 향합니다. 상대를 생략하면 기존처럼 왼쪽을 가리킵니다. `위가리키는손`은 왼쪽 팔과 검지를 들어 위의 칠판·그림을 가리킵니다. v0.8.0의 `손방향: 왼쪽`/`손방향: 오른쪽`은 이 자동 좌우 방향을 덮어씁니다. 상대가 없는 쪽의 칠판·물건을 가리키거나 오른쪽 인물에게 인사할 때만 적고, 자동 방향이 맞으면 생략합니다. 손방향은 손모양 없이 쓸 수 없고 `위가리키는손`에는 쓰지 않습니다(`위`는 값이 아닙니다). 이전 컷에서 손모양을 바꾸거나 `null`로 지우면 손방향도 함께 지워집니다. 대상 식별자를 지정하는 항목은 없습니다. 반복·지속시간·애니메이션은 정의하지 않습니다.

v0.7.2부터 사람의 `가리키는손`은 옷색 팔·손바닥·손가락을 연결합니다. v0.7.3부터 도형 캐릭터도 흰색 손바닥·엄지·두께 있는 손가락을 연결합니다. `인사손`은 펼친 손, `가리키는손`은 왼쪽으로 뻗은 손가락으로 구분하며 기존 문법·동작 방향과 정적인 표현을 유지합니다.

v0.7.6의 `인사손`은 넓은 손바닥, 길이와 각도가 다른 다섯 손가락, 연결된 팔과 손목, 손 바깥의 곡선으로 인사를 표현합니다. 사람은 피부색과 소매색을 반영하고 소품을 든 손의 엄지는 소품 앞에 놓입니다. 든소품과 전달이 같은 쪽 손을 사용하면 손 하나를 공유합니다. 표정·소품·말풍선도 개선했으며, SVG·PNG는 정적인 그림이고 새로운 문법 항목은 없습니다.

v0.7.7에서는 든 소품과 전달 소품이 좁은 컷에서도 겹치지 않도록 배치합니다. 전달 경로에 다른 인물이 있으면 선과 소품을 그 인물 위로 배치해 가림을 줄입니다.

v0.7.8에서 오른손으로 상대를 가리키는 인물이 소품도 들면 소품은 반대 손에 그립니다. 물건 한 개를 건네는 이야기는 `든소품` → `전달`만 표시 → 받는 사람의 `든소품` 순으로 컷을 나누고 주는 사람의 `든소품`은 `null`로 지우세요. 같은 소품을 들고 전달하는 설정을 동시에 쓰면 두 물건이 표시됩니다. v0.8.2부터 사람의 `전달`은 주는 사람이 소품을 손에 쥐고 내밀고, 받는 사람은 다섯 손가락을 펼친 손을 상대 쪽으로 뻗습니다. 아이콘은 손 없이 화살표 위에 소품을 얹습니다. 전달 화살표가 인사손·가리키는손 쪽으로 들어가면 손과 겹쳐 의미가 흐려지므로, 전달하는 컷에서는 그쪽 손모양을 지우세요.

### 대사와 소품 전달

| 위치 | 항목                   | 규칙 / 기본값                                                        |
| ---- | ---------------------- | -------------------------------------------------------------------- |
| 대사 | `화자`                 | 필수. 해당 컷에 있는 화자 식별자                                     |
| 대사 | `상대`                 | 선택. 해당 컷에 있는 대화 상대 한 명의 식별자                        |
| 대사 | `내용`                 | 필수 문자열                                                          |
| 대사 | `가로위치`, `세로위치` | 선택 숫자, 0~1. 기본 자동 배치. 가로는 말풍선 중심, 세로는 상단 위치 |
| 대사 | `글자크기`             | 숫자, 12~32. 기본 18                                                 |
| 전달 | `주는인물`, `받는인물` | 필수. 해당 컷에 있는 서로 다른 두 인물 식별자                        |
| 전달 | `소품`                 | 필수. `요청`, `데이터`, `열쇠`                                       |

`상대`는 대화 상대를 지정합니다. 화자의 얼굴은 그 화자의 첫 번째 대화 상대가 있는 좌우 방향으로 조금 이동하며, `가리키는손`도 그 상대 방향을 향합니다. 인물 몸은 정면을 유지합니다. 화면 밖 화자나 여러 상대를 한 목록으로 지정하는 문법은 없습니다. 해설 전용 캡션과 인물이 없는 컷도 현재 지원하지 않습니다.

`전달`은 두 인물 사이에 소품과 전달선을 그리는 정적 표현입니다. 다음 컷의 `든소품` 상태를 자동 변경하지 않으므로 직접 작성합니다. 대사 내용은 실행되지 않고 그림에 표시됩니다.

## 컷 안 Mermaid 다이어그램

한 컷 안에서 인물과 대사가 다이어그램을 설명하게 할 수 있습니다. 다이어그램은 인물·말풍선 영역과 구분되는 칠판에 표시됩니다. `원문`은 Mermaid 문법 그대로이며 `classDiagram`, `sequenceDiagram`, `flowchart` 등 첫 줄에서 그림 종류를 선택합니다. Mermaid 명령·식별자·라벨은 한글 문법 변환 대상이 아닙니다.

| 위치       | 항목   | 규칙 / 기본값                                                        |
| ---------- | ------ | -------------------------------------------------------------------- |
| 다이어그램 | `종류` | 필수. `머메이드`                                                     |
| 다이어그램 | `원문` | 필수 Mermaid 문자열. 최대 20,000자. YAML 블록 문자열로 여러 줄 작성  |
| 다이어그램 | `제목` | 선택 문자열. 기본 `다이어그램`                                       |
| 다이어그램 | `높이` | 선택 숫자 160~1200px. 칠판 영역 높이. 생략하면 그림 비율에 따라 결정 |

```comic-gen
제목: 회원과 주문의 관계
등장인물:
  선생님: {그림: 서버, 이름표: 선생님}
  학생: {그림: 클라이언트, 이름표: 학생}
컷:
  - 인물: [선생님, 학생]
    대사: [{화자: 선생님, 상대: 학생, 내용: "회원 한 명이 여러 주문을 만들어요."}]
    다이어그램:
      종류: 머메이드
      제목: 회원과 주문 클래스
      높이: 260
      원문: |
        classDiagram
          direction LR
          class 회원 {
            +String 이름
            +주문하기()
          }
          class 주문 {
            +String 번호
            +결제하기()
          }
          회원 "1" --> "*" 주문 : 생성
```

```comic-gen
제목: 요청에서 응답까지
등장인물:
  안내자: {그림: 서버, 이름표: 안내자}
컷:
  - 인물: [안내자]
    대사: [{화자: 안내자, 내용: "요청을 받은 서버가 조회한 뒤 응답을 돌려줘요."}]
    다이어그램:
      종류: 머메이드
      제목: 요청 순서
      높이: 440
      원문: |
        sequenceDiagram
          participant 방문자
          participant 서버 as 웹 서버
          participant 저장소 as 데이터베이스
          방문자->>서버: 데이터 요청
          서버->>저장소: 조회
          저장소-->>서버: 결과
          서버-->>방문자: 응답
```

다이어그램을 포함하면 비동기 API가 필요합니다. 동기 API의 반환값이 갑자기 Promise로 바뀌지는 않으며, 다이어그램 입력에는 비동기 함수로 바꾸라는 진단을 반환합니다. 원문과 그림은 다음 컷에 상속하지 않습니다. 반복해서 표시하려면 해당 컷에 다시 적습니다. 인물 없는 컷은 여전히 지원하지 않습니다. 큰 그림은 높이를 늘리거나 여러 컷으로 나누고 한글 라벨의 가독성을 실제 그림에서 확인합니다.

다이어그램을 처음 그릴 때만 Mermaid 11.17.2를 CDN에서 추가로 불러옵니다. 일반 만화는 Mermaid를 불러오지 않습니다. 링크·외부 이미지·HTML 태그·CSS 선언·노드/간선 메타데이터(`@{}`)·사용자 테마/init 지시문/frontmatter를 쓰지 않습니다. `style`, `classDef`, `linkStyle`, `cssClass`, `url()`, `@import` 같은 스타일·외부 참조 기능도 지원하지 않습니다. 원문에 구조와 텍스트 라벨만 작성합니다. 전체 SVG와 개별 컷 SVG에는 다이어그램이 함께 포함되며 완료한 결과를 기존 `exportPng`에 전달합니다.

## 이전 컷 상속

`구성: 이전`은 바로 이전 컷의 인물 상태를 복사한 뒤 식별자별 변경을 적용합니다. 첫 컷은 `구성: 전체`로 작성하거나 `구성`을 생략합니다. `구성`은 컷의 격자 배치나 시간 동작을 정의하는 항목이 아닙니다.

- `인물`을 생략하면 이전 인물의 순서·표정·손 제스처·소품·좌표·배율을 유지합니다.
- 기존 식별자의 객체는 명시한 항목만 바꿉니다. 식별자 문자열은 그 인물을 기본 상태로 초기화하지 않고 기존 상태를 유지합니다.
- 새 식별자는 목록 뒤에 추가하고 생략한 설정은 기본값을 적용합니다. 새 식별자도 `등장인물`에 선언해야 합니다.
- `제외인물`을 먼저 적용합니다. 이전 컷에 없는 식별자를 제거하면 오류입니다.
- 선택 인물 설정의 `null`은 초기화입니다: `표정` → `보통`, `배율` → 1, `가로위치`/`세로위치` → 자동, `손모양`/`손방향`/`든소품` → 없음. 이 초기화 문법은 `이전`의 인물 변경 객체에서 사용합니다. `식별자`는 항상 문자열이며 `null`을 한글로 바꾸지 않습니다.
- `인물: []`는 인물을 비우므로 오류입니다. 변화가 없으면 `인물` 자체를 생략합니다.
- 대사와 소품 전달은 상속하지 않습니다. 매 컷 작성하거나 생략해 빈 목록으로 둡니다. 다이어그램도 생략하면 표시하지 않습니다.
- `등장인물`은 만화 전체에서 공유합니다. 뒤 컷을 수정해도 앞 컷의 상태는 변하지 않습니다.

검증 가능한 네 컷 예제:

```comic-gen
제목: 데이터가 도착하기까지
등장인물:
  웹서버: {그림: 서버, 이름표: 웹 서버}
  저장소: {그림: 데이터베이스, 이름표: DB}
컷:
  - 인물: [{식별자: 웹서버, 표정: 어리둥절}, 저장소]
    대사: [{화자: 웹서버, 상대: 저장소, 내용: "데이터가 있니?"}]
  - 구성: 이전
    인물: [{식별자: 저장소, 표정: 기쁨, 든소품: 데이터}]
    대사: [{화자: 저장소, 상대: 웹서버, 내용: "찾았어!"}]
  - 구성: 이전
    인물: [{식별자: 저장소, 든소품: null}, {식별자: 웹서버, 표정: 기쁨}]
    전달: [{주는인물: 저장소, 받는인물: 웹서버, 소품: 데이터}]
    대사: [{화자: 웹서버, 상대: 저장소, 내용: "고마워!"}]
  - 구성: 이전
    제외인물: [저장소]
    인물: [{식별자: 웹서버, 든소품: 데이터, 손모양: 인사손}]
    대사: [{화자: 웹서버, 내용: "응답을 보낼게."}]
```

## 여러 줄과 수동 배치

자동 배치로 먼저 작성하고 필요할 때만 좌표를 조절합니다. 말풍선과 전달 선의 모든 교차를 자동 회피하지는 않습니다. 특히 양 끝 인물 사이의 전달선과 소품이 중간 인물을 덮을 수 있으므로 그림을 확인하고 인물 위치를 조절하거나 컷을 나눕니다. 긴 이름표는 두 줄 이내로 줄입니다. 여러 줄 대사는 `|-`로 표현할 수 있습니다.

```comic-gen
제목: 질문하기
등장인물:
  학생: {그림: 클라이언트, 이름표: 학생}
  선생님: {그림: 서버, 이름표: 선생님}
컷:
  - 인물:
      - {식별자: 학생, 가로위치: 0.25, 배율: 0.8}
      - {식별자: 선생님, 가로위치: 0.75, 표정: 기쁨}
    대사:
      - 화자: 학생
        상대: 선생님
        가로위치: 0.35
        글자크기: 16
        내용: |-
          첫 번째 질문이에요.
          답은 어디서 찾나요?
      - {화자: 선생님, 상대: 학생, 내용: "예제부터 함께 읽어보자."}
```

## 표시 크기와 레이아웃

`너비`, `컷비율`, `글꼴`, `글꼴버전`은 **SDK 호출 옵션**입니다. YAML 항목으로 넣으면 오류입니다.

| 옵션       | 허용 값 / 기본값                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------------------ |
| `너비`     | 480~2400 숫자, 기본 720                                                                                            |
| `컷비율`   | `기본` 또는 `모바일`. `만화그리기`/`renderer.render` 기본 `기본`, `컷그리기`/`renderer.renderPanels` 기본 `모바일` |
| `글꼴`     | 글꼴 CSS 문자열. 기본 `Malgun Gothic, Apple SD Gothic Neo, sans-serif`                                             |
| `글꼴버전` | 외부 글꼴이 바뀔 때 캐시 조건을 갱신하는 값                                                                        |

넓은 컷은 `만화그리기(원문, {너비: 1600, 컷비율: "기본"})`, 모바일 비율은 `컷그리기(원문, {컷비율: "모바일"})`처럼 호출합니다. `모바일`은 컷의 내용 배치를 유지하면서 위아래 여백을 늘립니다. 컷을 좌우로 재배열하는 문법이나 임의 높이 옵션은 없습니다. `컷그리기`는 컷별 독립 SVG를 반환하고 전체 SVG도 함께 반환합니다. 가로로 넓은 그림을 좁은 화면에서 읽을 때는 호스트 뷰어에서 원래 배치를 유지한 채 축소·확대·스크롤합니다.

`렌더러만들기()`는 독립 캐시를 가진 renderer를 반환합니다. renderer의 `render`, `renderPanels`, `renderAsync`, `renderPanelsAsync`, `clearCache`와 반환값의 `svg`, `panels`, `diagnostics`, `width`, `height`, `cache` 등은 개발자용 영어 이름을 유지합니다.

### 호스트에 선택형 뷰어 연결하기

뷰어 설정은 YAML 항목이 아닙니다. 만화 작성 요청에는 계속 `comic-gen` 펜스 안의 YAML만 전달합니다. 호스트를 구현할 때는 [v0.8.5 렌더링 모듈](https://cdn.jsdelivr.net/gh/jhs512/comic-gen@v0.8.5/cdn/comic-gen.render.js)과 [뷰어 모듈](https://cdn.jsdelivr.net/gh/jhs512/comic-gen@v0.8.5/cdn/comic-gen.viewer.js)을 각각 선택합니다. 기존 [호환 SDK](https://cdn.jsdelivr.net/gh/jhs512/comic-gen@v0.8.5/cdn/comic-gen.js)의 코드 블록 삽입 API도 유지합니다. 타입 선언은 같은 파일 이름의 `.d.ts`를 제공합니다.

- `mountComicCard(container, completedResult)`는 첫 컷 미리보기 카드와 실제 컷 수를 표시하며 정리 함수를 반환합니다. 내용을 교체하거나 컴포넌트를 제거할 때 정리 함수를 호출합니다.
- `createComicViewer()`는 `isOpen`, `open(result, {trigger?})`, `close()`, `destroy()`를 제공합니다. 자체 미리보기 버튼을 연결할 수 있습니다.
- `await renderPanelsAsync(source)` 또는 캐시 렌더러의 `await renderer.renderPanelsAsync(source)`가 반환한 완성된 결과를 전달합니다. 실패 진단이나 Promise를 뷰어에 전달하지 않습니다. 뷰어는 YAML·Mermaid를 직접 렌더링하지 않습니다.
- `ComicViewerResult`는 전체 SVG·너비·높이와 읽기 전용 `panels` 배열을 받습니다. 각 컷의 `index`, `svg`, `width`, `height`는 필수이고 `diagnostics`는 선택입니다. 기존 `PanelsResult`를 그대로 사용할 수 있습니다.

뷰어는 가장 큰 한 컷의 제목·여백을 포함해 가로·세로 화면에 맞추고 전체 만화는 원래 순서로 스크롤해 읽습니다. 화면 넘침 방지 체크박스와 100%·150%·200% 보기 크기는 독립입니다. 컷 좌측/우측, 이전/다음 버튼, 읽기 영역의 ←/→ 키로 이동하며 닫기·Escape는 원래 버튼으로 초점을 돌려줍니다. 현재/전체 수는 실제 컷 수이며 30은 상한입니다. 임의 컷을 추가하거나 같은 컷을 복제해 30을 채우지 않습니다.

Mermaid 렌더링은 임시 iframe에서 고정 [comic-gen.mermaid.js](https://cdn.jsdelivr.net/gh/jhs512/comic-gen@v0.6.0/cdn/comic-gen.mermaid.js)를 사용하며 호스트 AMD `define`을 바꾸지 않습니다. CSP가 있는 호스트에서는 사용할 SDK·jsDelivr 모듈의 스크립트와 뷰어의 Blob 이미지를 허용해야 합니다. 이미 완료한 SVG에는 외부 리소스가 없습니다.

## 영어 문법 호환

정적 vendor 방식의 호스트는 포함된 SDK를 직접 갱신해야 새 기능을 사용할 수 있습니다. 공개 CDN과 가이드만 새 버전으로 게시해도 기존 vendor 파일은 자동으로 바뀌지 않습니다. 사람·외형·페르소나는 v0.6.0 이상으로 갱신한 호스트에서 사용합니다. 다이어그램 기능에는 v0.4.0 이상 SDK와 비동기 API 연결이 모두 필요합니다. 실행 성공 여부는 갱신된 실제 호스트에서 검증합니다.

기존 영어 항목·값도 지원합니다. 한 문서 안에서 서로 다른 항목은 한글과 영어를 혼용할 수 있습니다. **같은 객체에서 같은 항목의 한글·영어 이름을 모두 쓰면 값이 같아도 오류**입니다. 예를 들어 같은 객체의 `제목`과 `title`, 같은 인물 설정의 `표정`과 `expression`, 같은 표시 설정의 `너비`와 `width`는 하나만 작성합니다. 같은 이름을 반복한 YAML 키도 오류입니다.

다음은 호환 문서를 읽을 때 사용하는 대응표입니다. 새 작성 예제에는 앞의 한글 문법을 사용합니다.

| 위치          | 영어 항목 → 한글 항목                                                                                                                                                   |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 만화          | `title` → `제목`, `cast` → `등장인물`, `panels` → `컷`, `personas` → `페르소나`                                                                                         |
| 등장인물 설정 | `asset` → `그림`, `label` → `이름표`, `appearance` → `외형`, `persona` → `페르소나`                                                                                     |
| 프로필        | `role` → `직무`, `personality` → `성격`, `speechStyle` → `말투`                                                                                                         |
| 외형          | `skinColor` → `피부색`, `hairStyle` → `머리모양`, `hairColor` → `머리색`, `outfit` → `옷`, `outfitColor` → `옷색`, `glasses` → `안경`                                   |
| 컷            | `mode` → `구성`, `actors` → `인물`, `dialogue` → `대사`, `transfer` → `전달`, `diagram` → `다이어그램`, `removeActors` → `제외인물`                                     |
| 인물 설정     | `id` → `식별자`, `expression` → `표정`, `gesture` → `손모양`, `gestureDirection` → `손방향`, `holding` → `든소품`, `x` → `가로위치`, `y` → `세로위치`, `scale` → `배율` |
| 대사          | `from` → `화자`, `to` → `상대`, `text` → `내용`, `x` → `가로위치`, `y` → `세로위치`, `fontSize` → `글자크기`                                                            |
| 다이어그램    | `type` → `종류`, `source` → `원문`, `title` → `제목`, `height` → `높이`                                                                                                 |
| 전달          | `from` → `주는인물`, `to` → `받는인물`, `prop` → `소품`                                                                                                                 |
| SDK 표시 옵션 | `width` → `너비`, `font` → `글꼴`, `fontVersion` → `글꼴버전`, `panelFormat` → `컷비율`                                                                                 |

| 값의 종류        | 영어 값 → 한글 값                                                                               |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| 그림             | `human` → `사람`, `client` → `클라이언트`, `server` → `서버`, `database` → `데이터베이스`       |
| 머리모양         | `short` → `짧은머리`, `bob` → `단발`, `long` → `긴머리`, `bald` → `민머리`                      |
| 옷               | `shirt` → `셔츠`, `jacket` → `재킷`, `hoodie` → `후드`                                          |
| 표정             | `neutral` → `보통`, `happy` → `기쁨`, `confused` → `어리둥절`, `sad` → `슬픔`, `angry` → `화남` |
| 손모양           | `wave` → `인사손`, `point` → `가리키는손`, `point-up` → `위가리키는손`                          |
| 손방향           | `left` → `왼쪽`, `right` → `오른쪽`                                                             |
| 든소품·전달 소품 | `request` → `요청`, `data` → `데이터`, `key` → `열쇠`                                           |
| 구성             | `full` → `전체`, `before` → `이전`                                                              |
| 다이어그램 종류  | `mermaid` → `머메이드`                                                                          |
| 컷비율 옵션      | `compact` → `기본`, `phone` → `모바일`                                                          |

항목과 값의 언어는 각각 선택할 수 있으므로 `표정: happy`와 `expression: 기쁨`도 지원합니다. 변환은 위에 열거한 문법 항목과 값에만 적용됩니다. 기존 인물 식별자 `web`을 `웹서버`로 자동 변경하거나 이름표·대사 내용을 번역하지 않습니다. YAML 초기화 값 `null`은 두 문법에서 동일합니다.

| 한글 SDK 함수          | 기존 영어 개발자 함수   |
| ---------------------- | ----------------------- |
| `만화그리기`           | `renderComic`           |
| `컷그리기`             | `renderPanels`          |
| `코드블록그리기`       | `renderCodeBlocks`      |
| `만화그리기비동기`     | `renderComicAsync`      |
| `컷그리기비동기`       | `renderPanelsAsync`     |
| `코드블록그리기비동기` | `renderCodeBlocksAsync` |
| `렌더러만들기`         | `createRenderer`        |
| `만화뷰어만들기`       | `createComicViewer`     |
| `만화카드붙이기`       | `mountComicCard`        |

기존 영어 함수는 계속 사용할 수 있고 같은 한글 문법·옵션을 받습니다. `exportPng`, `downloadBlob` 등 개발자용 함수도 영어 이름을 유지합니다. 개발 중인 `소품동작`/`actions` 확장은 이 가이드의 공개 허용 항목에 포함되지 않습니다. 받기·버리기·떨어뜨리기·던지기 동작을 작성하려면 그 확장을 지원하는 별도 SDK의 문법을 확인해야 합니다.

## 오류 수정과 완료 기준

| 진단 / 상황                                  | 수정                                                                                                                |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 없는 캐릭터 / 에셋 / 표정 / 손 제스처 / 소품 | `등장인물`의 식별자와 위 허용 값으로 맞춤                                                                           |
| 화자 / 대화 상대 / 전달 대상이 컷에 없음     | 해당 인물을 `인물`에 포함하거나 관계를 제거                                                                         |
| 중복 캐릭터 식별자                           | 같은 컷에 식별자당 한 인물만 유지. 같은 그림의 다른 인물은 다른 식별자로 선언                                       |
| 첫 컷 `이전` / `전체`의 `제외인물`           | 첫 컷에 완전한 `인물`을 쓰고 제거는 이후 `이전`에서 수행                                                            |
| `인물: []` / 캐릭터 수 범위 오류             | 변화가 없으면 `이전`의 `인물`을 생략. 최종 인물 수를 1~3명으로 유지                                                 |
| 캐릭터 겹침                                  | `가로위치`/`세로위치`를 벌리거나 `배율`을 줄이거나 자동 배치로 복원                                                 |
| 이름표가 너무 김                             | `이름표`를 두 줄 안에 들어가게 축약                                                                                 |
| 같은 항목의 한글·영어 이름 중복              | 같은 객체에서 둘 중 하나만 작성. 값이 같아도 하나를 제거                                                            |
| 없는 페르소나 / 빈 프로필                    | 최상위 사전에 참조 ID를 선언하거나 인라인 객체로 작성. 직무·성격·말투 중 하나 이상을 채움                           |
| 잘못된 외형                                  | 사람에만 지정. 허용 머리·옷 값을 사용하고 색상은 인용한 #RGB/#RRGGBB, 안경은 boolean으로 작성                       |
| 알 수 없는 항목 / YAML 구문 오류             | 객체별 항목 표에 맞추고 들여쓰기·인용부호·중복 키 수정                                                              |
| 입력 제한                                    | 전체 YAML 100,000자 이하, 일반 문자열마다 10,000자 이하, 다이어그램 원문 20,000자 이하, 컷·대사·전달 개수 제한 준수 |

완료 전에 모든 식별자 참조, 허용 항목·값, 상속 후 인물 수, 컷 순서, 출력 펜스를 확인합니다. 검증 도구가 있다면 모든 만화 블록의 `diagnostics`가 비어 있고 필요한 컷 수만큼 SVG가 반환되는지 확인합니다. 그림을 볼 수 있다면 대사와 소품의 가독성, 전달선이 다른 인물을 덮는지, 손모양의 고정 방향이 의도에 맞는지도 확인합니다.
