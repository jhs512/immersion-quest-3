# 네트워크 본편·채점기 배포

2026-11-09 사용자 지시에 따라 검증된 네트워크 수업과 실제 상태 채점기를 최신 main에 통합한다. 이전 작업 공간 전체를 배포하지 않는다. 현재 main의 Java 48·AICE 24·정보처리기사 30수업과 기존 기능을 유지하고 네트워크 시리즈 8수업을 추가했다. 생성된 기본 Java 코스는 56수업이다.

운영 Java 코스에는 별도로 게시된 웹 수업 두 개도 있으므로, 게시 시 생성 파일로 전체 코스를 덮어쓰지 않는다. `tools/publish-network-foundations.py`가 최신 운영 파일을 읽어 네트워크 8개만 병합한다. 기존 50개가 그대로라면 공개 후 58수업이다. 다른 수업의 상대 순서·ID·내용·분류·예고와 최신 메타데이터를 유지하고 contents SHA로 동시 갱신을 검사한다.

## 수업과 실제 판정

- 바이트·끝점·IP·라우팅·DNS·TCP·UDP·HTTP의 Java 실행 문제 32개를 포함한다.
- IP 수업에 루프백 바인딩·다중 주소·/29 할당 범위·마스크와 경로 실습 4개를 연결한다.
- 라우팅 수업에 특정 목적지의 다음 홉과 NAT 관찰 실습 2개를 연결한다.
- DNS 수업에 권한 A 레코드 전환과 별도 캐시 갱신 실습 2개를 연결한다.
- 새 8개 실습은 명령 이력이나 답안 파일 대신 실제 주소·프리픽스·경로·DNS 응답·HTTP 식별 응답을 검사한다. 주소 장부도 실제 IPAM과 경로에 대조한다.
- 마지막 한 문제만으로 나머지 학습을 완료시키지 않는다. 새 시리즈는 각 필수 문제를 통과하는 방식이다.

`src/network_practice.rs`가 학생의 저장 환경과 별도 해설 환경을 관리한다. 초기화는 실습 소유 라벨의 자원만 정리한다. 호스트 IP·경로·DNS를 바꾸거나 전체 Docker prune을 하지 않는다. 새 실행기는 기존 Docker CLI 탐색과 자식 PATH 설정을 재사용하며 사용자 범위 Windows 설치와 macOS Docker.app 경로도 고려한다. 관찰용 컨테이너에는 NET_ADMIN을 주지 않는다.

각 수업의 `lesson-preview.json`을 제작 기준으로 삼고 PRD·실행 문제와의 관계를 검사한다. 코스 목표와 `backend-sequence.json`의 승인된 흐름을 해시에 연결했다. Docker 도입 뒤 네트워크 시리즈를 배치하고 기존 Docker 네트워크 응용으로 이어간다. 다른 수업의 예고 원본 체계를 함께 바꾸지 않는다.

## 검증·게시 순서

1. 새 원고·해설 캐시·코스 묶음을 빌드하고 네트워크 Java 문제를 실제 플레이어 채점기로 확인한다.
2. Docker의 정답·오답·재접속·학생/해설 분리·초기화·소유 자원 정리와 최소 GUI PATH를 검사한다.
3. 소스 변경을 main에 푸시해 공식 데스크톱 릴리스 워크플로를 실행한다.
4. `--stage-lessons`로 불변 수업 파일과 태그만 먼저 준비할 수 있다. 운영 코스는 이 단계에서 바꾸지 않는다.
5. Windows 설치 파일·macOS Apple Silicon DMG·체크섬이 있는 공개 앱 릴리스를 확인한다. 릴리스 태그의 커밋과 실제 네트워크 채점기 소스 바이트가 검증한 소스와 같아야 한다.
6. `--publish --player-release <태그> --source-commit <커밋>`으로 운영 코스를 병합하고 모든 불변 수업 파일·태그·예고·코스 참조를 다시 확인한다.

기존 main에 들어 있던 큰 컬렉션 표시 상한(`685c7d55`)과 맞지 않는 Java 시각화 검증 해시도 발견했다. 렌더러 동작은 변경하지 않고 테스트의 기대 해시와 PROVENANCE 기록을 실제 추적 파일에 맞췄다.

Docker 실제 동작과 네이티브 학습 화면 검증은 Windows에서 수행한다. 실제 인터넷 공인 IP를 할당하는 실험은 아니다. 로컬 NAT 관찰자도 사설 주소이며, 이 결과를 공인 IP 할당 검증으로 표시하지 않는다. macOS의 Docker 실제 실습과 음성 청취는 별도 기기 검증 범위다.
