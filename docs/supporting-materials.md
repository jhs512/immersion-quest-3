# 선택 부가 설명 자료

공통 목표·핵심 흐름과 문제의 정답·채점은 그대로 둔다. 자료는 문제의 `supporting_materials`에 선택적으로 넣는다. 처음에는 제목 버튼만 보인다. 버튼으로 펼치거나 접으며, 자료 열람 자체는 성공이나 해설 열람으로 기록하지 않는다.

학생 데이터에는 표시할 자료만 넣는다. 내부 핵심 흐름, 이미지 생성 프롬프트, 생성 설정은 넣지 않는다. 알려지지 않은 자료 종류·필드, 중복 키, 과도한 개수·크기는 수업을 받아올 때 거절한다.

## 표시 형식

```json
{
  "supporting_materials": [
    {"id":"flow", "title":"관계 그림", "kind":"mermaid", "source":"flowchart LR\n A --> B"},
    {"id":"state", "title":"값 변화", "kind":"interactive", "variants":[
      {"label":"처음 조건", "frames":[
        {"caption":"값을 준비해요.", "facts":{"value":"1"}},
        {"caption":"하나를 더했어요.", "facts":{"value":"2"}}
      ]}
    ]}
  ]
}
```

Mermaid는 기존에 번들된 버전으로 그린다. 네트워크 연결 없이 실행하며 `strict` 설정과 같은 출처 접근이 없는 iframe sandbox를 함께 사용한다. 원문 오류가 있으면 오류 안내와 원문을 보여 준다. 이는 Mermaid 문법의 정확성이나 다이어그램의 교육적 품질을 자동 보장한다는 뜻은 아니다.

인터랙티브 자료는 조건별 상태들의 목록이다. 이전·다음으로 이동하고 조건을 바꾸면 그 조건의 처음 상태로 돌아간다. 브라우저 기본 버튼·선택 상자를 쓰고 현재 상태는 표와 짧은 글로 보여 준다. 수업에서 임의 JavaScript를 전달하지 않는다. 계산이나 코드 실행의 실제 결과를 표현할 때는 제작 과정에서 결과와 상태를 대조해야 한다. 이 자료 자체가 범용 코드 디버거는 아니다.

이미지와 만화는 각각 `kind: "image"`, `kind: "comic"`을 사용한다. 둘 다 `image` 객체에 `alt`, `png_base64`, `sha256`을 넣는다. 외부 URL·SVG·HTML은 받지 않는다. PNG 헤더·고정 해시·크기 제한을 검사하고 브라우저가 그림을 디코딩한다. PNG 헤더 검사는 전체 파일 디코딩 검사가 아니다. 그림의 대체 설명은 필수이고 그림 아래에도 보인다. 여러 컷 만화는 하나의 PNG로 제공할 수 있다. 이 기능은 이미지·만화 생성 서비스를 새로 도입하지 않는다.

자료는 스텝당 8개, Mermaid 원문은 32768바이트, 조건은 8개, 조건별 상태는 80개까지다. PNG는 base64 2800000자 이하, 한 변 4096픽셀 이하이며 총 800만 픽셀 이하다. 이 한도들은 학습자가 읽을 분량의 권장값이 아니다. 실제 문제는 단순하게 유지한다.

## 이미지 원본과 재사용

제작자 작업 폴더에서 다음 세 자료를 분리한다.

- 의미 원문(`support_spec`): 교육적 의미와 반드시 보여야 할 요소만 적는다. 프롬프트·렌더러 설정은 넣지 않는다.
- 생성 레시피: 프롬프트, 모델/렌더러 버전, 크기 등 생성 설정을 별도 파일로 관리한다.
- 이미지 결과(`asset`): 결과 파일과 내용 해시를 기록한다. 학생에게는 검증된 PNG·대체 설명·해시만 내보낸다.

`docs/content-review.md`의 인접 검토 경로를 사용한다. 학습 콘텐츠가 바뀌면 의미 원문의 영향부터 판단한다. 의미 원문이 바뀌면 변경 전후와 기존 이미지를 검토한다. 의미·필수 요소가 같다는 검토 결과면 기존 파일과 해시를 유지한다. 필수 시각 요소가 달라진 경우만 그 이미지의 생성을 요청한다. 판단 실패는 재사용 승인으로 처리하지 않는다. 검토·생성은 서로 다른 이력을 남기며 동일한 성공 요청은 재사용한다. 생성 레시피를 바꾼 사실만으로 의미 원문을 덮어쓰거나 모든 이미지를 자동 재생성하지 않는다.

## 검증 범위

고정 코스·수업의 J fixture는 A의 문제·정답·채점을 유지하며 네 종류의 자료만 추가한다. 한 픽셀 PNG는 로딩 경로 검증용이며 실제 만화 품질의 증거가 아니다. 제작 정책·모델 판단의 품질과 실제 수업 승인도 별도다.

`tests/supporting_materials.rs`는 수업 입수·고정 해시·자료 검증과 격리 문서의 입력 처리를 검사한다. `tools/test_supporting_assets.py`는 합성 검토기를 사용해 의미 동일 수정의 이미지 재사용과 필수 요소 변경 시 해당 이미지만 생성하는 흐름을 검사한다. 실제 WebView 검사는 `tools/player-pilot-native.js`에 있다. 실제 OS 키보드 입력 검증 범위는 완료 보고에서 별도로 명시한다.
