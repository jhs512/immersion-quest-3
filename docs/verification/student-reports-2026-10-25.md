## 배포를 막던 검사 두 건

9dd6f12의 릴리즈 실행이 두 플랫폼에서 실패했다. 둘 다 원인을 재현해 고쳤다.

- macOS `git_graph`: Git 2.55의 `git merge`가 `git maintenance run --auto --detach`를 띄우고, 이 분리 프로세스가 merge가 끝난 뒤에도 명령 기록(trace2)에 줄을 덧붙였다. 학습자가 실행하지 않은 백그라운드 작업이 학습 저장소와 명령 기록을 건드린다. Windows Git 2.54에서도 같은 자식 프로세스를 확인했다. 실습 전용 전역 설정에 `maintenance.auto=false`를 넣는다. 새 실습과 초기화한 실습에만 넣고, 학습자가 이미 쓴 전역 설정은 고쳐 쓰지 않는다. 검사 `practice_git_never_starts_background_maintenance_and_keeps_learner_global_config`.
- Windows `vim_practice`: 실시간 상태는 입력 모드·2열이었지만 다시 연 Vim은 일반 모드·2열이었다. 마지막 복원 기록이 사라진 것이다. 반복 실행으로는 재현되지 않았다. 다른 프로세스가 `vim-resume.json`을 잠깐 열고 있으면(예: 실시간 검사) Vim의 rename이 실패한다. 다음 상태가 같으면 다시 쓰지 않아 낡은 기록이 남는 것을 재현했다. CI와 같은 결과(seq 1, ready, n, 2열)다. `assets/vim/practice.vim`은 저장에 성공할 때까지 마지막 학습자 상태를 보관하고, 매 기록과 80ms 타이머마다 다시 쓴다. 종료 중 상태로 덮어쓰지 않는 기존 규칙은 그대로다. 검사 `a_briefly_locked_resume_file_still_receives_the_latest_insert_state`.
