# Mac 한글 입력 시 공백 추가 · 2026-10-24

## 재현과 원인

사용자는 현재 게시 앱(build.104)에서 영문으로 `echo "`를 입력한 뒤 한영 전환하여 두벌식으로 `첫`을 치면 `echo " 첫`처럼 공백이 끼는 현상을 보고했다.

별도의 격리된 실제 Mac WKWebView 앱에서 사용자가 직접 입력한 이벤트를 로컬로 기록했다. `compositionstart/end` 없이 `insertText`와 `insertReplacementText`가 발생했다. 앞서 Space 키로 이미 전송된 공백이 숨겨진 helper textarea에는 NBSP(U+00A0)로 남아 있었고, 한글을 시작할 때 WebKit이 이 기존 NBSP를 일반 공백(U+0020)으로 바꿨다. 브리지는 입력 전후 문자열의 접두사가 달라졌다고 판단해, 기존 공백을 새 입력으로 오인하여 자모 앞에 추가 전송했다. 실제 로컬 기록에서 이 추가 전송을 확인했다. 모든 시도에서 동일하게 발생하는 것은 아니었다.

원본 이벤트 기록은 로컬 검증 산출물에만 보관한다. 입력 전문이나 개인 진단 자료를 저장소에 넣지 않는다. 검사에는 NBSP가 일반 공백으로 바뀌는 최소 이벤트만 재구성했다.

## 수정

`assets/terminal/terminal.js`에서 helper textarea의 입력 전·후 스냅샷을 비교할 때도 PTY 전송과 동일한 NBSP → 일반 공백 및 NFC 정규화를 적용한다. 이미 전송된 구분자가 WebKit 내부에서 표현만 바뀐 경우 다시 전송하지 않는다. 공백을 일괄 삭제하거나 trim하지 않으며, 사용자가 실제로 입력한 선행 공백과 단어 사이 공백은 유지한다. 터미널 번들을 다시 빌드했다.

## 검증

- 수정 전: 기록을 최소화한 Chromium/WebKit 회귀 검사 6건이 `echo " 첫 memo"`를 만들어 실패했다.
- 수정 후: `node --test tests/js/terminal-ime.test.cjs` 34건 통과. 기존 18건에 NBSP 접두사 4종 × 의도한 선행 공백 유무 2종 × Chromium/WebKit 2종을 추가했다. 의도한 공백이 없을 때는 `echo "첫 memo"`, 있을 때는 `echo " 첫 memo"`를 유지한다.
- `npm --prefix assets/terminal run build`, `cargo build --locked --bin molip-quest` 통과.
- 이벤트 추적 코드는 임시 디버그 바이너리에서만 사용했고 소스 변경에는 포함하지 않았다. 수정본 검증 앱에서는 추적을 껐다.
- 수정본의 실제 두벌식 재입력 확인: 사용자 확인 대기.

이는 소스와 검증 앱의 수정이며 새 설치 파일 배포 완료를 뜻하지 않는다. 직접/복사 입력 차이 신고 전체나 별도 증상까지 해결됐다고 일반화하지 않는다.
