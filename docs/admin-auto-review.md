# 관리자 자동 풀이

코스 관리자가 수업을 손 놓고 끝까지 보며 검수하는 기능이다. 현재 스텝부터 Esc를 누를 때까지 스텝마다 해설을 재생하고, 최종 정답을 실제로 입력·실행·채점한다. 통과하면 그 관리자 계정의 진도에 일반 학습과 같은 경로로 기록하고 다음 스텝, 수업 끝에서는 같은 코스의 다음 수업으로 이어 간다.

## 누가 쓰나

GitHub가 코스 저장소 push 권한을 알려 주는 계정만 쓴다(`Github::can_edit_course`, 도전 과제 초안과 같은 기준). 앱은 관리자 목록을 따로 두지 않는다. 권한은 코스를 열 때 읽고, 시작할 때와 다음 수업을 열기 직전에 다시 읽는다. 권한이 없으면 실행 막대와 시작 버튼이 없고 단축키는 안내만 띄운다. 미리 풀어 보기(준비 중 수업의 도전 과제)에서는 쓰지 않는다.

## 조작

| 행동 | Windows | macOS |
| --- | --- | --- |
| 시작 (현재 스텝부터) | Ctrl + Alt + Shift + A | Control + Option + Shift + A |
| 일시정지 · 재개 | Space | Space |
| 멈춤 | Esc | Esc |

자동 풀이는 화면에 줄이나 너비를 새로 차지하지 않는다. 좁은 창(640px 이하)에서는 수업 머리줄에 남는 자리가 없다는 것을 실제 앱에서 확인했다.

- 시작 버튼 `▶ 자동 풀이`는 관리자에게만 해설 버튼 옆(해설 재생 · 멈춤 · 속도)에 있다. 실행 중에도 그 자리에 비활성으로 남아, 시작해도 아무것도 움직이지 않는다. 마우스를 올리면 설명과 단축키가 보인다.
- 실행 중에는 머리줄의 `수업 링크 복사` 버튼 자리를 같은 크기로 덮는다. 현재 문제 번호(`●23`, 일시정지면 `⏸23`)와 일시정지·재개, 멈춤(■) 버튼만 보인다. 수업·스텝·단계 전체 문장은 마우스를 올리거나 화면 읽기 프로그램으로 확인한다.
- 멈추거나 끝나면 같은 자리에 `! 멈춤` 또는 `✓ 완료`만 남는다. 누르면 이유와 실제로 채점해 기록한 스텝 목록이 페이지 위에 떠서 보이고, `닫기`를 누르면 링크 복사 버튼이 돌아온다.
- 실행 중에는 문제 영역의 클릭·입력을 막는다. 해설 속도 선택과 음성 속도 단축키는 그대로 쓸 수 있다.

## 한 스텝에서 하는 일

1. 해설: 기존 `해설 재생` 버튼을 누른다. 음성·자막·강조·시연과 끝난 뒤의 학습자 작업 복원은 수동 재생과 같다. 해설 중 오류가 나면 멈춘다.
2. 실습 환경은 실행마다 한 번만 준비: 실행이 어떤 실습 환경(그 수업·모드의 실습 작업 공간)을 처음 쓰는 스텝에서만 기존 `초기화`(`reset_step`)로 그 스텝의 공식 시작 상태(앞 스텝의 파일·현재 폴더·Git 상태 포함)를 만들고 새 셸을 연다. 중간 스텝에서 시작해도 앞 스텝의 결과가 갖춰진 상태에서 시작한다. 그 뒤의 스텝은 이미 통과한 스텝이어도 초기화하지 않고, 앞 스텝이 실제로 남긴 파일·현재 폴더·Git 상태 위에서 이어 간다(`AutoRun::claim_initialization`). 다음 수업은 자기 실습 환경을 처음 쓸 때 한 번 준비한다. 같은 실습 환경을 다시 만나면 수업이 바뀌어도 다시 준비하지 않는다. 이어진 상태에서 명령이 목표에 닿지 못하면 상태를 그대로 두고 이유와 함께 멈춘다. 처음부터 다시 하려면 사람이 직접 `초기화`를 누른 뒤 다시 시작한다. 오류나 완료 표시 때문에 몰래 초기화하는 대체 경로는 없다. 수업 전체 기록을 지우거나 되돌리는 기능도 없다.
3. 정답 입력: 코드 문제는 정답 코드, 답 문제는 채점 기준의 답, 터미널 문제는 해설의 터미널 동작(`bash_command`, `git_command`, Vim 키, Java `patch_code` 등)을 학습자의 실제 터미널에 입력한다. 답이 있는 터미널 문제는 예상 보기를 먼저 고른다.
4. 실행·제출: 기존 `코드 실행`·`제출` 버튼을 누른다. 채점기가 통과시킨 경우에만 진행한다. 오답·실행 오류·지원하지 않는 문제(실제 GitHub 저장소와 PR을 만드는 문제)는 그 스텝에서 이유를 보이고 멈춘다.
5. 기록: 제출의 기존 기록 스레드가 이 기기에 먼저 저장하고 GitHub에는 백그라운드로 올린다. 자동 풀이는 이 기기 저장이 확인된 뒤에 다음 스텝으로 간다.

## 속도

해설과 자동 풀이의 타이핑은 기존 해설 속도 설정(0.75~3배, `assets/layout/voice.js`의 목록 하나)을 따른다. 속도 선택 상자는 스텝·수업이 바뀌어 다시 그려져도 고른 속도를 보이고, 1.5배 기본값은 아무것도 고른 적 없을 때만 쓴다. 실행 중에 속도를 바꾸면 말하는 문장과 남은 타이핑에 바로 적용된다. 실행·채점·기록 같은 실제 처리는 속도와 상관없이 실제 완료 신호를 기다린다.

## 멈춤과 이동

Esc, 멈춤 버튼, 해설 멈춤 버튼, 스텝·수업 목록·링크로 직접 이동, 계정 다시 확인, 콘텐츠 업데이트 적용은 실행을 끝낸다. 실행마다 세대 번호와 현재 대상(수업·회차·스텝)이 있어 멈춘 실행이나 지난 스텝의 늦은 콜백은 아무것도 진행하지 않는다. 다음 수업은 실행 자신의 수업 끝 처리만 연다. 다음 수업을 불러오는 중에 Esc를 누르면 그 수업의 시작 기록도 남기지 않는다. 이미 누른 제출의 통과는 일반 제출처럼 그 문제에 기록된다.

## 검증

- `cargo test --lib auto_review`: 모든 번들 수업 스텝의 풀이 계획, 정답 형식, 다음 수업 순서, 세대·대상 보호.
- `cargo test --test auto_review_terminal`: 실제 PTY의 Bash·Git에서 통과한 스텝이 그대로 다시 통과하는 문제, 스텝 초기화 뒤 실제 명령으로 다시 통과.
- `node --test tests/js/auto-run.test.cjs`: 속도별·속도 변경 중 타이핑과 음성, 일시정지, Esc 즉시 중단, 단축키·입력 보호.
- `cargo test --test player_auto_state_native -- --ignored`: 실제 앱에서 고른 속도(2배·3배)가 다음 스텝·다시 그린 선택 상자·다음 수업의 새 음성에서 선택 상자·`molipVoice.rate`·저장값·재생 속도로 같은지, 7~10번 연속 실행(처음·이미 푼 상태 반복)과 22번→Java 수업 실행이 실습 환경을 한 번만 준비하고 실제 파일·폴더·현재 위치를 이어 가는지, 업로드된 통과 수. `MOLIP_AUTO_STATE_PART=rate|runs`로 반만 돌린다. 진행은 세션 폴더의 `auto-state.log`에 남는다.
- `cargo test --test player_auto_review_native -- --ignored`: 실제 앱에서 학생 계정 거부, Bash→Java 연속 실행, 권한 회수, Esc, 직접 이동, 코스 끝, 업로드된 기록 수. 시작·멈춤·이유 보기 전후로 머리줄·스텝 목록·문제 영역의 위치와 크기가 같은지(1280px, 640px) 재고, `target/admin-review/screens/`에 실제 창 화면을 남긴다(`tools/capture-window.ps1`).
