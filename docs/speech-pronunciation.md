# 음성 발음 변환: 사전과 기호 문맥

음성으로 보내는 문장만 바꾼다. 화면 글, 자막, 코드, 정답, 터미널 입력, 강조 위치는 원문 그대로다. 구현과 사전은
`assets/speech/pronunciation.js` 하나이고, 기기 음성(Web Speech)과 Edge 신경망 음성(`assets/layout/voice.js` → `src/tts.rs`),
해설 모드(`assets/layout/agent.js`), 본문 읽어주기(`assets/speech/speech.js`)가 모두 `molipPronunciation.pronunciationText`를 부른다.
말투 규칙은 `docs/voice.md`에 있다.

## 사전 (`LEXICON`)

단어를 어떻게 읽는지는 `LEXICON` 배열이 유일한 근거다. 묶음마다 `scope`(적용 범위), `rationale`(이렇게 읽는 이유),
`evidence`(수업에서의 근거·빈도), 항목마다 `[원문, 읽는 말, 예]`가 있다. 이 문서는 사전을 옮겨 적지 않는다.

| scope | 적용 |
| --- | --- |
| `term` | 본문의 기존 수업 용어. 더 긴 영문 단어나 하이픈 이름(`py-2`) 안에서는 바꾸지 않는다. |
| `strict` | 본문의 약어·제품명. 경로, URL, 옵션, 식별자, 환경 변수(`$JAVA_HOME`), 파일 이름(`nginx.conf`) 안에서는 바꾸지 않는다. |
| `command` | `strict`에 더해, 코드 안에서는 명령 자리(줄 처음, `|` `;` `&&` `$` `sudo` 뒤)이거나 코드 전체가 그 단어일 때만. |
| `after:<명령>` | 그 명령 바로 뒤의 하위 명령만(`git commit`의 `commit`). 인수(`git add status`의 `status`)는 그대로. |
| `java-class` | Java 클래스 이름(`Main`). `.java`·`.class` 파일 이름 앞부분, `java [옵션] Main`의 클래스 인수, `class Main`·`new Main()`, 코드 전체가 그 이름일 때만. `MainTest`, URL, 일반 문장의 `Main`은 그대로. |
| `extension` | 파일 확장자(`.class` → 클래스). 표에 없는 확장자는 그대로. |
| `brand` | Git, GitHub. 대소문자 무관. |

읽는 말은 한국 개발자가 실제로 말하는 형태를 쓴다. 약어는 알파벳 이름으로 읽어 원래 철자를 알아볼 수 있게 하고(`mkdir` →
엠케이디아이알, `JDBC` → 제이디비씨), 뜻으로 바꾸거나 철자와 뜻을 길게 겹쳐 말하지 않는다. 항목을 더할 때는 예를 넣고
`assets/speech/symbols-lexicon.test.mjs`에 한 줄 검사를 더한다. 같은 원문이 두 번 들어가면 검사가 실패한다.

`javac`는 자바 씨로 두 단어로 띄운다(붙여 쓰면 자백으로 들린다). 파일 이름 앞부분이 사전의 한 단어이면 그 단어로 읽는다
(`nginx.conf` → 엔진엑스 점 콘프, `Main.java` → 메인 점 자바). 확장자나 점 파일을 혼자 말하면 점을 읽는다(`.java를` → 점 자바를,
`.practice` → 점 practice).

코드(백틱) 안에서도 사전 단어는 본문과 같은 경계로 같은 말로 읽는다(`print(x)` → 프린트(x), `` `for` `` → 포). 코드에만 있는 규칙
(명령 자리, 하위 명령, 셸 리다이렉션, 옵션)이 먼저 적용되고, 더 긴 식별자(`print_total`, `git_status`)와 경로 안의 파일 이름은 그대로다.
같은 낱말이 백틱 여부에 따라 다르게 들리지 않게 하고, 변환한 글을 다시 넣어도 바뀌지 않게 하려는 것이다(아래 「멱등」).

바꾼 단어 뒤의 조사는 읽는 말에 맞춘다(`:는` → 콜론은, `rm로` → 알엠으로). 단어 끝에 붙은 조사만 바꾼다.

## 기호

기호는 문맥에 따라 세 가지로 읽는다. 바뀐 말 뒤에 조사가 붙어 있으면 붙여 둔다.

| 문맥 | 예 | 읽는 말 |
| --- | --- | --- |
| 두 값 사이(식) | `a >= b`, `x != y`, `total += price` | a 크거나 같다 b, x 같지 않다 y, total 플러스 이퀄 price |
| 기호 자체를 말함 | `>는`, `` `>=` ``, `답은 |.`, `==예요` | 크다 기호는, 크거나 같다 기호, 답은 파이프, 등호 두 개예요 |
| 앞에 붙는 기호 | `!done`, `*p`, `&stock`, `-1`, `:2` | 낫 done, 별표 p, 앰퍼샌드 stock, 마이너스 1, 콜론 2 |
| 뒤에 붙는 기호 | `i++`, `HEAD^`, `b%` | i 플러스 플러스, HEAD 캐럿, b 퍼센트 |

긴 기호를 먼저 읽는다(`!==` → `!=` → `!`). 한 번 바꾼 말은 다시 바꾸지 않는다.

### 구별 규칙과 한계

- **비교와 Bash 리다이렉션.** `>`·`>>`·`<`는 셸 명령으로 시작하는 코드(`echo`, `cat`, `ls`, `git`, `docker` …)에서, 뒤가 파일
  경로(`memo.txt`, `../inbox/a.txt`, `.practice`, `/dev/null`)일 때, 또는 같은 문장이 파일 쓰기를 말할 때(파일·덮어·덧붙·
  사본·끝에 붙…) 꺾쇠로 읽는다. 그 밖에는 비교다. 파일 이야기를 하는 문장 안의 단독 비교 기호는 꺾쇠로 읽힐 수 있다.
- **제네릭·HTML과 비교.** `List<String>`처럼 이름에 붙고 대문자 타입이 들어간 꺾쇠는 읽지 않는다(List String).
  소문자 태그 `<li>`·`</li>`는 li 태그, 닫는 li 태그. `i<n`처럼 소문자 변수 사이는 비교다.
- **파이프와 논리.** `|`는 파이프, `||`는 식에서 오어, 기호 자체는 파이프 두 개. `&&`는 앤드 / 앰퍼샌드 두 개.
- **퍼센트와 나머지.** 숫자 뒤 `%`는 퍼센트(38.20% 포함), 두 값 사이는 나머지, 기호 자체는 퍼센트 기호, `%d`·`%{…}`는 퍼센트.
- **경로와 나눗셈.** 붙어 있는 `/`는 경로라 읽지 않는다. 띄어 쓴 `/`는 코드나 숫자·괄호 옆에서만 나누기다
  (`훈련 / 테스트`는 그대로). `/29`(네트워크 접두사)는 슬래시 29. 숫자 `1/2`는 2분의 1.
- **빼기와 하이픈·옵션.** `-r`, `--base`, `no-error`는 그대로. 빼기는 양쪽을 띄운 `5 - 3`만이다. 이름·아이디 안의 하이픈
  (`app2-127-0-0-1.nip.io`, 스트림 아이디 `1-1`, 키 `attend:2026-10`)은 그대로, 띄움이 한쪽뿐인 `0 -1`·`head -1`은 마이너스 1.
- **숫자 묶음.** `1,000`은 천이지만 `0,100`(튜플)은 그대로. `1.27-alpine` 같은 버전 꼬리표는 소수로 읽지 않는다. `0/1`(라벨)은
  0 또는 1, 그 밖의 `a/b`는 b분의 a.
- **꺾쇠 안의 자리 표시.** `<값>`, `<unset>`은 안의 말만 읽는다. HTML 태그 이름(`li`, `div` …)만 태그로 읽는다. Java 다이아몬드
  `ArrayList<>()`는 읽지 않고, SQL `<>`는 같지 않다.
- **따옴표 안의 셸 인수.** `psql -c "… stock > 0"`처럼 큰따옴표 안의 `>`는 그 언어의 비교다. 리다이렉션이 아니다.
- **Markdown.** 목록 기호(`- `), 굵게(`**…**`), 일반 문장 앞의 인용 `> `는 읽지 않는다. `> 0으로`, `> 로`, `> 기호`,
  `> memo.txt`처럼 값·조사·파일이 바로 오면 기호를 읽는다. 읽어주기는 화면에 그려진 글을 읽으므로 인용 기호가 오지 않는다.
- **자연 문장부호.** `KPC!`, `Unnamed: 0`, `5;는`, `md:가`, `(나이, 요금)`의 기호는 읽지 않는다. 괄호·콜론·세미콜론·따옴표·
  백틱은 그 기호 하나가 코드 전체이거나 홀로 쓰였을 때만 이름으로 읽는다.
- **겹쳐 읽지 않기.** 문장이 이미 기호 이름을 말하면(`화살표(->)`, `세미콜론 ;`, `등호 하나(=)`) 기호를 다시 읽지 않는다.
- **Vim 명령.** 단어 첫머리의 콜론 뒤 `w`·`q`·`wq`(끝의 `!` 포함)는 낱자 이름으로 읽는다(`:wq` → 콜론 더블유큐, `:q!` → 콜론 큐 느낌표).
  그대로 두면 음성이 wq를 더벨유큐로 읽었다(2026-10-28 사용자 제보). 맨 `wq`, `a[:w]`, `x:q`, URL 안의 콜론은 바꾸지 않는다.
- **URL.** URL은 쓴 그대로 보낸다. 호스트와 포트 사이 콜론(`localhost:8080`)은 읽는다.
- **엔티티와 이스케이프.** 본문의 `&gt;`·`&amp;gt;`(두 번 이스케이프)는 기호로 풀고, Markdown 이스케이프(`\>`)의 역슬래시는
  빼며, Windows 경로(`C:\work`)는 그대로 둔다. 코드 안의 엔티티는 HTML을 가르치는 글자이므로 풀지 않는다.
- **범위.** `0~100`의 물결은 음성에 맡긴다.
- **멱등.** 변환한 글을 다시 넣어도 바뀌지 않게 만든다. 코드 조각은 따로 변환하고, 그 둘레 문장은 코드 자리에 자리표시자를 둔
  한 덩어리로 변환한다(「(`X`)는」의 닫는 괄호가 코드 옆이라는 것을 안다). 따옴표는 조각마다 뺀다. 공개 수업의 음성 대상 줄 전부(약
  17,000줄)를 두 번 변환해 같은지 `assets/speech/pronunciation-review.test.mjs`가 매번 확인한다. 예외는 한 줄뿐이고
  `docs/speech-pronunciation-review.json`의 `idempotency_exceptions`에 이유와 함께 있다: 두 코드 조각 사이의 띄운 `/`(또는)는
  읽지 않지만, 백틱이 빠진 출력 `a] / b`는 나누기로 읽힌다. 평문에는 그 차이를 남길 수 없다. 앱의 경로(`agent.js`,
  `voice.js`, `speech.js`)는 원문을 한 번만 변환하지만, 멱등은 그 사실에 기대지 않고 위 검사로 확인한다.

## 수업 전체 점검 (`tools/speech-audit.mjs`)

공개 수업(번들 코스 세 개가 가리키는 수업과 내장 코스 네 개; 추적되지 않은 초안은 제외)의 음성 대상 글에서 명령, 하위 명령, 옵션,
파일 이름, 확장자, 경로, 클래스 이름, 약어를 모두 뽑아 문맥과 함께 `docs/speech-pronunciation-review.json`에 둔다. 항목마다
결정이 있다: `lexicon`(규칙·사전이 바꿈), `as-written`(검토했고 음성이 쓴 그대로 읽음, 이유를 `note`에), `unresolved`(정할 일,
무엇을 정할지 `note`에). 검사가 실패하는 경우와 할 일:

- 새 수업에 새 항목이 생기면 → `node tools/speech-audit.mjs --write`로 `unreviewed`로 넣고 결정과 이유를 손으로 적는다.
- 규칙이나 사전을 고쳐 검토한 문장의 음성 글이 바뀌면 → 검사가 차이를 보여 준다. 확인한 뒤 `node tools/speech-audit.mjs --accept`.

음성이 실제로 어떻게 읽는지는 듣지 못했고, 선택된 음성(SunHi)으로 합성해 길이를 비교해 가늠했다(`.scratch/speech-command-audit/spec.md`).
대문자 약어(FN, MSE, BCNF …)는 알파벳 이름으로 읽혀 사전에 넣지 않았고, 대문자 SQL 단어 중 ROLLBACK·HAVING·EXISTS 등 14개는 한
글자씩 읽혀 사전에 넣었다. CamelCase 클래스 이름은 낱말로 읽힌다. 옵션의 `-`는 소리 나지 않는다(`-m` ≈ `m`).

### 정하지 않은 것

- 옵션의 대시를 말할지(마이너스/대시/하이픈), 지금은 쓴 그대로라 `-m`이 m으로 들린다.
- 일반 문장의 `Main`(「Main 안의 다른 위치」)은 그대로라 마인으로 들릴 수 있다. 클래스 문맥이 글에 없다.
- FIFO(피포?), XOR(엑스오어?), ReLU(렐루?), SemVer(셈버?)의 읽는 말. `PostgreSQL18`처럼 붙은 버전.
- 표의 날짜 `1/13`과 「열 week 1/2」은 분수로 읽힌다. 글에 날짜·선택 문맥이 없다.

## 캐시와 확인

- Edge 음성 캐시(`tts-cache`)의 키는 (음성, 변환한 문장)이다. 규칙이 바뀌면 문장이 바뀌므로 새 MP3를 받고, 예전 MP3는 쓰이지
  않는다. 해설 대본(`narration_cache`)은 원문이라 다시 만들 필요가 없다.
- `node --test assets/speech/`는 변환한 문장을 검사한다. 소리가 실제로 어떻게 나는지는 합성해서 들어 봐야 하며, 이 검사로
  대신하지 않는다.
