# 음성 발음 변환: 사전과 기호 문맥

음성으로 보내는 문장만 바꾼다. 화면 글, 자막, 코드, 정답, 터미널 입력, 강조 위치는 원문 그대로다. 구현과 사전은
`assets/speech/pronunciation.js` 하나이고, 기기 음성(Web Speech)과 Edge 신경망 음성(`assets/layout/voice.js` → `src/tts.rs`),
해설 모드(`assets/layout/agent.js`), 본문 읽어주기(`assets/speech/speech.js`)가 모두 `molipPronunciation.pronunciationText`를 부른다.
말투 규칙은 `docs/voice.md`에 있다.

## 사전 (`LEXICON`)

단어를 어떻게 읽는지는 `LEXICON` 배열이 유일한 근거다. 묶음마다 `scope`(적용 범위), `rationale`(이렇게 읽는 이유),
`evidence`(수업에서의 근거·빈도), 항목마다 `[원문, 읽는 말, 예]`가 있다. 이 문서는 사전을 옮겨 적지 않는다.

| scope | 적용 |
| --- | --- |
| `term` | 본문의 기존 수업 용어. 더 긴 영문 단어나 하이픈 이름(`py-2`) 안에서는 바꾸지 않는다. |
| `strict` | 본문의 약어·제품명. 경로, URL, 옵션, 식별자, 환경 변수(`$JAVA_HOME`), 파일 이름(`nginx.conf`) 안에서는 바꾸지 않는다. |
| `command` | `strict`에 더해, 코드 안에서는 명령 자리(줄 처음, `|` `;` `&&` `$` `sudo` 뒤)이거나 코드 전체가 그 단어일 때만. |
| `after:<명령>` | 그 명령 바로 뒤의 하위 명령만(`git commit`의 `commit`). 인수(`git add status`의 `status`)는 그대로. |
| `brand` | Git, GitHub. 대소문자 무관. |

읽는 말은 한국 개발자가 실제로 말하는 형태를 쓴다. 약어는 알파벳 이름으로 읽어 원래 철자를 알아볼 수 있게 하고(`mkdir` →
엠케이디아이알, `JDBC` → 제이디비씨), 뜻으로 바꾸거나 철자와 뜻을 길게 겹쳐 말하지 않는다. 항목을 더할 때는 예를 넣고
`assets/speech/symbols-lexicon.test.mjs`에 한 줄 검사를 더한다. 같은 원문이 두 번 들어가면 검사가 실패한다.

바꾼 단어 뒤의 조사는 읽는 말에 맞춘다(`:는` → 콜론은, `rm로` → 알엠으로). 단어 끝에 붙은 조사만 바꾼다.

## 기호

기호는 문맥에 따라 세 가지로 읽는다. 바뀐 말 뒤에 조사가 붙어 있으면 붙여 둔다.

| 문맥 | 예 | 읽는 말 |
| --- | --- | --- |
| 두 값 사이(식) | `a >= b`, `x != y`, `total += price` | a 크거나 같다 b, x 같지 않다 y, total 플러스 이퀄 price |
| 기호 자체를 말함 | `>는`, `` `>=` ``, `답은 |.`, `==예요` | 크다 기호는, 크거나 같다 기호, 답은 파이프, 등호 두 개예요 |
| 앞에 붙는 기호 | `!done`, `*p`, `&stock`, `-1`, `:2` | 낫 done, 별표 p, 앰퍼샌드 stock, 마이너스 1, 콜론 2 |
| 뒤에 붙는 기호 | `i++`, `HEAD^`, `b%` | i 플러스 플러스, HEAD 캐럿, b 퍼센트 |

긴 기호를 먼저 읽는다(`!==` → `!=` → `!`). 한 번 바꾼 말은 다시 바꾸지 않는다.

### 구별 규칙과 한계

- **비교와 Bash 리다이렉션.** `>`·`>>`·`<`는 셸 명령으로 시작하는 코드(`echo`, `cat`, `ls`, `git`, `docker` …)에서, 뒤가 파일
  경로(`memo.txt`, `../inbox/a.txt`, `.practice`, `/dev/null`)일 때, 또는 같은 문장이 파일 쓰기를 말할 때(파일·덮어·덧붙·
  사본·끝에 붙…) 꺾쇠로 읽는다. 그 밖에는 비교다. 파일 이야기를 하는 문장 안의 단독 비교 기호는 꺾쇠로 읽힐 수 있다.
- **제네릭·HTML과 비교.** `List<String>`처럼 이름에 붙고 대문자 타입이 들어간 꺾쇠는 읽지 않는다(List String).
  소문자 태그 `<li>`·`</li>`는 li 태그, 닫는 li 태그. `i<n`처럼 소문자 변수 사이는 비교다.
- **파이프와 논리.** `|`는 파이프, `||`는 식에서 오어, 기호 자체는 파이프 두 개. `&&`는 앤드 / 앰퍼샌드 두 개.
- **퍼센트와 나머지.** 숫자 뒤 `%`는 퍼센트(38.20% 포함), 두 값 사이는 나머지, 기호 자체는 퍼센트 기호, `%d`·`%{…}`는 퍼센트.
- **경로와 나눗셈.** 붙어 있는 `/`는 경로라 읽지 않는다. 띄어 쓴 `/`는 코드나 숫자·괄호 옆에서만 나누기다
  (`훈련 / 테스트`는 그대로). `/29`(네트워크 접두사)는 슬래시 29. 숫자 `1/2`는 2분의 1.
- **빼기와 하이픈·옵션.** `-r`, `--base`, `no-error`는 그대로. 셸 코드의 `-1`(`head -1`)도 옵션이라 그대로.
- **Markdown.** 목록 기호(`- `), 굵게(`**…**`), 일반 문장 앞의 인용 `> `는 읽지 않는다. `> 0으로`, `> 로`, `> 기호`,
  `> memo.txt`처럼 값·조사·파일이 바로 오면 기호를 읽는다. 읽어주기는 화면에 그려진 글을 읽으므로 인용 기호가 오지 않는다.
- **자연 문장부호.** `KPC!`, `Unnamed: 0`, `5;는`, `md:가`, `(나이, 요금)`의 기호는 읽지 않는다. 괄호·콜론·세미콜론·따옴표·
  백틱은 그 기호 하나가 코드 전체이거나 홀로 쓰였을 때만 이름으로 읽는다.
- **겹쳐 읽지 않기.** 문장이 이미 기호 이름을 말하면(`화살표(->)`, `세미콜론 ;`, `등호 하나(=)`) 기호를 다시 읽지 않는다.
- **URL.** URL은 쓴 그대로 보낸다. 호스트와 포트 사이 콜론(`localhost:8080`)은 읽는다.
- **엔티티와 이스케이프.** 본문의 `&gt;`·`&amp;gt;`(두 번 이스케이프)는 기호로 풀고, Markdown 이스케이프(`\>`)의 역슬래시는
  빼며, Windows 경로(`C:\work`)는 그대로 둔다. 코드 안의 엔티티는 HTML을 가르치는 글자이므로 풀지 않는다.
- **범위.** `0~100`의 물결은 음성에 맡긴다.
- **멱등.** 같은 문장을 다시 넣어도 바뀌지 않는다. 다만 출력에서 코드의 백틱이 빠지므로, 출력을 다시 넣으면 코드 안 단어가
  본문 용어로 읽힐 수 있다. 앱의 어떤 경로도 변환을 두 번 하지 않는다.

## 캐시와 확인

- Edge 음성 캐시(`tts-cache`)의 키는 (음성, 변환한 문장)이다. 규칙이 바뀌면 문장이 바뀌므로 새 MP3를 받고, 예전 MP3는 쓰이지
  않는다. 해설 대본(`narration_cache`)은 원문이라 다시 만들 필요가 없다.
- `node --test assets/speech/`는 변환한 문장을 검사한다. 소리가 실제로 어떻게 나는지는 합성해서 들어 봐야 하며, 이 검사로
  대신하지 않는다.
