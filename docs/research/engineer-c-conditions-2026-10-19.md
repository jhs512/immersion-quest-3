# 정보처리기사 실기: C 연산과 조건 조사

확인일: 2026-10-19. 제작자용 조사이며 **다음 수업의 PRD·대표 문제는 아직 미승인**이다. 정식 콘텐츠·실행기·진도·게시물을 변경하지 않는다. 이미 승인된 C 첫 수업 여섯 스텝을 선수 범위로 삼는다. Java·AICE 수업 및 기록과 분리한다.

## 출처와 확인 범위

언어 근거는 WG14의 [N1570 공개 위원회 초안](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)만 사용한다. 표지는 **2011-04-12 Committee Draft**, C11 계열 초안이다. 이것이 정보처리기사의 지정 C 표준·컴파일러·실행 환경이라는 뜻은 아니다. 원문의 절·문단을 직접 읽었다. 아래 `page`는 PDF 뷰어의 1부터 시작하는 페이지 번호다.

시험 범위와 언어 의미를 혼동하지 않는다. 이미 확보한 [큐넷 2026 기준](https://www.q-net.or.kr/pageLink.do?link=cst/cstReport&jmCd=1320&mcrtrNo=991), [2027~2029 기준](https://www.q-net.or.kr/pageLink.do?link=cst/cstReport&jmCd=1320&mcrtrNo=1453)은 프로그래밍 언어 활용과 필답형을 다루지만 N1570 또는 특정 C 버전·컴파일러를 지정하지 않는다. 이 시험 자료의 직접 확인일은 2026-10-16이며 보존본은 `.scratch/certification-research/sources/qnet-991.pdf`, `qnet-1453.pdf`다. 오늘 공식 시험 환경을 새로 검증했다는 의미는 아니다.

## 언어 규칙: 직접 확인

| 주제 | 확인한 의미 | 정확한 원문 위치 |
| --- | --- | --- |
| 작은 정수 연산 | `+`, `-`, `*`는 합·차·곱이다. 이항 정수 `/`는 소수 부분을 버려 0 쪽으로 절단한다. `%`는 나머지이며 정수 피연산자에 쓴다. | [6.5.5 ¶2~6, 6.5.6 ¶4~6](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=110) |
| 몫·나머지의 연결 | 몫이 표현 가능할 때 `(a / b) * b + a % b`는 `a`다. `/`와 `%`의 두 번째 피연산자 0은 정의되지 않은 동작이다. | [6.5.5 ¶5~6 및 주105](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=110) |
| 관계·동등 비교 | `<`, `>`, `<=`, `>=`, `==`, `!=`는 참이면 `int` 1, 거짓이면 `int` 0이다. | [6.5.8 ¶6, 6.5.9 ¶3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=114) |
| 조건 분기 | `if` 조건이 0이 아니면 첫 문장, 0이면 `else` 문장이 실행된다. 참은 반드시 숫자 1일 필요가 없다. | [6.8.4.1 ¶1~2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=166) |
| 대입과 비교 | `=`는 저장값을 바꾸고 대입식 자체도 저장 후 값을 갖는다. `==`는 같은지 비교한다. | [6.5.16 ¶3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=119), [6.5.16.1 ¶2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=120), [6.5.9 ¶3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=114) |

비교의 결과가 0/1이라는 규칙과, `if`가 임의의 비영 값을 참으로 취급한다는 규칙을 구별해야 한다. 재고 2는 비교식의 결과가 아니어도 `if (stock)`의 조건으로 참이다. 음수 나눗셈·혼합 자료형은 이번 제안에서 제외하므로 ‘내림’이라는 부정확한 일반화를 사용하지 않는다.

## 안전한 숫자와 경계 사례

다음 표는 위 규칙에서 도출한 **자체 설계 검토값**이다. 실제 컴파일·실행 검증은 아직 하지 않았다. 제작 승인 후 실제 결과와 맞춰야 한다. 모든 변수는 먼저 초기화한 `int`이며 재고는 0~20, 묶음 크기는 상수 3으로 제한한다.

| 목적 | 입력·표현식 | 예상 결과·관찰 |
| --- | --- | --- |
| 묶음 경계 전·동일·후 | `stock` 5, 6, 7에서 `stock / 3` | 1, 2, 2묶음 |
| 남은 낱개 | 같은 입력에서 `stock % 3` | 2, 0, 1개 |
| 0 재고 | `0 / 3`, `0 % 3` | 각각 0. 분모가 0인 경우와 다르다. |
| 비교 경계 | 재고 2, 3, 4에서 `stock >= 3` | 0, 1, 1 |
| 잘못 고른 경계 연산자 | 같은 입력에서 `stock > 3` | 0, 0, 1. 재고가 정확히 3일 때 차이가 난다. |
| 같음·다름 | 재고 0, 2에서 `stock == 0`, `stock != 0` | 각각 (1, 0), (0, 1) |
| 분기 판정 | 재고 0, 2에서 `if (stock)` | 각각 `else`, 첫 분기. 숫자 2도 참이다. |
| 작은 계산의 묶임 | 재고 7에서 `stock + 2 * 3`와 `(stock + 2) * 3` | 13과 27. 묶임 설명을 피연산자 실행 순서 주장으로 넓히지 않는다. |

마지막 행의 묶임 근거는 [6.5 ¶3 및 6.5.5~6.5.6 문법](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=94)이다. 전체 수치를 30 이하로 다듬고 모든 값·중간 결과가 `int` 최소 보장 범위 안에 있도록 한다. 정수 최소 범위의 근거는 [5.2.4.2.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=45)이다.

## 초보 오해와 피할 함정

- ‘정수 나눗셈 결과가 2.33’이라는 오해에는 완성한 묶음과 낱개를 같은 수량 그림으로 비교한다.
- ‘`%`는 퍼센트’라는 오해에는 몫과 남은 개수의 합성 관계를 확인한다.
- ‘비교가 원래 재고를 바꾼다’는 오해에는 비교 출력 전후 저장값을 나란히 확인한다.
- ‘참은 1뿐’이라는 오해에는 0과 2를 조건으로 대조한다. 음수까지 늘리지 않는다.
- ‘`>`와 `>=`는 대충 같다’는 오해에는 경계값 3을 반드시 포함한다. 경계에서 떨어진 입력만으로 검사하지 않는다.
- `if (stock = 0)`은 ‘문법 오류’라고 가르치지 않는다. 초안상 유효한 대입식이므로 재고를 0으로 바꾸고 거짓 분기로 간다. 필요하면 **미리 제공한 오류를 한 글자 고치는 진단 예시**로만 다루고, 조건 안 대입을 정답 작성 습관으로 만들지 않는다. 본 제안 여덟 스텝의 필수 새 개념으로 추가하지 않는다.

피연산자에 `++`·`--`·함수 호출을 넣거나, 읽기·대입을 한 식에서 섞지 않는다. 부호 혼합, 미초기화 값, 정수 넘침, 0으로 나눔, 연쇄 비교, 중첩 `if`의 `else` 결합, 비트 연산은 범위 밖이다. 문법·참거짓·상태 변화의 핵심을 평가 순서 퍼즐로 대체하지 않는다. 원문 안전 경계는 [6.5 ¶2~5](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=94)다.

## 절제한 여덟 스텝 제안: 같은 재고 상황

다음은 PRD 작성에 참고할 **미승인 구성안**이다. 정식 문제·정답·해설 원고가 아니다. 상황은 앞 수업의 매장 재고 표시를 이어 쓰며 모든 스텝에 완성된 프로그램 틀을 제공한다. 각 스텝은 별도 초기 상태로 시작한다.

| 순서 | 추가하는 관계 한 가지 | 권장 수행 |
| --- | --- | --- |
| 1 | 재고 7개를 3개씩 포장한 몫 | `/` 결과를 짧게 직접 답하고 실행 확인 |
| 2 | 같은 포장 뒤 남은 낱개 | `%` 결과를 답하고 두 값을 연결 |
| 3 | 3개 이상인지 비교한 값 | `>=` 결과를 0/1로 판단. 저장값 유지 관찰 |
| 4 | 비교 결과에 따라 한 문장만 실행 | 준비된 단일 `if`에서 출력·실행 여부 추적 |
| 5 | 조건이 거짓일 때의 다른 출력 | 같은 코드에 `else`만 추가해 한 분기 선택 |
| 6 | 정확히 3개도 포장 가능한 경계 | 제공된 `>`를 `>=`로 한 곳 수정하고 2/3/4 대조 |
| 7 | 재고 자체의 0·비영 조건 | `if (stock)`의 재고 0/2를 비교. 새 연산자 없음 |
| 8 | 몫과 나머지·한 조건을 함께 읽기 | 재고 7에서 묶음 2·낱개 1을 구한 뒤 낱개가 0인지에 따른 출력 추적 |

8번을 도전 성격으로 삼되 힌트는 필요할 때만 펼친다. 보일러플레이트나 긴 코드 작성으로 난이도를 올리지 않는다. 실제 필답으로 연결하려면 직접 결과를 제출하는 수행을 포함하되 시간·실행 금지 모드를 새로 강제하지 않는다. 복습모드 제공 여부는 다음 PRD에서 별도 결정한다.

## 승인 전후 구분과 남은 검증

이 조사는 언어 의미와 안전한 예시의 근거를 제공한다. 수업·챕터·단원·스텝 교육 목표, 상세 핵심 흐름, 대표 문제와 성공 판정은 다음 수업 PRD의 승인 대상이다. 코드·문항 제작, 음성 해설 재생성, 앱 실행 검증, 리포지터리 게시를 수행하지 않았다. 승인 후에는 실제 C 실행으로 모든 예상값과 경계 검사를 확인하고, 선택지·예상 출력·해설이 같은 규칙을 설명하는지 검증해야 한다.
