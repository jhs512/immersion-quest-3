# Floci and infrastructure foundations: planning evidence

Research date: 2026-11-09. Audience: graduates of Java and Bash, adding infrastructure practice to the existing Java backend course. At least 30 genuinely new lessons are required after excluding the existing eight; final deduplication is owned by the planning map. Planning input only; no lessons, Docker instances, or environment changes were created. Proposed ordering below is a pedagogical judgment, not an upstream guarantee. Runtime checks remain outstanding.

## Identity and version boundary

“Floci local AWS emulator” means the AWS project maintained at [floci-io/floci](https://github.com/floci-io/floci), not its Azure/GCP/OCI siblings. Its documented AWS endpoint is `http://localhost:4566`; it requires neither an AWS account nor a Floci auth token. Its source license is MIT. This makes a local-only course possible without AWS billing, subject to the separate licensing of the chosen container runtime and downloaded images. [Pinned README](https://github.com/floci-io/floci/blob/2.4.0/README.md), [MIT license](https://github.com/floci-io/floci/blob/2.4.0/LICENSE), [Docker Desktop terms](https://docs.docker.com/subscription-billing/desktop-license/).

All implementation findings below use 2.4.0, not main; this avoids silently combining capabilities from different releases. ## Preventing accidental AWS requests

The AWS CLI normally chooses real service endpoints if none is overridden; explicit `--endpoint-url` overrides endpoint configuration. Consequently, dummy credentials alone do not prevent real-network requests. [AWS CLI endpoint precedence](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-endpoints.html).

Proposed course harness, subject to implementation review:

- Every executable AWS operation goes through a wrapper that accepts only `http://127.0.0.1:4566` on the host or the declared `http://floci:4566` Compose service; it always injects `--endpoint-url` and a fixed region `us-east-1`.
- Supply task-process dummy `AWS_ACCESS_KEY_ID=test`, `AWS_SECRET_ACCESS_KEY=test`, `AWS_DEFAULT_REGION=us-east-1`, `AWS_ENDPOINT_URL=http://127.0.0.1:4566`, and `AWS_EC2_METADATA_DISABLED=true`; clear inherited session tokens, profiles and conflicting service endpoint overrides. Never reuse the learner's real AWS profile. IAM labs replace only dummy identities with credentials issued by this local emulator. [Floci credentials/account behavior](https://github.com/floci-io/floci/blob/2.4.0/README.md#multi-account-isolation), [AWS CLI endpoint behavior](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-endpoints.html).
- Require a disposable client environment with egress restricted to the lab network for a **guarantee** against hitting AWS; endpoint assertions and dummy credentials alone are not a network sandbox. Prefetch pinned images/providers before isolation. Verify this on the chosen Windows/WSL/Docker runtime; no firewall changes were made in this research.
- Terraform must configure every used service endpoint explicitly, along with dummy credentials and metadata/credential-validation skips. Reject an unconfigured resource/service before running its plan. The upstream fixture is a useful starting point, not proof that an arbitrary future resource is routed locally. [Pinned provider fixture](https://github.com/floci-io/floci/blob/2.4.0/compatibility-tests/compat-terraform/provider.tf).
- Do not rely on transparent AWS DNS spoofing as the safety boundary: it defaults false; spawned-container fallback DNS defaults enabled with public resolvers. Avoid global machine environment changes and host DNS edits. [DNS configuration](https://github.com/floci-io/floci/blob/2.4.0/src/main/resources/application.yml).

## Proposed sequence: 41 tiny lab candidates

Each row is a **planning candidate**, adding one resource or relationship. Every eventual lesson should have: known starting state → one change → direct observation → deliberate failure → smallest fix → the same observation again. A failure must make one causal distinction visible, not introduce a second hidden prerequisite. Rows are ordered by estimated learning return per setup/debug cost, retaining prerequisites. This is a new candidate inventory; comparison against existing lessons belongs to the parent planning map.

Rows 1–13 use actual local Docker/networking, independent of Floci. User-defined Docker bridges provide name resolution; published ports expose a different host-facing path; volumes outlive containers. Docker Desktop runs the engine inside a VM, so use container clients for private-network checks. These facts underpin the proposed experiments. [Bridge/DNS](https://docs.docker.com/engine/network/drivers/bridge/), [Desktop networking](https://docs.docker.com/desktop/features/networking/), [volumes](https://docs.docker.com/engine/storage/volumes/).

## Decisions and acceptance work still needed

Human decisions remaining after the confirmed Java/Bash-graduate audience and existing Java-backend-course placement: Windows PowerShell vs WSL execution surface; provided Docker runtime vs installation work; whether own-local-DNS and real Floci EC2 networking belong in required or optional path; whether IAM enforcement is required; number and duration of sessions; resource budget/concurrent learners; quiz vs executable evidence expectations; and final lesson identity/deduplication against the eight existing lessons. The suggested 41 rows do not settle those choices.

Runtime acceptance, intentionally **not executed** in this research: pull the pinned digest on target architectures; measure cold/warm cost; validate Docker socket on Windows; prove host/client/container endpoint rules; test S3/SQS/DynamoDB happy/fail/fix observations; exercise local IAM allow/deny; test persistence and reset including child artifacts; verify every Terraform service endpoint; enforce egress isolation; inspect UDP DNS answers from actual clients; and check actual cross-VPC/SG packets on the selected daemon before claiming isolation. Source/test existence narrows the investigation but does not replace these runs.

Do not make beginner completion depend on EKS, databases, NAT/IGW routing, TLS interception, service meshes or multi-service application deployment. This is a scope recommendation based on their additional prerequisites, not a claim that Floci lacks those services. Keep each lesson's state/evidence understandable before adding another relationship.
