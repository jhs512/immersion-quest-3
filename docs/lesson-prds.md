# 수업 PRD 제작과 승인

공통 콘텐츠 정책은 `docs/content-rules.md`, 용어는 `CONTEXT.md`가 원본이다. 수업별 제작자는 관련 정책을 종합한 수업 PRD와 대표 문제 초안을 먼저 제시한다. 이 문서는 정책을 다시 정의하지 않고 제작·검사 절차만 설명한다.

## 하나의 제작 기준서

`policy_snapshot.artifacts`에는 적용 당시 정책 파일의 경로와 원문을 함께 보존한다. 버전은 이 배열의 순서를 유지하고 원문의 CRLF·CR을 LF로 바꾼 다음, 키 정렬·공백 없는 UTF-8 JSON(`ensure_ascii=False`, `sort_keys=True`, `separators=(',', ':')`)의 SHA-256으로 계산한다. `tools/lesson_prd.py`의 `policy_revision`이 이 절차를 정의한다. 최신 정책과 같아야 하는 검사가 아니라 보관한 당시 원문의 무결성 검사다. 적용 규칙은 PRD에 별도로 종합해 둔다.

대표 문제의 실행 가능한 입력과 기대 상태는 `representative.execution_spec`에 둔다. 검증 도구는 그 값을 읽고 결과에 PRD 내용 해시를 기록한다. 따라서 다른 PRD를 검증한 결과를 현재 초안의 증거로 취급하지 않는다.

수업 PRD에는 수업 제목·목표·대상·선수 지식·범위·제외 범위, 조사 결과·출처·확인 시점·불확실성, 적용 정책의 버전과 실제 적용 규칙, 챕터·단원·스텝별 목표와 상세 핵심 흐름, 채점·초기화·해설·검증 기준, 대표 문제를 담는다. 교육 전략은 필요할 때만 추가한다.

이 내용은 PRD 안에 종합한다. 제작 중 정책 링크를 따라가 매번 새로 해석하게 하지 않는다. 출처 링크는 근거 재확인과 갱신을 위해 남긴다. 공통 정책이 바뀌면 PRD의 적용 버전과 전후 차이를 검토하고, 관련이 없으면 검토한 사실만 갱신한다. 관련 콘텐츠 변경 전파는 인접 검토 규칙을 따른다.

## 초안과 정식 제작의 구분

기계 판독 원본은 JSON이고, 사람이 검토하는 Markdown은 같은 원본에서 만든다. Markdown만 따로 수정해 서로 다른 두 기준서를 만들지 않는다. 핵심 흐름은 내부 제작 자료이므로 이 검토 문서를 학생 문제 본문으로 자동 배포하지 않는다.

```powershell
python tools/lesson_prd.py check tests/fixtures/lesson-prd/git-first.json
python tools/lesson_prd.py render tests/fixtures/lesson-prd/git-first.json --output target/lesson-prd-preview.md
```

기본 검사는 초안의 형식·필수 목표·고유 코드·대표 문제 연결을 확인한다. 수업의 교육 품질이나 출처의 사실 여부를 자동으로 입증하지 않는다. 대표 문제를 실제 수행해 보고 목표·흐름·짧은 설명과 함께 검토한다.

```powershell
python tools/verify-prd-git-example.py
python tools/lesson_prd.py check tests/fixtures/lesson-prd/git-first.json --require-approval
```

마지막 명령은 초안에서 실패해야 정상이다. 정식 제작 경로는 승인 검사를 거쳐야 하며, `draft`를 임의로 `approved`로 고쳐 통과시키지 않는다. 승인자와 근거, 검토된 내용 해시가 필요하다. 코드의 승인 함수는 신뢰할 수 있는 사용자 승인을 기록하는 수단일 뿐 승인을 대신하지 않는다.

승인된 교육 목표·기법이 바뀌면 초안으로 되돌려 다시 검토받는다. 허용된 오탈자·명백한 오류 수정은 기존 승인 범위 안에서 처리하고 변경 이력과 검토 근거를 남긴다. 검사기가 승인 후 변경을 발견하면 무조건 새 사용자 결정을 요구한다는 뜻이 아니라, 변경 범위를 확인하지 않은 채 정식 제작으로 넘기지 않는다는 뜻이다.

## 현재 검토 예제

Git 첫 수업 예제는 두 단원·여섯 스텝과 대표 문제 하나를 담은 초안이다. 실제 임시 Git 저장소에서 대표 상태 전이를 확인했지만 전체 수업 구현·해설·운영체제별 터미널 검증은 아직 아니다. 이 예제의 존재를 수업 제작 승인이나 전체 과정 완성으로 보고하지 않는다.
