# 인접 변경 검토 도구

`tools/content_review.py`는 제작 자료의 변경 전후와 바로 다음 레이어의 원문을 비교하는 공통 기반이다. 라이브러리와 로컬 제작 명령을 제공하며 정식 수업을 게시하거나 승인하지 않는다.

`Artifact`는 고유 코드·레이어·LF로 정규화한 원문과 내용 해시를 구분한다. `ReviewLedger`는 SQLite에 변경 전후 원문·해시, 검토 대상 원문·해시, 검토기와 지침 버전, 시각, 판단과 이유를 저장한다. 동일한 입력과 검토기 버전의 성공한 판단만 재사용한다. 실패하거나 형식이 모호한 응답은 실패 이력으로 남기며 영향 없음으로 취급하지 않는다.

`ContentTree.apply`는 직접 연결된 자료만 검토한다. 변경 불필요면 자료를 유지하고 그 아래로 내려가지 않는다. 변경 필요면 실제로 다른 결과가 생성된 뒤 그 자료의 변경 전후를 다음 인접 검토에 전달한다. 출처가 불명확한 기존 자료를 등록했다는 이유만으로 현재 원문에서 생성됐다고 표시하지 않는다. 생성 근거와 새 원문을 검토한 근거는 별도로 조회한다.

검토·생성 실패 시 그 경로는 미완료로 남고 `resume`으로 재시도한다. 다른 원본 개정은 앞의 미완료 작업이 끝난 뒤 시작한다. 검토 함수는 요청의 복사본을 받는다.

```powershell
python tools/test_content_review.py
```

현재 검사는 고정 플레이어 fixture와 별도 원문으로 무변경 중단, 인접 차이 전달, 실패·모호한 응답의 재시도, 검토 캐시 재열기를 다룬다. 별도 Python 프로세스에서 미완료 상태를 다시 열어 이미 저장한 생성 결과를 재사용하는지도 확인한다. 실제 외부 모델의 판단 정확성을 입증하는 검사는 아니다.

제작 명령의 모델·승인 경계는 아래와 같다. 플레이어 안에서 검토·제작을 조작하는 화면과 결과의 콘텐츠 빌드·게시 연결은 아직 없다. 이 기반만으로 티켓 06 완료나 실제 수업 개편 완료로 보고하지 않는다.


생성이 필요한 경우 `generator_key`에 생성 모델·지침·설정의 버전을 명시한다. 검토기와 생성기는 서로 다른 버전으로 관리한다. 생성 요청은 해당 source/target의 변경 필요 검토에 묶이며 실패와 성공을 별도 이력에 보관한다. 성공한 동일 요청은 실제 결과를 재사용하고, 과거 출력의 원문·내용 해시·검토 코드도 조회할 수 있다. `ContentTree.save(path)`는 원문·근거·미완료 연결을 해시가 붙은 JSON으로 원자 저장하고 이후 단계마다 다시 저장한다. `load(path)`는 해시·계층·미완료 연결을 확인한 뒤 같은 상태를 재개한다. 손상된 파일을 초기화하거나 성공한 척하지 않는다. 생성 결과는 먼저 SQLite에 기록하므로 파일 저장 전 중단돼도 다음 프로세스가 결과를 재사용한다.

하나의 트리 상태 파일에는 작성자 한 프로세스만 쓰는 순차 재개 방식이다. 여러 프로세스가 같은 파일을 동시에 수정하는 분산 작업 조율은 아직 제공하지 않는다.

## 모델과 로컬 제작 명령

`JsonReviewModel`은 로컬에서 명시한 명령을 셸 없이 실행한다. 표준 입력으로 변경 전후·대상 원문, 목소리 지침과 콘텐츠 룰 전체를 전달한다. 표준 출력은 검토의 경우 `{"change_required": false, "reason": "구체적인 근거"}`, 제작의 경우 `{"text": "대상 원문 전체"}` 형태의 JSON 하나여야 한다. 모호한 응답·비정상 종료·시간 초과는 미완료로 남는다. 모델의 표준 오류는 비밀 값이 섞일 수 있어 이력에 복사하지 않는다.

모델 설정 JSON에는 `command`(인수 배열), `model_revision`(고정한 실제 모델·설정 버전)을 둔다. Claude CLI를 연결한다면 `--print --output-format text --tools "" --safe-mode --disable-slash-commands --no-session-persistence --strict-mcp-config --mcp-config '{"mcpServers":{}}'`와 명시적인 `--model`을 사용한다. 도구 실행 권한을 주지 않고 JSON 응답만 받는다. 모델 별칭이 가리키는 버전이 바뀌면 `model_revision`도 갱신한다. 설정은 신뢰할 수 있는 제작자 로컬 파일이며 내려받은 수업에서 실행 명령을 받지 않는다.

생성이 필요한 경우 설정에 `prd`(설정 파일 기준 JSON 경로), `target_steps`(자료 키→PRD의 스텝 코드)를 추가한다. 승인 해시가 유효한 PRD이고 해당 스텝에 연결된 자료만 생성한다. 목표 원문은 승인된 스텝의 목표 항목을 LF로 연결한 값과 같아야 한다. 목표가 달라지면 새 PRD 승인부터 필요하다. 이 어댑터는 핵심 흐름·학습 콘텐츠·자료 설명문·해설 텍스트만 생성한다. 정책·PRD·목표 승인이나 실제 이미지·음성 파일 생성은 맡지 않는다.

명령·모델 버전·전체 지침·PRD·스텝 연결을 캐시 식별에 포함한다. 검토는 현재 공통 지침을 읽지만, 생성은 승인된 PRD 안의 목소리·콘텐츠 정책 원문을 기준으로 한다. 공통 철학 파일이 바뀌어도 새 철학을 수업에 몰래 적용하지 않는다. 정책→PRD 인접 검토와 필요한 승인·검토 버전 기록을 마치기 전에는 기존 승인 기준을 유지한다. 모델의 의미 판단은 자동 승인이나 교육 품질 검증을 대신하지 않는다. 형식이 맞더라도 범위·정체성·설명 품질 검토와 수업 빌드가 별도로 필요하다.

```powershell
python tools/content_review_command.py apply --state tree.json --ledger review.db --model-config model.json --replacement changed-artifact.json
python tools/content_review_command.py resume --state tree.json --ledger review.db --model-config model.json
python tools/content_review_command.py history --ledger review.db --target artifact-key
```

트리 파일은 `ContentTree.save`로 등록한다. 변경 입력은 `key`, `layer`, `text` 세 필드만 갖는다. 명령은 로컬 트리와 검토 이력만 갱신하고 원래 수업 파일·답안·진도·승인 상태를 쓰지 않는다. 실패 후 PRD 승인을 받았다면 승인 기록을 모델 설정의 PRD 파일에 반영한 뒤 `resume`한다. 명령 자체에는 승인 기능이 없다.
