# 인접 변경 검토 도구

`tools/content_review.py`는 제작 자료의 변경 전후와 바로 다음 레이어의 원문을 비교하는 공통 기반이다. 현재는 주입된 검토 함수와 생성 함수를 쓰는 라이브러리이며 정식 수업을 게시하거나 승인하지 않는다.

`Artifact`는 고유 코드·레이어·LF로 정규화한 원문과 내용 해시를 구분한다. `ReviewLedger`는 SQLite에 변경 전후 원문·해시, 검토 대상 원문·해시, 검토기와 지침 버전, 시각, 판단과 이유를 저장한다. 동일한 입력과 검토기 버전의 성공한 판단만 재사용한다. 실패하거나 형식이 모호한 응답은 실패 이력으로 남기며 영향 없음으로 취급하지 않는다.

`ContentTree.apply`는 직접 연결된 자료만 검토한다. 변경 불필요면 자료를 유지하고 그 아래로 내려가지 않는다. 변경 필요면 실제로 다른 결과가 생성된 뒤 그 자료의 변경 전후를 다음 인접 검토에 전달한다. 출처가 불명확한 기존 자료를 등록했다는 이유만으로 현재 원문에서 생성됐다고 표시하지 않는다. 생성 근거와 새 원문을 검토한 근거는 별도로 조회한다.

검토·생성 실패 시 그 경로는 미완료로 남고 `resume`으로 재시도한다. 다른 원본 개정은 앞의 미완료 작업이 끝난 뒤 시작한다. 검토 함수는 요청의 복사본을 받는다.

```powershell
python tools/test_content_review.py
```

현재 검사는 고정 플레이어 fixture와 별도 원문으로 무변경 중단, 인접 차이 전달, 실패·모호한 응답의 재시도, 검토 캐시 재열기를 다룬다. 실제 외부 모델의 판단 정확성을 입증하는 검사는 아니다.

아직 미구현인 부분은 트리·미완료 생성 작업의 프로세스 간 재개, 실제 모델 어댑터·제작 명령, 승인된 PRD와 정식 제작 경계 연결이다. 이 기반만으로 티켓 06 완료나 실제 수업 개편 완료로 보고하지 않는다.


생성이 필요한 경우 `generator_key`에 생성 모델·지침·설정의 버전을 명시한다. 검토기와 생성기는 서로 다른 버전으로 관리한다. 생성 요청은 해당 source/target의 변경 필요 검토에 묶이며 실패와 성공을 별도 이력에 보관한다. 성공한 동일 요청은 실제 결과를 재사용하고, 과거 출력의 원문·내용 해시·검토 코드도 조회할 수 있다. 트리의 영구 재개는 아직 별도 구현 대상이다.
