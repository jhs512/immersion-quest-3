# Floci를 활용한 MQ 클라우드 실습의 적용 경로

Labels: wayfinder:map

## Destination

Floci를 MQ 수업에 적용할 수 있는 학습 목표, 실제 검증 범위, 기존 실습·채점기와의 결합 방식을 근거와 함께 정한다. 이번 지도는 적용 방안을 결정하는 단계이며 수업 구현이나 운영 배포를 포함하지 않는다.

## Notes

- 사용자가 Wayfinder 스킬을 명시적으로 요청했다.
- 사용자와의 음성 대화 및 실제 실험 후, 기존 네트워크 실습을 유지하며 후속 클라우드 인프라는 VPC·서브넷·EC2 구성·수명주기부터 시작하고 S3로 이어가기로 했다. S3 다음은 미결이며 SQS를 후보로 제안했다. Mac 동일 동작은 계획상 가정이며 Mac 실행 검증은 아니다.
- 기존 사용자 작업 브랜치와 미커밋 변경은 보존한다. 구현 분석은 최신 로컬 origin/main을 기준으로 하며 현재 작업 브랜치의 오래된 상태와 구분한다.
- skills: wayfinder, grilling, domain-modeling, research.
- 최신 MQ AGENTS의 Claude 기본 실행 규칙을 연구 에이전트에 전달했다. 별도 브리지 도구는 사용자가 앞서 제거한 상태이므로 재설치하지 않으며, 사용 가능한 Claude Code CLI로 연구 자료 작성·검토를 진행하고 요청 실패 여부는 별도로 기록한다.
- 공식 문서·소스에 근거한 지원과 실제 실행 검증을 구분한다. AWS 계정, 실제 클라우드 리소스, 과금 작업을 사용하지 않는다.
- 이 지도의 이슈와 연구 자료는 계획·조사 산출물이다. 학생에게 제공되는 수업 원고가 아니다.
- 실행 범위 예외(사용자 요청 2026-11-09): VPC·서브넷·EC2·네트워크 동작을 충분히 로컬에서 실험한다. 기존 Docker 자원은 보존하고 실험 소유 자원만 정리한다. 실제 AWS, 클라우드 배포·과금, 수업 운영 반영은 계속 범위 밖이다. 이는 적용 판단을 위한 사실 검증이며 수업 구현 승인은 아니다.
- 추가 사용자 요청: S3·Lambda·데이터베이스도 실제로 충분히 실험하고 활용 범위와 수업 순서를 제안한다. 데이터베이스는 DynamoDB와 RDS PostgreSQL을 구분해 검증한다. Docker 자원 실행은 서비스 연구별로 순차 진행한다.
- 사용자 결정: 이 수업 묶음은 기존 자바 과정의 후속이며 이미 있는 네트워크·DB·JDBC 등의 수업 지식은 안다고 가정한다. 선수 범위를 되묻지 않고 실제 기존 수업 내용을 기준으로 이어간다.

## Decisions so far

- [Floci로 어떤 AWS 학습 목표를 실제로 검증할 수 있는가](issues/01-floci-supported-learning-boundary.md): 안정 버전의 공식 지원·제약과 미실측 범위를 정리했다. S3·SQS는 후보이며 네트워크·권한의 AWS 동등성은 별도 검증 대상이다.
- [MQ의 기존 실습과 채점기 어디에 Floci를 연결할 수 있는가](issues/02-mq-runtime-and-grading-fit.md): 자원 관리와 상태 채점 원칙은 재사용 후보지만 이미지·SDK·서비스 관찰 계약은 새 검토가 필요하다.
- [첫 적용은 네트워크 보강인가 후속 AWS 실습인가](issues/03-first-learning-goal.md): 기존 네트워크 실습을 유지하고 VPC·서브넷·EC2 구성과 수명주기 → S3 순서로 간다. 그다음은 미결이다.
- [VPC·서브넷·EC2 구성과 실제 통신은 어디까지 일치하는가](issues/06-vpc-subnet-runtime-experiments.md): 실제 구성·수명주기와 통신을 확인했다. 라우팅·NACL·피어링·SG 주소 매핑의 한계가 있어 AWS 네트워크 동등성은 주장하지 않는다.
- [DynamoDB와 RDS의 실제 데이터 동작 중 무엇을 수업에 쓸 수 있는가](issues/08-database-runtime-experiments.md): DynamoDB 항목·조건·원자성과 실제 PostgreSQL SQL·수명주기·스냅샷 복원을 확인했다. 관리형 서비스의 운영 보장과 구분한다.
- [S3 저장과 Lambda 실행·이벤트 연결은 수업용으로 재현되는가](issues/07-s3-lambda-runtime-experiments.md): 객체 바이트·함수 실행·S3 이벤트 경로와 저장 보존·대표 이벤트 재처리를 확인했다. 출력 인코딩의 실패 판정과 실측 한계는 보존했다.
- [첫 수업 예고·PRD·대표 문제](issues/10-first-lesson-preview-prd.md): 2026-11-09 사용자 “고고”로 제시한 설계에 따른 다음 제작 단계를 승인했다. 첫 실습은 준비된 CLI 명령의 작은 변경으로 자원 관계와 배치를 확인한다([도구 결정](issues/04-first-practice-interface.md)). Java 게스트·MQ 통합은 여전히 검증 조건이다.
- [선택한 대표 문제와 Java 게스트의 사전 검증](issues/05-selected-practice-preflight.md): Windows 실제 실행에서 서브넷 19/19·Java 15/15, 정리 전후 동일을 확인했다. Codex 독립 실제 API·HTTP 요청도 성공했다. 실패와 잔재 정리 증거는 보존했고 Mac·MQ 네이티브 통과로 간주하지 않는다.
- [MQ 네이티브 실행기 연결](issues/11-native-cloud-runtime.md): 2026-11-10 Windows 단위 10개·실제 Docker 경로 8개와 실제 제출 분기·해설 분리·정리를 확인했다. 실패·재실행과 독립 검토 원자료를 보존했다. Mac·화면·배포는 별도 미검증이다.

## Not yet specified

- 첫 목표와 관찰 결과를 바탕으로 정할 대표 문제의 작은 수정과 피드백 구조.
- 선택한 서비스의 상태에 맞는 문제 간 격리·초기화·해설 시연·채점 관찰 계약.
- 검증된 최소 예제의 교육 목표를 넘지 않도록 수업을 나누는 경계와 선수 관계.
- 로컬에서 확인한 동작과 실제 AWS에 옮겨 설명할 수 있는 범위의 수업별 표시.

초기 실습 도구 선택은 질문이 구체화되어 [첫 실습은 AWS CLI로 원리를 확인할 것인가 SDK 코드로 시작할 것인가](issues/04-first-practice-interface.md) 티켓으로 옮겼다.

고정 이미지·플랫폼·정답/오답 관찰의 실행 증거는 [선택한 실습은 고정한 로컬 환경에서 재현되고 상태로 판정되는가](issues/05-selected-practice-preflight.md)에서 얻는다. 첫 학습 목표와 도구가 정해지기 전에는 실행하지 않는다.

서비스 실험을 바탕으로 [Floci 기반 클라우드 수업 활용 범위와 순서 제안](service-teaching-plan.md)을 작성했다. VPC·EC2 → S3 뒤의 순서는 추천안이며 [EC2 다음 S3·데이터베이스·Lambda를 어떤 학습 흐름으로 연결할 것인가](issues/09-service-learning-sequence.md)에서 사용자와 결정한다. 기존 승인 순서를 대신하지 않는다.

기존 목표·실습을 확인한 [자바 수업 연결 근거](existing-curriculum-alignment.md)를 기준으로 새 기초를 중복 도입하지 않는다.

사용자가 첫 수업의 예고·PRD·대표 문제를 확인하고 다음 단계 진행을 승인했다. [선택한 대표 문제의 사전 검증](issues/05-selected-practice-preflight.md)과 [MQ 네이티브 실행기 연결](issues/11-native-cloud-runtime.md)을 마쳤다. 2026-11-10 현재까지 커밋·인수인계를 남기라는 요청으로 제작 프로세스를 종료했다. [첫 수업 본편](issues/12-first-lesson-content.md)은 소스 생성 전이며 [인수인계](../../docs/floci-cloud-handoff.md)의 마지막 단위 검사 실패부터 확인해 재개한다. 본편·운영 반영은 미완료다.

## Out of scope

- 기술 준비 조건을 확인하기 전에 본편을 완료로 표시하거나 운영 코스를 게시하는 일. 이번 사용자 승인만으로 운영 배포를 승인받았다고 해석하지 않는다.
- 실제 AWS 계정 로그인, 리소스 생성·배포·과금 작업.
- 조사만으로 에뮬레이터와 실제 AWS의 동작이 완전히 같다고 간주하는 일.
