# EC2 다음 S3·데이터베이스·Lambda를 어떤 학습 흐름으로 연결할 것인가

Labels: wayfinder:grilling
Type: grilling
Status: open
Blocked by: 07, 08
Parent: [Floci를 활용한 MQ 클라우드 실습의 적용 경로](../map.md)

## Question

이미 정한 VPC·서브넷·EC2 → S3 다음에 실제 검증된 저장·자료 모델·관리형 DB·함수·이벤트 원리를 어떤 순서로 다룰 것인가? 기술 개수나 배포 프로젝트 완성보다 작은 변화와 관찰로 원리를 설명할 수 있는지를 기준으로, 필수 흐름과 선택 후속을 제안한다.

## Comments

사용자는 먼저 S3·Lambda·데이터베이스를 충분히 실험하고 쓸 범위와 가르칠 순서를 정리해달라고 요청했다. 조사 후 추천안을 작성하되 아직 사용자에게 승인받지 않은 순서를 확정 결정으로 기록하지 않는다. 수업 원고·PRD·운영 코스 구현은 별도다.

실험 후 [활용 범위와 순서 제안](../service-teaching-plan.md)을 작성했다. SQL 기초가 있는 MQ 학습자는 기존 VPC·EC2 → S3 뒤에 RDS → 독립 Lambda → Lambda의 S3 사용 → S3 이벤트로 이어가는 안을 추천한다. DynamoDB는 다른 key 중심 자료 접근 모델을 다루는 선택 후속이다. SQL이 없으면 RDS를 분기로 두며, Lambda의 실측 언어는 Python 3.12이므로 그 함수·JSON 준비 경험 또는 별도 언어 런타임 검증을 명시한다. 이 추천안에 대한 사용자 결정은 아직 기록하지 않았다.

사용자 결정: 독립 클라우드 코스가 아니라 기존 자바 과정의 후속이다. 자바의 함수·자료·예외 등 기존 경험에 연결하며, 실제 선수 범위와 Java Lambda/SDK 검증 필요 여부는 별도로 정한다. 아직 검증하지 않은 Java 런타임을 Python 성공으로 대체하지 않는다.

사용자 추가 결정: 기존 네트워크·DB·JDBC 등의 수업은 이미 있으므로 그 지식을 안다고 가정한다. 목표와 실제 실습을 직접 확인했고 [연결 근거](../existing-curriculum-alignment.md)를 남겼다. SQL·JDBC 지식 보유를 다시 확인하는 질문은 필요 없다. Java 런타임의 기술 검증은 학습자 수준 질문과 분리해 해당 수업 준비 작업으로 둔다.
