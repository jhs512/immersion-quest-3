## Question

기존 자바 과정의 네트워크·DB·JDBC 지식을 전제하고, VPC·서브넷·EC2의 선언된 자원 관계와 서버 배치를 첫 수업의 중심 목표로 잡은 예고·PRD·대표 문제가 적절한가? 운영 수업 제작 전에 검토할 구체적인 교육 설계 초안을 만든다.

## Comments

사용자는 수업 예고·PRD·대표 문제를 작성하는 방향에 동의했다. 이 prototype은 사용자 요청에 맞춘 교육 문서 초안이며 UI나 상태 머신을 구현하는 HTML 프로토타입이 아니다. 본편·catalog·approved-prd·배포는 바꾸지 않는다.

Claude Code에 세 초안 파일만 작성하도록 맡기고 주 에이전트가 근거와 정책을 직접 검토한다. 사용자 반응으로 설계 방향이 확인되기 전에는 이 티켓을 resolved로 바꾸지 않는다.

현재 Java 게스트 배치와 MQ Floci 실행기 통합은 미검증이다. 이미 실측한 subnet 제어면을 대표 문제로 삼고 나머지는 제작 전 검증 조건으로 표시한다.

첫 수업은 VPC·서브넷·EC2 배치에 집중하며 수명주기는 다음 수업으로 분리했다. 대표 문제는 CIDR 한 곳 수정과 실제 소유 VPC·서브넷 상태 판정이다. Java 게스트 배치와 MQ 통합은 미검증으로 표시했다.

주 에이전트 검토에서 기존 Docker 수업의 실제 제목·키를 대조했고, 오배치 비교에 종료 명령 대신 다시 시작을 쓰도록 줄였다. HTTP 채점은 학생 출력 재실행에 의존하지 않고 선택 주소 검사와 채점기 자체 통신 검증으로 명시했다. 세 문서는 검토용 초안이며 본편 제작·운영 반영·사용자 승인은 아직 없다.

## Answer

2026-11-09 사용자가 세 초안과 검증 전 항목을 확인한 뒤 “고고”라고 답해 이 설계를 기준으로 다음 제작 단계를 진행하도록 승인했다. 승인 범위는 자바 후속 첫 수업의 VPC·서브넷·EC2 배치 목표, 준비된 CLI 명령의 작은 변경, 실제 자원 상태 판정이다. Java 게스트·MQ 통합의 미검증을 통과로 바꾼 것은 아니다. 후속 작업은 해당 기술 준비 조건부터 실제 검증한다. 운영 게시·배포를 완료했거나 승인받았다는 기록이 아니다.
