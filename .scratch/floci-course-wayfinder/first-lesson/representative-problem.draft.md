# 대표 문제 초안 — 범위 밖 서브넷을 VPC 안으로 옮겨요

Status: draft_for_review
수업: [클라우드 · 주소 공간 안에 서버 한 대를 배치해요](lesson-preview.draft.json) / PRD [prd.draft.md](prd.draft.md) 스텝 1.2.2
작성일: 2026-11-09

> 이 문서는 사용자 검토용 초안이다. 운영 content.json·approved-prd·채점기에 반영하지 않았다. 아래 「채점 계약」은 **MQ에 구현되지 않은 설계안**이다. 지금 MQ에는 Floci 이미지 실행기·자원 소유 기록·상태 채점·초기화 통합이 없다.

## 왜 이 문제를 대표로 골랐나

- 수업의 중심 관계(VPC 안의 서브넷)를 가장 작은 행동 하나로 드러낸다. 학생은 CIDR 한 곳만 고친다.
- 서브넷 생성·조회와 범위 밖 거절은 공식 Floci 2.4.0 실측에서 실제로 동작했다([06 실험](../issues/06-vpc-subnet-runtime-experiments.md)). EC2 게스트나 자바 서버 실행이 필요 없으므로 미검증 범위를 피한다.
- 이미 배운 IPv4/마스크 판단(`network-ip`)을 새 자원 선언에 그대로 적용한다. 비트 계산을 다시 가르치지 않는다.

## 시작 상태 (학생 화면에 먼저 보이는 설명)

자, 이번 문제는 새 실습 상태에서 시작해요. 앞 문제에서 만든 서브넷은 없어요.

실습 환경이 미리 준비해 둔 것이 있어요.

- `LAB_ENDPOINT`: 로컬 실습 주소예요. 실제 AWS로 가지 않아요.
- 연습용 자격 값과 리전도 미리 넣어 뒀어요.
- `LAB_VPC_ID`: 준비된 VPC의 ID예요. 이 VPC의 주소 공간은 `10.91.0.0/16`이에요.
- `create-subnet.sh`: 서브넷을 만드는 준비 명령이에요. 그런데 한 곳이 틀렸어요.

이 VPC 안에 `10.91.2.0/24` 서브넷을 만들어야 해요. 서브넷은 VPC 주소 공간의 일부 범위예요. VPC 밖 범위는 받아 주지 않아요.

## 준비 코드 (`create-subnet.sh` 원문)

```bash
# 준비된 VPC 안에 서브넷 하나를 만드는 명령이에요.
# 실행 전에 --cidr-block 값을 VPC 범위와 비교해 보세요.
aws ec2 create-subnet \
  --endpoint-url "$LAB_ENDPOINT" \
  --vpc-id "$LAB_VPC_ID" \
  --cidr-block 10.92.2.0/24
```

준비 코드의 주석은 무엇을 볼지만 말한다. 결과(거절)는 미리 알리지 않는다.

## 확인 명령 (준비 제공, 원문)

```bash
aws ec2 describe-subnets \
  --endpoint-url "$LAB_ENDPOINT" \
  --filters Name=vpc-id,Values="$LAB_VPC_ID"
```

## 목표

준비된 VPC(`10.91.0.0/16`) 안에 `10.91.2.0/24` 서브넷이 하나 있게 하세요. `--endpoint-url "$LAB_ENDPOINT"`와 `--vpc-id "$LAB_VPC_ID"`는 그대로 두세요.

## 할 일

1. `cat create-subnet.sh`를 실행해 준비 명령을 읽으세요.
2. `--cidr-block` 값을 VPC 범위 `10.91.0.0/16`과 비교하세요.
3. `bash create-subnet.sh`를 실행해 결과를 확인하세요.
4. 확인 명령 `describe-subnets`를 실행해 VPC 안의 서브넷 목록을 확인하세요.
5. `create-subnet.sh`의 `--cidr-block` 값 한 곳만 `10.91.2.0/24`로 고치세요.
6. `bash create-subnet.sh`를 다시 실행해 결과를 확인하세요.
7. 확인 명령 `describe-subnets`를 다시 실행해 서브넷의 `CidrBlock`과 `VpcId`를 확인하세요.
8. 고친 뒤 상태를 확인했으면 제출 버튼을 누르세요.

할 일은 변경 전 관찰(3–4) → 한 곳 수정(5) → 실행(6) → 변경 후 관찰(7) → 제출(8) 순서다. 3번의 거절 메시지 원문은 Floci 출력에 따르며 이 초안에 지어내지 않는다. 해설은 실제로 나온 메시지를 읽는다.

## 정답 명령 (원문)

```bash
# 준비된 VPC 안에 서브넷 하나를 만드는 명령이에요.
# 로컬 실습 주소로만 보내요. 이 줄이 없으면 실제 AWS 주소를 찾으려 해요.
# VPC ID는 실습 환경이 준비한 값이에요. 직접 만든 VPC로 바꾸지 않아요.
# VPC가 10.91.0.0/16이니 앞 두 칸 10.91이 같아야 그 안의 범위예요.
# 10.92로 시작하면 VPC 밖이라 거절돼요. /24라서 10.91.2.0~10.91.2.255를 써요.
aws ec2 create-subnet \
  --endpoint-url "$LAB_ENDPOINT" \
  --vpc-id "$LAB_VPC_ID" \
  --cidr-block 10.91.2.0/24
```

주석을 지우면 준비 코드와 `--cidr-block` 한 줄만 다르다.

## 채점 계약 (설계안 · MQ 미구현)

채점은 명령 문자열·터미널 출력 캡처가 아니라 제출 시점의 실습 상태를 읽는다.

1. 채점기는 이 스텝의 초기화 기록에서 **실습 소유 VPC ID**를 읽는다. 학생 셸의 `LAB_VPC_ID` 값을 믿지 않는다. 학생이 변수를 바꿔도 채점 대상은 바뀌지 않는다.
2. 채점기는 자기 전용 자격 값과 같은 로컬 endpoint로 `DescribeSubnets`를 호출한다. 실제 AWS를 호출하지 않는다.
3. 통과 조건:
   - 소유 VPC의 `VpcId`를 가진 서브넷 중 `CidrBlock`이 정확히 `10.91.2.0/24`인 것이 **정확히 하나**다.
   - 그 서브넷의 `State`가 `available`이다.
   - 소유 VPC에 그 밖의 서브넷이 없다(초기 상태는 서브넷 0개).
   - 소유 VPC가 초기화 기록의 CIDR `10.91.0.0/16`을 그대로 가진다.
4. 소유 VPC 밖의 VPC(학생이 새로 만든 VPC 포함)에 같은 CIDR 서브넷이 있으면, 통과 조건과 별개로 그 사실을 피드백에 적는다. 그 서브넷은 통과 근거가 되지 않는다.
5. 피드백은 관찰한 상태로 말한다. 예: 「준비된 VPC에 서브넷이 없어요」, 「10.91.2.0/24가 아닌 서브넷이 있어요」.

### 오답 판정

| 오답 | 실제 상태 | 판정 |
|---|---|---|
| 준비 코드를 그대로 실행(10.92.2.0/24) | 생성 거절. 소유 VPC 서브넷 0개 | 실패 |
| 다른 VPC를 직접 만들고 거기에 10.91.2.0/24 생성 | 소유 VPC 서브넷 0개, 다른 VPC에 서브넷 1개 | 실패. 「준비된 VPC가 아닌 곳에 만들었어요」 |
| `--vpc-id`를 다른 값으로 바꿈 | 소유 VPC 서브넷 0개 | 실패 |
| 명령은 실패했는데 `echo`로 성공 JSON 같은 텍스트를 출력 | 상태 변화 없음 | 실패. 출력은 채점 근거가 아니다 |
| 범위 밖 다른 값(예: 10.92.3.0/24, 10.0.2.0/24) | 생성 거절 | 실패 |
| VPC 안이지만 다른 범위(10.91.3.0/24) | 소유 VPC에 10.91.3.0/24 하나 | 실패. 「목표 범위와 다른 서브넷이 있어요」 |
| 10.91.2.0/24와 다른 범위를 함께 만듦 | 서브넷 2개 | 실패(불필요 자원) |
| 같은 명령을 두 번 실행 | 두 번째는 겹침으로 거절. 서브넷 1개 | 통과(상태 기준) |
| `--endpoint-url`을 지움 | 로컬 상태 변화 없음. 실제 AWS 호출 시도 | 실패. 실행 환경이 외부 AWS endpoint를 막아야 한다(제작 전 게이트) |

### 동등한 유효 풀이

- 준비 파일을 고치지 않고 정답 명령을 직접 입력해 실행한 경우: 상태가 같으므로 통과.
- 잘못 만든 서브넷을 `delete-subnet`으로 지우고 다시 만든 경우: 최종 상태가 조건을 만족하면 통과.

### 변형 입력 (수업 검증 사례)

- 초기화가 VPC를 `10.73.0.0/16`, 목표를 `10.73.2.0/24`로 바꾼 변형에서도 같은 계약이 통과·실패를 가른다. 채점기는 목표 CIDR을 초기화 기록에서 읽는다.

## 초기화 (설계안)

- 스텝마다 새 Floci 상태에서 시작한다. 앞 스텝 자원을 이어 쓰지 않는다.
- 준비 스크립트가 VPC `10.91.0.0/16`을 만들고, 그 VPC ID·CIDR·목표 CIDR을 **채점 전용 소유 기록**에 쓴다. 학생 셸에는 `LAB_ENDPOINT`·연습용 자격 값·리전·`LAB_VPC_ID`만 내보낸다.
- 준비 스크립트가 만든 VPC는 학생이 한 일이 아니다. 시작 상태 설명에서 먼저 알린다.
- 「다시 시작」은 Floci 상태와 `create-subnet.sh`를 원래대로 돌린다.

## 해설 방향 (요약)

- 첫머리: VPC 범위와 목표 범위, 고칠 곳이 한 곳뿐이라는 제약을 말한다.
- 준비 명령을 그대로 실행해 실제 거절 메시지를 읽는다. 「조심하세요」: 끝자리 2만 맞추고 앞 두 칸을 안 보기 쉽다. 10.92와 10.91의 차이를 짚는다.
- 고친 뒤 실행 출력의 `CidrBlock`·`VpcId`·`State`를 읽는다. 그다음 `describe-subnets`로 같은 상태를 다시 읽는다.
- 「조심하세요」(말로): 다른 VPC에 같은 숫자를 만들어도 같은 자리가 아니다.
