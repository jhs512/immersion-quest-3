# 코스별 이름과 통합 진도 조회 — 설계안

상태: 요구사항 정리와 권장 설계. 이름 입력·변경 및 대시보드는 아직 구현하지 않음.

## 확정된 사용자 요구

- GitHub 계정은 신원이며 코스마다 서로 다른 표시 이름을 쓴다.
- 코스 진입 시 이름을 받고 문자열 내부를 포함한 공백을 제거한다. 예: `[BE16]홍 길동` → `[BE16]홍길동`.
- 학생이 코스별 이름을 나중에 수정할 수 있다.
- 다른 코스가 같은 수업을 참조하더라도 이름과 진도를 섞지 않는다.
- 관리자는 `jhs512` 계정이다. GitHub에서 확인한 불변 사용자 ID로 판단한다.
- 진도는 수업별 이슈에 모아 한 시간에 한 번 이하로 전송한다. 로컬 채점·진도 표시는 즉시 반영한다.
- 관리자는 앱의 특정 코스에 들어가지 않아도 여러 코스의 학생 진도를 편하게 조회하고 싶다.

## 권장 데이터 구조

| 대상 | 고유 기준 | 변경 가능한 값 |
| --- | --- | --- |
| 신원 | 검증된 GitHub 숫자 사용자 ID | GitHub 로그인 이름 |
| 코스 등록 | 사용자 ID + 코스 고유 코드 | 표시 이름, 이름 수정 시각 |
| 진도 | 사용자 ID + 코스 고유 코드 + 수업 고유 코드 | 스텝별 시도·완료·해설 열람 기록 |

예: 한 학생이 A 코스와 B 코스에서 같은 수업 L을 만난다. A에서 `[BE16]홍길동`, B에서 `홍길동`을 쓴다. A의 L에서 통과해도 B의 L은 통과되지 않는다. A의 이름을 고쳐도 A의 진도와 B의 이름은 유지한다. 현재 `ProgressKey`는 이미 사용자·코스·수업을 포함한다.

## 코스 등록 이슈

- 코스 저장소에서 학생·코스당 등록 이슈 하나를 유지한다. 수업별 진도 이슈와 구별한다.
- 이슈에는 현재 표시 이름과 코스 고유 코드, 확인 가능한 사용자 ID를 저장한다.
- 이름 변경은 새 이슈·댓글을 만들지 않고 같은 등록 이슈의 현재 이름을 수정한다.
- 실제 작성자의 GitHub 사용자 ID를 확인한다. 본문에 적힌 사용자 ID만 믿지 않는다.
- 이름 변경은 진도 전송과 별개로 즉시 시도한다. 전송 실패 시 로컬에 보관하고 전송 대기를 표시한다.
- 이름을 복원할 때 오래된 기기의 값으로 무조건 덮어쓰지 않는다. 마지막으로 읽은 등록 버전과 수정 시각을 비교하고 충돌은 다시 읽어 해결한다.

## 관리자 조회 화면 권장안

플레이어 저장소에 단일 웹 조회 화면을 두고 GitHub Pages로 배포한다. 코스마다 별도 사이트나 새 저장소를 만들 필요는 없다. 코스 저장소를 입력하거나 여러 코스를 저장해 놓고 선택할 수 있게 한다.

1. 코스의 구성과 수업별 필수 스텝을 읽는다.
2. 등록 이슈에서 현재 코스별 이름을 읽는다.
3. 수업별 진도 이슈의 작성자와 고유 코드를 기준으로 기록을 합친다. 시간별 묶음 댓글과 기존 댓글을 모두 읽는다.
4. 학생 이름·GitHub 계정·완료율·마지막 통과 스텝·최근 전송 시각을 표로 보여준다.
5. 이름은 다음 조회에서 새 값으로 갱신한다. 진도에는 시간당 전송으로 생기는 지연을 명시한다.

이름 변경을 진도 전송 시점까지 기다리게 하지 않는다. 다만 GitHub Pages는 실시간 전달 서버가 아니므로, 실제 화면 반영은 갱신 또는 조회 주기에 따른다. 짧은 고정 폴링으로 전체 이슈를 매번 읽지 말고 갱신 시점·캐시·페이지 나누기·API 사용량을 함께 고려한다.

## 공개 조회와 관리자 권한의 경계

GitHub Pages의 일반 정적 화면은 공개 조회 도구다. 화면에서 관리자 계정만 보이게 조건을 거는 것은 비공개 접근 제어가 아니다. 현재 공개 코스 이슈를 읽는 조회 도구로 시작하는 안과, 관리자만 접근 가능한 비공개 서비스를 만드는 안을 구별해야 한다. 후자가 필요하면 서버 측 인증 또는 비공개 배포 수단이 필요하다. 토큰을 정적 페이지나 저장소에 넣지 않는다.

## 이번에 구현하는 범위

시간당 진도 묶음 전송과 하단 이전·다음 바 제거를 구현한다. 이름 입력·이름 변경·등록 이슈·통합 웹 화면은 위 설계를 바탕으로 이어서 구현할 별도 범위다. 문서 작성이나 화면 제안만으로 구현·배포 완료로 취급하지 않는다.
